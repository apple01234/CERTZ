# 故障·解决记录（FAQ 源）

> 记录规则：只记**实际发生并已解决**的故障，禁止臆测性记录。同一类型故障重复 2 次以上、或新用户大概率遇到时，升级到 `tutorials/` 的「问题解决」章节。
> 格式：症状 / 原因 / 解决 / 复发防止（来源标注 worklog 迭代）

## 2026-09-10 · 版本提交包含陈旧构建产物（worklog Task 71）
- 症状：版本号已递增，但产物内容检测不到本次修改的任何特征标记（新代码 0 检出）
- 原因：绕过完整构建管线、单独执行增量构建，打包读取的是上一轮遗留的陈旧产物目录（stale .next-apk）
- 解决：废弃该版本产物，从头执行完整管线（全量构建 → 打包），构建后用本次修改的特征字符串检索产物内容再验收
- 复发防止：版本提交前必须确认产物是"本次输入"的新鲜输出；禁止把单独增量构建的结果当作最终交付物

## 2026-09-10 · 推送被远端分叉拒绝（worklog Task 71）
- 症状：`git push` 被拒，远端包含本地没有的提交；常见于并行会话各自提交了同名记录文件（如 worklog）
- 原因：push 前未 fetch，本地与远端在共同祖先之后各自前进形成分叉
- 解决：push 前先 `git fetch origin`；确认分叉后按"保留本地内容版本"的策略合并（ours），合并结果回归验证后再 push
- 复发防止：把 fetch 固定为 push 流程的第一步，禁止跳过

## 2026-09-10 · 远端版本产物校验遇到截断下载（worklog Task 71）
- 症状：发布后从远端重新下载校验 md5 与本地不一致，险些误判为"上传损坏"
- 原因：首次校验用的下载本身被网络中途截断，拿到的是不完整文件
- 解决：先比对文件字节数与本地是否一致，再重新完整下载计算 md5；两次独立下载结果一致才判通过
- 复发防止：远程产物 md5 校验必须包含「字节数比对 → md5 → 复检」三步
