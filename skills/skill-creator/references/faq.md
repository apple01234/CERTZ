# 故障·解决记录（FAQ 源）— skill-creator

> 记录规则：只记**实际发生并已解决**的故障，禁止臆测性记录。来源标注（worklog 迭代 / 本会话实测）。
> 格式：症状 / 原因 / 解决 / 复发防止

## 2026-09-10 · 본문이 언급한 포인터 파일이 실재하지 않아 구조 게이트 실패 (본 세션 실측)
- 症状：SKILL.md 본문이 `evals/evals.json`을 안내 문구로 언급하고 있는데 실제 파일이 없어 G6(포인터 실재) 검증 실패 — 원본 상태 4/9
- 原因：본문 초안 시점에 파일 경로를 먼저 기술해 놓고 파일 생성을 뒤로 미룬 채 방치됨 (스킬 배포자의 초기 작성 실수)
- 解决：언급된 경로를 전수 나열해 실재 여부 확인 → 없는 파일은 생성하거나 문구에서 제외. 본 회차는 evals/evals.json을 실제로 신설해 해소
- 复发防止：본문에 포인터(references/tutorials/evals 경로)를 추가하는 즉시 파일을 생성하거나 문구에서 뺀다 — "먼저 쓰고 나중 만들기" 금지

## 2026-09-10 · evals 실실행이 불가능한 환경에서 품질 판정 근거 공백 (worklog Task 74 실측)
- 症状：evals.json은 있지만 서브에이전트 병렬 런이나 `glm -p` CLI가 없는 환경에서 회귀 테스트를 실실행할 수 없어, 스킬 개선이 "검증 없는 편집"으로 보이는 상태가 됨
- 原因：트리거 판정 러너(run_eval.py·run_loop.py)는 glm CLI와 서브에이전트 인프라에 의존 — 환경에 따라 부재
- 解决：수동 폴백 판정으로 대체 — 구조 게이트 9개 정량 통과 + 트리거용例(expectations) 검토로 동등 이상 확인, 그 판정 근거를 worklog 본문에 기록
- 复发防止：자동화 미실행 시 "자동화 미실행" 사실과 대체 근거를 의무 기록 (근거 없는 "통과" 선언 금지). 다음 회차에 트리거 판정 자동화 러너 이관이 과제

## 2026-09-10 · description에 비발동 경계가 없어 단순 요청에서도 스킬이 발동 시도됨 (worklog Task 74 실측 — task-review 사례)
- 症状：파일 몇 줄 읽기 같은 단순 일회성 요청에서도 스킬 제작 루프가 발동 시도되어 불필요한 오버헤드 발생
- 原因：description에 발동 조건(when-to-use)만 있고 비발동 경계(when-not-to-use)가 없어, 키워드 유사도만으로 트리거 판정됨
- 解决：description을 3요소로 재작성 — ①정량 트리거 기준 ②발동 발화 예시 ③비발동 경계("Do NOT use it to merely use or invoke an existing skill…")
- 复发防止：스킬 description 작성·수정 시 3요소 체크리스트를 상시 적용 (G3 경계 게이트가 이를 정량 감시)
