───────────────────────────────────────────────────────────────────────────────
[섹션 0] 이 문서의 용도와 당신(실행 AI)의 역할
───────────────────────────────────────────────────────────────────────────────

이 문서는 이미 완성·운영된 2D 픽셀 액션 RPG 「SERTZ(세르츠)」를 로블록스(ROBLOX)
플랫폼으로 이관 리빌드하기 위해 작성된, 자기완결형(single-source) 제작 지시서다.
당신은 로블록스 스튜디오 전문가로서 이 문서의 모든 규격을 코드로 구현한다.

■ 당신이 알아야 할 배경 (외부 검색 불필요 — 전부 여기 있다)
  1) 원작 SERTZ는 Phaser 4 + Next.js + Capacitor로 만들어진 메이플스토리풍
     탑다운 픽셀 액션 RPG다. Android APK(com.sertz.myapp)로 배포되어 왔다.
  2) 원작의 세계관/직업/스킬/맵/보스/아이템/경제/콘텐츠 설계는 그대로 승계한다.
     단, "로블록스에 맞게 변형"이 이 지시의 핵심이므로 [섹션 2]의 변환 총칙을
     우선 적용한다. 무엇을 유지하고 무엇을 바꿀지는 전부 이 문서가 결정했다.
  3) 원작에는 유저가 겪은 심각한 버그 13건이 있었다(예: 보이지 않는 히트박스,
     3레벨 NPC 진행 막힘, 무한 재부팅). [섹션 19]에 재발 방지 대책을 확정해
     두었으므로 반드시 그 방향으로 설계한다.
  4) 원작에는 ARG(이스터에그 알파벳/암호 페이지/이상한 돌/비밀 수첩)가 있었으나
     이것이 게임 무한 재부팅·오류 페이지의 근원으로 판명되어 삭제가 확정됐다.
     [섹션 18] 절대 금지 목록에 따라 로블록스판에 절대 구현하지 않는다.

■ 작업 방식 (엄수)
  - 이 문서를 한 번에 다 구현하려 하지 마라. [섹션 20]의 마일스톤 M0부터 순서대로
    진행하고, 각 마일스톤이 끝날 때마다 "완료 항목 / 테스트 방법 / 다음 단계"를
    보고한 뒤 다음 마일스톤으로 넘어간다.
  - 모든 코드는 완전한 전체 코드여야 한다. "…이하 동일", "생략", "TODO" 금지.
  - 로블록스 정책/한도(오디오 업로드 제한, 광고 금지, Robux 결제 방식 등)는
    [섹션 2]·[섹션 10]의 지정을 따르고, 임의로 외부 서비스를 붙이지 않는다.
  - 원작의 수치(밸런스 표)는 이 문서에 적힌 값을 그대로 쓴다. 임의 변경 금지.

[섹션 1] 원작 게임 개요 — SERTZ가 무엇인가
───────────────────────────────────────────────────────────────────────────────

■ 정체
  - 타이틀: SERTZ — 이그드라실 (로블록스 경험명 제안: 「SERTZ: 이그드라실」)
  - 장르: 메이플스토리풍 2D 탑다운 픽셀 액션 RPG (오토사냥 지원, MMORPG적 요소)
  - 세계관: 세계수(이그드라실)의 뿌리를 타고 심연에서 침공하는 마룡 아부디토스와
    심연군들로부터 9개 해역/왕국을 지키는 모험가의 이야기. 북유럽 신화 기반
    지명(미드가르드·알프헤임·무스펠헤임·니플헤임·스바르트알프헤임·니다벨리르·
    헬·심연)을 사용한다.
  - 플레이어는 미드가르드 항구 마을(쿠소디아 왕국, 본마을)에서 시작해 9챕터를
    돌파하고 세계수 결정 9종을 모아 세계수의 가호를 받은 뒤, 종언의 왕좌에서
    아부디토스를 쓰러뜨린다. 그 너머에는 재림의 땅(15구역)과 5차 각성(Lv.200),
    환생(레벨 리셋 영구 강화)이 기다린다.

■ 원작 콘텐츠 규모 (이 규모를 전부 이관한다)
  - 맵: 10챕터(마을 포함) × 구역 = 본마을 + 9챕터 90구역, 마을 10곳
  - 재림의 땅 r1~r15 별도 15구역 (보스 3종 포함)
  - 콘텐츠 전용 스테이지 5종: 무릉도장 / 바르가 수비전 / 균열 던전 / 심연의 탑 /
    몬스터 파크 (+ 전직 시련)
  - 직업: 4계열 × 1~4차 = 28클래스 + 5차 각성 (아래 [섹션 6]에 전수 데이터)
  - 스킬: 직업당 스킬1~4 + 기동기(대시) + 3차기 + 4차기 + 5차 궁극기(12종)
  - 몬스터: 잡몹 34종 + 보스 9종 + 재림 보스 3종 (도감 43종+)
  - 아이템: 무기/방어구/장신구/챕터 세트 27종/스타포스 강화/eert 큐브(잠재)/
    등급업 큐브/물약 10+10종/버프/치장(코스튬·오라·어태치)/펫 9종
  - 경제: 골드/에메랄드💎/실버/파크코인/유니온코인, 상점 7종, 거래소, 시즌패스
  - 소셜: 파티/친구/채팅/왕국 랭킹/랭커 상점/유니온/거래소
  - UI 패널 19종 (메이플식 4탭 인벤토리 등)

[섹션 2] 플랫폼 변환 총칙 — 원작(2D 웹) → 로블록스(3D) 매핑 총표
───────────────────────────────────────────────────────────────────────────────

이것이 "로블록스에 맞게 변형"의 핵심 결정 사항이다. 예외 없이 준수한다.

■ 2.1 시점·조작 (최우선 변환)
  - 카메라: 탑다운 고정 앵글(수평에서 약 50~60° 아래로 내려다봄) + 휠/핀치 줌
    (최소 12스터드 ~ 최대 34스터드, 차단 앵글 고정 — 사이뷰로 우회 금지).
    원작의 "탑다운에 캐릭터 앞방향이 공격 방향"인 감각을 유지한다.
  - 이동: WASD/화살표 8방향 자유 이동(마을/필드), 전투 중에도 동일.
    모바일은 로블록스 기본 버추얼 조이스틱 사용(데드존 8%, 최대 이동 42% 지점에서
    포화 — 원작 튜닝치 승계).
  - 스킬 입력: 로블록스 표준 핫바(1~8) 사용. 매핑: 1=기본공격, 2~5=스킬1~4,
    6=기동기(대시), 7=HP물약, 8=MP물약, 9=궁극기(해금 시). ContextActionService로
    바인딩하고 모바일용 버튼을 자동 생성한다(아이콘 + 쿨다운 오버레이).
  - 공격 방향: 캐릭터의 현재 조준 방향(마우스 커서 방향 또는 이동 방향)을 향해
    발사. 원작의 "공격 방향 근본 수정(픽셀 실측)" 사례를 반면교사 삼아, 발사
    방향 벡터는 서버에서 최종 검증한다.

■ 2.2 그래픽 스타일
  - 월드: 로블록스식 저폴리(low-poly) + 플랫 셰이딩. 픽셀 텍스처를 억지로 붙이지
    말고, 챕터별 색상 팔레트로 지역 감성을 표현한다
    (숲=연록/늪=독초록/알프헤임=빛금/무스펠헤임=용암주홍/니플헤임=서리청/
     스바르트알프=수정보라/니다벨리르=룬은회/헬=혈적/심연=흑자).
  - 캐릭터: R15 아바타 기본형 + 직업별 의상(Shirt/Pants 텍스처) + 직업색 조명
    틴트. 원작 SPUM의 "직업별 머리/의상 분화"는 의상+헤어 액세서리 조합으로 승계.
  - UI: 원작 「이그드라실 왕가」 디자인 시스템 유지 — 배경 딥네이비(#101528 계열),
    프레임 우드 브라운(#5a3a24 계열), 강조 골드(#f0c060 계열). 폰트는 로블록스
    기본(Gotham 계열)에서 시작하고, 굵은 세리프 제목용으로 Enum.Font.Cinzel 계열
    사용. 픽셀 폰트 업로드는 선택 사항(정책 확인 후).

■ 2.4 유지 vs 변형 판정 기준 (충돌 시 이 기준으로 결정)
  1) 유저 감성 요소(직업명/스킬명/스토리/밸런스 수치/UI 색감/콘텐츠 룰) = 유지.
  2) 플랫폼 위반 소지(광고/결제/계정/ARG/외부 링크) = 로블록스식으로 변형.
  3) 원작의 기술적 부채(클라이언트 판정, 자가치유 땜질, 로컬 세이브) = 서버 권위
     아키텍처로 근본 교체. 땜질 코드를 이식하지 않는다.
  4) 2D 전용 연출(픽셀 스프라이트 애니메이션) = 3D 등가물(파티클/메시/카메라
     연출)로 재해석. 스프라이트 시트를 그대로 옮기지 않는다.

[섹션 3] 로블록스 아키텍처 설계 지시 (엄수)

■ 3.1 Place 구성
  - 단일 Place로 시작한다(챕터 간 TeleportService 금지 — 로딩 끊김/파티 분리
    위험). 전체 구역을 하나의 월드에 배치하되, 구역 간 이동은 포탈(파트 터치 →
    서버 검증 → 캐릭터 Pivot 이동 + 페이드)로 처리한다.
  - 월드는 기능별 폴더로 격리: workspace/World/{Zones, Villages, Interiors,
    Gates, Portals, Props} / workspace/Enemies / workspace/NPCs.
  - StreamingEnabled = true (구역 멀리서 언로드). 단, 전투 히트박스 판정은
    서버에서 하므로 스트리밍 영향 없음.
  - 조명: 구역 진입 시 서버가 LocalLight 트리거 → 챕터별 Lighting 속성 세트
    (무스펠헤임 주홍 Ambience, 니플헤임 청백, 헬 암적, 심연 어둠+에임라이트).

■ 3.3 서버 권위 원칙 (원작 부채의 근본 교체 — 최우선 설계 규칙)
  - 데미지 계산/크리 판정/상태이상/드롭 롤/골드 지급/확률(스타포스·eert·가챠)은
    전부 서버가 한다. 클라이언트는 "입력 전달 + 연출"만 담당한다.
  - 모든 RemoteEvent 핸들러는: ①발신자가 실제로 그 행동이 가능한 상태인지(쿨다운/
    거리/MP/재화/구역 권한) 서버 기준으로 검증 ②속도 제한(스킬 8회/초 이상 거부,
    상점 3요청/초) ③pcall로 감싸 오류 유출 방지.
  - 재화/아이템 변경은 단일 진입점(ProfileService:Mutate)으로만. 중복 지급 방지
    (원작 거래소 복제 익스플로잇 사례 반면교사 — 에스크로 트랜잭션 섹션 10.4).
  - GM/AdminServer는 Owner UserId + 지정 UserId 화이트리스트만 통과. GM 커맨드:
    자유전직/레벨설정/아이템지급/보스소환/구역이동/통계조회.

■ 3.4 부팅 순서 (원작 무한 재부팅 사례의 근본 대책)
  1) ClientBoot: ProfileService 로드 완료까지 HUD 숨김 + 로딩 화면(진행바).
  2) ContentProvider:PreloadAsync로 스폰 구역 필수 에셋 선로딩, 실패해도 게임은
     계속(재시도 3회 로그 후 진행) — 원작 "로드 실패 스프라이트 영구 누락" 재발
     방지. 로딩 실패 항목은 게임 내 오류 수집 콘솔(telemetry)로만 기록.
  3) 캐릭터 스폰은 서버가 본마을 safeSpawn(닫힌 셀 금지 검증) 좌표에 배치.
  4) 게임 내 어떤 스크립트 오류도 리부팅 루프로 이어지지 않게: 최상위 pcall +
     실패 시 플레이어 안전구역 유지 + 관리자용 오류 리포트 수집.

■ 4.1 구역(Zone) 모델
  - 로블록스판의 기본 단위는 "구역(Stage)"이다. 각 구역은 workspace/World/Zones
    아래 모델 하나(바닥 파트 + 장식 + 적 스폰 앵커 + 포탈 파트)이며,
    ReplicatedStorage/Shared/ZoneConfigs가 다음 필드로 정의한다(원작 stages.ts
    구조 승계): { key, chapter, name, subtitle, sizeX, sizeZ, theme, tiles,
    enemies:{key,count}[], main, portalNext, portalPrev, lvGateEnter, lvGateMid,
    fragment?, boss? }.
  - 포탈: 파트 터치 → ZoneServer가 (a)레벨게이트 충족 여부 (b)미수락 퀘스트
    알림 → 검증 후 플레이어 Pivot을 대상 구역 스폰 앵커로 이동 + 페이드(0.35초)

    이 함수 하나로만 발생시킨다(다른 경로로 좌표 이동 금지).
  - 구역 이동 시 캐릭터는 가까운 마을 부활 지점·긴급귀환 좌표를 함께 갱신.
  - 엣지 안내: 다음 목표 구역 방향에 월드 스페이스 화살표(맥동 애니) + 목표명

    GM 스킨 > 코스튬 > 직업 프리셋 > 기본 아바타.

■ 11.1 퀘스트 타입/구조
  - QuestDef: { type: hunt(토벌)|reach(도달)|beat(처치)|boss(보스), targetKeys,
    targetLabel } — 구역 체인(questIdx) + 스토리 beat + 반복의뢰를 buildQuests
    논리로 구역에 배치. reach 퀘스트는 포탈 진입 시 완료 처리.
  - 수락/추적: acceptedQuests/questTracked 세이브. 퀘스트 로그에 [수락]/[추적]
    버튼, 미수락 카운트 게이트, HUD "수락 대기" 배지.
  - 난이도 곡선 questNeedByLv(목표 처치 수): 구간별 5~8 / 10~15 / 18~25 / 30~40
    / 45~60 + 보상 동반 상향. 스토리 토벌 need ×2.5, 반복의뢰 ×2.

■ 11.2 일일/시즌 퀘스트
  - 일일퀘 5종: 토벌/파밍(드롭 40개)/보스 사냥/균열/수비전 — 혜택 패널 진행바.
  - 시즌 미션: 일일 4종(토벌 50/보스 3/균열 1/수비전 2파) + 주간 5종(토벌 400/
    보스 15/균열 4/일일퀘 4일/거래소 1회) → 패스 XP(30~200).

■ 11.3 반복의뢰(일퀘 해금)
  - 최종 보스(아부디토스) 클리어 후 해금. 라고스 의뢰 — 상인 대화로 수주, 체인
    완료 구역에서 [반복] 활성. 전용 대사: "아홉 왕국의 스토리를 전부 끝낸 진짜
    모험가".

■ 11.4 NPC 명부 (이름/역할 그대로)

■ 11.5 ★ 3레벨 튜토리얼 NPC 진행 (원작 리포트 "3레벨 NPC 진행 막힘"의
        로블록스판 최종 설계 — 반드시 이 스펙으로)
  - 목표: 신규 캐릭터가 튜토리얼 대화 3건(전직 NPC 카이엔 1회 + 일반 NPC 2회
    = 이그니, 상인)을 완료하면 Lv.3 도달 + 다음 퀘스트가 자동으로 잡힌다.
  - 구현 요건(전부 필수):
    ① 대화 완료 판정은 서버가 세이브에 기록(tutorial.talked={kayen,igni,merchant})
    ② 3건 완료 즉시 서버가 경험치 지급으로 Lv.3을 보장(레벨 커브와 무관하게
       보정 지급) — "대화를 다 했는데 3레벨이 안 됨" 절대 방지
    ③ 미완료 NPC 위에 빛기둥 + 미니맵 마커 + HUD 안내("카이엔에게 말 걸기 1/3")
    ④ 대화 도중 접속 종료 시 미완료 NPC부터 재개(완료분은 유지)
    ⑤ 퀘스트 게이트(구역 이동/전직)는 튜토리얼 3건과 충돌하지 않게 순서 보장
    ⑥ 인수 테스트: "아무것도 안 하고 NPC 3명만 말 걸기 → Lv.3 → 전직 시련
       안내" 시나리오를 스튜디오 2인 테스트로 검증

■ 12.1 레벨/스탯 커브 (원작 확정치 그대로)

    성장 가속 — 마지막 구간 42배).
  - 공격 계수 CH_ATK = 1 → 5.0배 선형+구간.
  - 구역 스케일: 구역당 HP +7.5% / ATK +6%, 보스 HP×1.6/ATK×1.15 추가.
  - 스탯 자동배분 토글(autoAlloc): 주스탯 80% + 행운 20%, 레벨업 훅 자동 분배.
  - 이속: 기본 240 + 민첩 0.5%/점(캡 +60%) + 강화 0.5%/성(캡 +15%).

■ 12.2 레벨게이트 커브

    챕터 10에서 150+에 도달하도록 배치. GM은 예외 통과.

■ 12.3 세계수 결정 9종 → 세계수의 가호

    수정/룬 광석의 눈/전쟁의 잔광/세계수의 눈동자) 전부 수집 시 세계수의 가호
    영구 효과: ATK +20 / DEF +8 / HP +200 / 공격 +3%.
  - ATK 보너스는 환생 횟수에 따라 5→30 단계 성장.

■ 12.4 환생(리셋 성장) — 원작 규격 그대로

    rebirthLog(최근 30건) 기록. 구세이브 체인 역산 마이그레이션(세이브 파손

[섹션 22] 산출물 형식 — 당신(AI)의 답변 규칙
───────────────────────────────────────────────────────────────────────────────

  1. 마일스톤 단위로 산출한다. 각 답변의 시작에 현재 마일스톤/완료 항목/다음
     항목을 명시한다.
  2. 코드 블록마다 반드시 3요소를 먼저 적는다:
     [위치] 생성할 인스턴스의 전체 경로 (예: ServerScriptService/Services/
            CombatServer — ModuleScript)
     [역할] 한 줄 설명
     [연결] 이 코드가 참조/호출하는 모듈·리모트·오브젝트
     이후 전체 코드(생략 금지)를 붙인다.
  3. 코드로 안 되는 Studio 수동 작업(파트 배치/속성값/폴더 생성 등)은
     "Studio 작업" 체크리스트로 단계별로 적는다(속성 이름=값 형식).
  4. 데이터 모듈(ClassDefs/ItemDefs/ZoneConfigs/Balance 등)은 원작 수치를
     그대로 담은 완전한 Luau 테이블로 산출한다. 수치 축약 금지.
  5. 각 마일스톤 끝에 [섹션 21] 해당 시나리오의 테스트 방법(스튜디오 조작
     순서)을 적는다.
  6. 이 문서와 충돌하는 로블록스 정책 변동이 발견되면, 어느 지시를 어떻게
     대체했는지 명시하고 안전한 쪽(정책 준수)을 따른다.
  7. 한국어로 답변하고, 코드 주석도 한국어로 쓴다.
