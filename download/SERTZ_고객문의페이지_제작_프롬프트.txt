【웹사이트 제작 지시서】 모바일 액션 RPG 「SERTZ」 공식 고객 문의 페이지 (히든 ARG 포함)

■ 당신의 역할
너는 레트로 게임 감성의 웹 퍼블리셔이자 UI 디자이너다. 아래 사양에 맞춰 단일 HTML 파일(index.html)로 완성된 웹페이지를 제작하라. 추가 질문 없이 지시된 범위 안에서 스스로 판단하여 끝까지 완성하라. 결과물은 정적 호스팅(GitHub Pages 등)에 바로 올릴 수 있어야 한다.

■ 1. 배경 지식 — 이 게임에 대해
- 게임명: SERTZ (세르츠)
- 플랫폼: Android (Google Play 배포) / 패키지명: com.sertz.myapp
- 장르: 2D 횡스크롤 액션 RPG (마을과 사냥터·유적을 오가며 사냥하고, 보스 레이드와 장비 육성, 전직 시스템)
- 주요 콘텐츠 명칭: 마을, 요세유적, 보스 유물, 재림 시리즈 장비, 등급업 큐브, 르쯔(게임 화폐)
- 세계관 키워드: 고대 유적, 봉인, 차원 균열, 그리고 「이상한 돌」 — 정체를 알 수 없는 광물. 이번 ARG의 핵심 소재다.
- 운영 표기명: 「SERTZ 운영팀」 (페이지 전체에서 개발자/운영자 명의는 이 이름으로 통일)

■ 2. 페이지의 목적 — 두 가지가 동시에 성립해야 한다
A. 표면: 공식 고객 문의 페이지
   이 URL은 Google Play 스토어 등록정보의 "계정 삭제 URL" 필드에 등록될 공식 문서다.
   Google 정책 요건(아래 3번)을 빠짐없이 충족해야 하고, 성실하고 차분한 공식 문서의 톤을 유지해야 한다.
B. 이면: ARG 은닉 페이지
   페이지 곳곳에 게임 세계관과 연결된 ARG(대체현실게임) 힌트가 숨겨져 있다.
   겉보기에는 평범한 고객센터지만, 파고드는 유저는 단서를 연쇄적으로 발견하며 숨겨진 이야기에 도달한다.
   힌트는 절대 표면의 공식성을 해치지 않는다 — "발견한 자에게만 존재"해야 한다.

■ 3. 필수 공개 섹션 (Google Play 요건 포함) — 전부 구현
1) 헤더: SERTZ 로고 타이틀 + "고객 지원 센터" 부제
2) 공지사항: 더미 공지 2~3건 (예: "v1.4 업데이트 안내", "콘텐츠 정비 완료 안내")
3) 자주 묻는 질문(FAQ) 6~8건. 반드시 포함할 주제:
   - 세이브 데이터는 어디에 저장되나요?
   - 게임 데이터를 완전히 삭제하고 싶습니다
   - 오류/버그를 신고하는 방법
   - 문의 후 응답까지 걸리는 시간
   ※ 그리고 이 질문을 반드시 하나 끼워 넣어라:
      Q. "마을에 있던 이상한 돌은 어디 갔나요?"
      A. "콘텐츠 정비를 위해 일시적으로 치웠습니다. 다시 만날 수 있을지는 아무도 모릅니다…"
      (이 답변은 5번의 ARG 트리거 e와 연결된다)
4) 계정 및 데이터 삭제 안내 (Google 심사 3요건을 명확히 충족):
   ① 개발자명 표기: SERTZ 운영팀
   ② 삭제 절차 — 아래 3가지 방법을 단계별로 안내:
      - 방법 1: 앱 실행 → 설정 → 「데이터 초기화」 선택
      - 방법 2: 기기에서 앱 삭제 (게임 데이터는 기기 로컬에만 저장되므로 앱 삭제 시 즉시 삭제)
      - 방법 3: 문의 이메일로 "계정/데이터 삭제 요청" 발송 → 영업일 3일 내 처리
   ③ 삭제되는 데이터 유형과 보관 기간:
      - 게임 진행 데이터(레벨, 장비, 재화, 진행도) — 기기 로컬에만 저장, 앱 삭제 시 즉시 삭제
      - 설정값(사운드, 조작 설정 등) — 기기 로컬, 즉시 삭제
      - 문의 메일 내용(기기명, OS 버전, 문의 내용) — 처리 완료 후 최대 12개월 보관 후 파기
      - 서버에 별도의 회원 정보를 저장하지 않음
5) 문의하기: mailto:support@sertz.game 링크 + 문의 시 포함할 정보 안내(기기명 / OS 버전 / 발생 상황 설명)
   코드에 <!-- TODO: 실제 운영 이메일로 교체 --> 주석을 달아둘 것
6) 푸터: © SERTZ / SERTZ 운영팀 / 게임 버전 표기

■ 4. 디자인 방향 (서브컬처/오타쿠 감성)
- 무드: 레트로 픽셀 아트 × 다크 판타지. 딥다크 배경(#0b0e1a 계열) + 네온 포인트 컬러(시안 #00e5ff, 마젠타 #ff2e88)
- 한글 픽셀 웹폰트를 CDN으로 로드 (예: Galmuri — jsDelivr CDN, 또는 둥근모꼴 DungGeunMo). 로드 실패 시 시스템 폰트로 폴백되게 할 것
- CRT 스캔라인 오버레이(은은하게), 타이틀에 간헐적 글리치 애니메이션(0.2초, 10~20초 간격으로 가끔만)
- RPG UI 차용 연출:
  - 섹션 제목에 게임식 라벨: [QUEST] 공지사항 / [SYSTEM] 데이터 삭제 / [TALK] 자주 묻는 질문
  - FAQ는 NPC 대화창 연출(▼ 깜빡이는 커서), 문의 폼은 "퀘스트 접수 창" 느낌
  - 페이지 상단에 얇은 HP/EXP 게이지 장식 (순수 장식)
- 모바일 퍼스트 반응형(360px 기준 무리 없이), 데스크톱에서도 깨지지 않게
- 외부 이미지 금지 — 모든 그래픽은 CSS/SVG/유니코드 문자로 직접 그려라

■ 5. ARG 힌트 설계 (핵심 — 아래 전부 구현)
세계관 설정(모든 힌트는 이 하나의 스토리로 연결되어야 한다):
  "개발진은 게임에서 이상한 돌을 삭제했다. 하지만 돌은 지워지지 않고 이 웹사이트에 남아, 자신을 관측하는 자에게 말을 건다."
쉬움 → 어려움 순서의 3단계로 배치해, 단서가 연쇄적으로 이어지게 만들어라.

[1단계 — 우연히 지나가다 발견]
  a. 푸터 맨 아래 아주 작고 어두운 회색 텍스트 한 줄: 「돌은 지워지지 않았다.」 (호버/터치 시 1회 플래시)
  b. 공지사항 문장 중 "정비"라는 단어에 title="observed" 속성 숨기기
  c. 일부 장식 요소의 alt/aria-label에 "stone", "Yoze" 같은 키워드 숨기기

[2단계 — 의심해서 만지작거리는 유저]
  d. 배경과 같은 색의 숨겨진 문장(드래그로 선택해야만 보임): 「요세유적 지하 3층 — 돌이 잠들던 곳을 기억하라.」
  e. FAQ "이상한 돌" 답변을 3회 연속 탭 → 대화창이 0.8초간 글리치하며 숨겨진 답변 노출:
     「…정비가 아니야. 그것은 이곳으로 옮겨진 것이다.」
  f. 페이지 로고를 7회 연속 클릭/탭 → 히든 대화창(NPC 대사 형식) 등장:
     「…너도 들리니? 돌이 속삭이는 소리가. / 이름이 궁금하다면… 거꾸로 읽어 보아라.」
     → 정답 키워드는 SERTZ를 거꾸로 쓴 "ZERTS" (상수로 관리)

[3단계 — 적극적으로 파고드는 유저]
  g. HTML 소스 주석에 Base64 암호문 1문장 삽입 (디코딩 시: 「소스를 보는 당신, 관측자의 자격이 있습니다. 다음 단서는 콘솔에 있습니다.」)
  h. 브라우저 콘솔(console.log)에 픽셀 아트 "돌" ASCII 아트 + 메시지 출력: 「관측자여, 환영한다. ZERTS 를 기억하라.」
  i. Konami 코드(↑↑↓↓←→←→BA) 입력 → 히든 섹션 「관측되지 않은 돌」 활성화: 배경이 더 어두워지고 CSS/SVG로 그린 픽셀 돌 오브젝트가 떠오르며 짧은 세계관 텍스트가 표시된다. 마지막 문장: 「마을로 돌아가라. 새벽의 유적에서 다시 만나자.」 (추후 게임 업데이트와 연계 예정)
  j. 뒷문: URL 파라미터 ?stone=awake 로 접속하면 i의 히든 섹션 즉시 활성화 (공유·검증용)

[구현 규칙]
  - ARG 문구·설정값은 전부 JS 상수 객체 ARG_DATA에 모으고 주석으로 "★ARG 수정 지점" 표시 — 운영자가 문구만 쉽게 교체할 수 있게
  - 히든 발동 시 0.2~0.5초 글리치/CRT 노이즈 연출로 "무언가 일어났다"는 감각을 줄 것
  - 모든 ARG 코드는 try/catch로 감싸라 — ARG가 죽어도 공식 페이지 기능은 절대 죽지 않게
  - 표면의 공식 문서 톤은 언제나 유지 — 힌트는 "발견했을 때만" 존재한다

■ 6. 기술 제약
- 산출물: index.html 단일 파일 (CSS/JS 전부 인라인)
- 정적 호스팅 가정(GitHub Pages 등): 서버리스, 빌드 불필요, 모든 경로는 상대경로만 사용
- 외부 리소스는 한글 픽셀 폰트 CDN 하나만 허용 (이미지·API·JS 라이브러리 호출 금지)
- mailto: 링크 외 외부 통신 없음
- <html lang="ko">, title / meta description / og 태그 작성 (og:description에 세계관 키워드를 아주 은근히 한 단어 섞을 것)
- 콘솔 에러 0 유지. 모바일 Chrome/Safari 최신 기준 동작
- JS가 꺼져 있어도 3번의 공개 섹션(문의·삭제 안내)은 완전하게 읽혀야 함 (ARG는 JS 의존 허용)

■ 7. 산출물 형식
1) index.html 1개 파일
2) 코드 맨 위 주석에 「운영자용 ARG 위치표」 작성: 각 힌트의 위치·발동 조건·노출 문구 요약
3) 답변 마지막에 운영자용 사용법 요약: 배포 방법(GitHub Pages), 나중에 수정할 곳(이메일·공지·ARG 문구 = ARG_DATA)

지금부터 위 사양을 전부 만족하는 index.html을 작성하라.
