■ 경고 1 — "이 App Bundle 유형과 연결된 가독화 파일이 없습니다"
──────────────────────────────────────────────
- 가독화 파일(mapping.txt)이란: R8(코드 난독화)을 켰을 때만 생성되는
  "난독화된 이름 ↔ 원래 이름" 대조표. 크래시 스택을 읽기 쉽게 되돌려 주는 파일.

- 이 앱의 상태: android/app/build.gradle release 블록이
    minifyEnabled false   ← 난독화 OFF
  → R8을 사용하지 않으므로 mapping.txt가 애초에 생성되지 않습니다.
    따라서 지금 업로드할 파일이 존재하지 않습니다.

- "난독화 비율 1%"의 정체: 우리 코드가 아니라 구글 SDK(광고 AdMob·결제 Billing·
  androidx) 안에 미리 난독화되어 배포되는 내부 클래스(zz… 형태 이름)가 1%로
  잡힌 것입니다. 우리 코드는 100% 원래 이름 그대로입니다.
  → 난독화가 없으므로 크래시 리포트가 이미 읽기 쉬운 상태. 이 경고는 무시해도 안전.

- 근본 해소(선택사항): 다음 버전(vc123) 빌드부터 R8을 켜면 됩니다.
    release {
        minifyEnabled true
        shrinkResources true
        proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
    }
  → 빌드 시 mapping.txt가 자동 생성되어 경고가 사라지고, 코드(덱스) 일부 축소.
  ※ 원하시면 다음 릴리스에 적용해 드립니다. 적용 시 결제·광고·게임 부팅
    회귀 테스트를 함께 진행합니다. (기능상 리스크는 낮은 편)

■ 경고 2 — "네이티브 코드를 포함하며 디버그 기호가 업로드되지 않았습니다"
──────────────────────────────────────────────
- 이 경고가 원래 뜨는 경우: 앱에 C/C++ 네이티브 라이브러리(.so)가 들어 있을 때,
  크래시 분석용 기호 파일을 함께 올리라는 권고.

- 이 앱의 실측 결과: AAB 전수 검사(총 4,674개 항목) 결과 .so 네이티브 라이브러리
  0개입니다. 구성은 아래와 같습니다.
    · 게임 에셋(base/assets) 4,137개 — Next.js 게임 본체
    · 리소스(base/res) 439개
    · 덱스(base/dex) 2개 — classes.dex 9.3MB + classes2.dex 8.1MB (코드 17.4MB)
    · 메타데이터·서명 79+ 여러 개
  → Capacitor(웹뷰 하이브리드) 앱이라 네이티브 바이너리가 없는 것이 정상이며,
    업로드할 기호 파일 자체가 없습니다. 이 경고 역시 무시 가능합니다.
    (번들 처리가 완료되면 카드가 저절로 사라지는 경우도 있습니다.)

■ "AGP 9.0으로 업그레이드하세요" / "축소 비율 -" 안내에 대하여
──────────────────────────────────────────────
- 구글이 모든 개발자에게 보여주는 일반 광고문입니다.

  마이그레이션 작업이 필요하고, 지금 얻는 이득이 없습니다. 무시 권장.
