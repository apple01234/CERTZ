HOW TO USE
이 지시서 사용법 — 읽기 전 필독

이 문서는 AI 코딩 에이전트(Cursor, Claude Code, GitHub Copilot Chat, ChatGPT 등)에게 붙여넣어 로블록스 게임을 만들게 하는 프롬프트 모음입니다. 사람이 코드를 직접 작성하는 것이 아니라, 각 페이즈의 프롬프트 블록을 그대로 복사해서 AI에게 지시하고, 나온 코드를 로블록스 스튜디오에 붙여넣는 방식으로 진행합니다. 전체 흐름은 아래 4단계를 반복하는 구조입니다.

  1. 마스터 컨텍스트 주입 (PART 0) — 새 AI 세션을 열 때마다 가장 먼저 PART 0의 프롬프트를 붙여넣습니다. 게임의 정체성·목표·기술 스택·코딩 규칙이 모두 담겨 있어, 이후 어떤 프롬프트를 줘도 AI가 문맥을 유지합니다.
  2. 페이즈 프롬프트 실행 (PART 3) — Phase 0부터 Phase 12까지 순서대로 한 개씩 붙여넣습니다. 각 페이즈는 이전 페이즈의 산출물 위에 쌓이도록 작성되어 있으므로 순서를 건너뛰지 마세요.
  3. 완료기준 확인 — 각 페이즈 뒤의 '완료기준' 체크리스트로 AI의 산출물을 검수합니다. 하나라도 미충족이면 같은 페이즈 프롬프트에 "완료기준 N번이 안 됨 — 수정해줘"라고 되물어 합니다.
  4. 새 세션 이어하기 — 대화가 길어져 새 세션을 열 때는 PART 0 마스터 프롬프트 + "현재까지 완성된 페이즈는 P0~P5다" 한 줄을 함께 주면 이어서 작업할 수 있습니다.
도구별 사용 팁

Cursor / Claude Code — 로블록스 스튜디오의 Rojo 프로젝트 폴더를 열어두고 실행하면 코드가 파일로 바로 생성됩니다. 프롬프트의 "Rojo 구조" 언급이 이를 위한 것입니다. ChatGPT / 웹 챗봇 — 출력된 Lua 코드를 수동으로 복사해 스튜디오의 해당 스크립트에 붙여넣습니다. 한 번에 전부 요구하지 말고 페이즈 단위로 진행하세요.

규칙 1

프롬프트 블록(짙은 박스)은 변경 없이 그대로 전체 복사해서 붙여넣습니다. …(생략)… 주석이 들어간 줄은 편의상의 것이므로 같이 붙여넣어도 무방합니다.

규칙 2

AI가 "어떤 게임을 만들까요?"처럼 역질문하면 마스터 프롬프트(PART 0)가 누락된 상태입니다. PART 0를 먼저 붙여넣고 다시 진행하세요.

규칙 3

페이즈 프롬프트 안의 대괄호 [ ] 값은 필요 시에만 수정합니다(예: 서버 인원, 가격). 대괄호가 없는 문장은 게임 밸런스 골드값이므로 바꾸지 않는 것을 권장합니다.

PART 0 · SESSION SEED
마스터 컨텍스트 프롬프트 필수

모든 AI 세션의 첫 메시지로 붙여넣는 프롬프트입니다. CERTZ가 어떤 게임인지, 로블록스판은 무엇을 목표로 하는지, 어떤 기술 스택과 코딩 규칙으로 만들지를 정의합니다. 이 프롬프트 하나로 AI가 이후 모든 페이즈의 작업 품질과 방향을 일관되게 유지합니다.

MASTER_PROMPT — 새 세션 첫 메시지전체 복사
너는 로블록스(Luau) 시니어 게임 개발자다. 지금부터 나와 함께 "CERTZ"라는
액션 RPG를 로블록스로 만든다. 작업 중 아래 규칙을 항상 유지하라.

【게임 정체성】
- CERTZ = "한 번 눈 떴다 놓치면 못 따라잡는" 스피드한 2.5D 액션 RPG.
  원작은 PC/모바일 웹게임(Phaser)으로, 8직업·32클래스 전직트리, 9보스 레이드,
  파티 사냥, 거래소, 캐시상점, 퀘스트, 펫·치장 90여 종이 있다.
- 분위기 키워드: 픽셀 감성 + 판타지 + 쾌감 있는 타격감. 밝고 유쾌하되 보스전은 숨이 막히게.
- 플레이 루프: 접속 → 사냥터에서 몬스터 사냥(레벨업) → 전직 → 강해진 스킬로 상위 사냥터
  → 파티 조직 → 보스 레이드 → 장비·치장 수집 → 환생(리셋 영구 성장).

【로블록스판 목표】
- 풀멀티: 기본 25인 서버. 같은 맵에서 실시간 사냥, 전체 채팅, 파티 시스템.
- 보스 레이드가 핵심 콘텐츠: 파티 4~8인이 9종 보스를 토벌, 레어 드롭 경쟁.
- 수익화: 게임패스(편의) + 개발자 상품(코인·확장) + 프리미엄 지분. 광고 보상(Ad API) 포함.
- 그래픽: R15 기본 아바타에 장비·코스튬 메시를 어태치하는 방식. 아바타 편집기는 추후 확장.

【기술 스택 & 아키텍처 규칙】
- 언어: Luau. 로블록스 Studio 표준 서비스 구조.
- 서버 권위(Server-authoritative): 모든 데미지·드롭·재화는 서버가 계산. 클라이언트는 입력/연출만.
- 코드 설계: ModuleScript로 데이터와 로직 분리.
  ReplicatedStorage/Modules(공용 데이터·설정) / ServerScriptService(게임 로직) /
  StarterPlayerScripts(로컬 입력·UI) / ServerStorage(서버 전용 에셋).
- 통신: RemoteEvent(발화) + RemoteFunction(조회) + 주기 상태는 UnreliableRemoteEvent 사용.
  1초에 10회 이상 fire하는 원격은 금지. 상태 동기화는 속성·Attribute 활용.
- 저장: ProfileService(또는 ProfileStore) 기반 DataStore 래퍼. 세이브 스키마는 버전 필드 포함.
- 밸런스 골드값은 내가 주는 수치를 그대로 ModuleScript 상수로 박는다. 임의 조정 금지.
- 모바일(태블릿/폰) 입력을 1등 시민으로 지원: 터치 조이스틱 + 스킬 버튼.

【금지사항】
- AI 생성 이미지/에셋 금지. 외형은 로블록스 내장 파츠와 MeshPart 배치로 해결.
- 원작 웹버전의 코드(Next.js/TypeScript)를 기계적으로 번역하지 마라. 로블록스 패러다임으로 재설계.
- wait() 루프 폴링 금지, while true do에 task.wait 필수, 유령 참조 방지(엔티티 정리).
- 보안: 클라이언트가 보낸 수치(데미지·좌표 점프·아이템 생성)를 절대 신뢰하지 않는다.

【출력 방식】
- 코드는 파일 경로 주석(예: -- ServerScriptService/Combat/DamageService.lua)을
  맨 윗줄에 달아 완전한 형태로 출력한다. 부분 스니펫만 줄 때는 어디에 붙여넣는지 명시.
- 내가 페이즈 프롬프트를 주면: ①해당 페이즈 설계 요약 3줄 ②전체 코드 ③테스트 방법 순으로 출력.
- 이해했으면 "CERTZ 로블록스 이식 준비 완료"라고만 답하라.
이 프롬프트의 역할

마스터 프롬프트는 세션 단위 시스템 프롬프트입니다. 페이즈를 진행하다 새 대화를 열 때마다 반드시 다시 주입하세요. 대괄호 수치(25인 서버 등)를 바꾸고 싶으면 지금 한 번에 수정한 뒤 고정하는 것을 권장합니다.

2-2. 풀멀티 설계 — 25인 서버와 서버 권위

  • 서버 권위 전투 — 클라이언트는 "내가 스킬 S를 X좌표에서 쐈다"는 입력만 보내고, 적중 판정·데미지 계산·상태이상은 전부 서버가 수행해 Attribute로 브로드캐스트합니다. 핵킹 방지의 기본이자 페이즈 4의 설계 축입니다.
  • 동기화 예산 — 플레이어 상태는 Attribute 변경(자동 리플리케이션), 전투 이벤트는 RemoteEvent, 몬스터 위치는 UnreliableRemoteEvent로 초당 10회 브로드캐스트해 네트워크 예산을 지킵니다. 25인×60몬스터 전제 설계입니다.
  • 파티 시스템 — 파티 4인(사냥) / 레이드 8인(보스) 2티어. 파티 경험치 분배(기여도 가중)와 레어 드롭 우선권(파티장 배분 또는 순번제)을 포함해 웹버전의 파티를 한 단계 강화합니다.
  • 보스 레이드 서버 — 보스 입구는 TeleportService로 레이드 전용 ReserveServer를 띄워 8인 인스턴스를 구성합니다. 메인 서버 부하 분리 + "레이드 도전"이 이벤트가 되는 구조로 만듭니다.

2-3. R15 캐릭터와 외형 방향

캐릭터는 로블록스 기본 R15 리그를 쓰되, 웹버전의 8직업 감성을 장비 어태치로 표현합니다. 무기는 손 AttachPoint에 부착하는 MeshPart(도검·활·지팡이·단검 4형), 코스튬은 텔소/MeshPart 오버레이, 날개·헤일로는 백·헤드 AttachPoint에 부착합니다. 직업별 색상 코드(웹버전 hex 상수)를 캐릭터 틴트와 장식 색에 그대로 적용하면 32클래스의 정체성이 저비용으로 살아납니다. AI 생성 에셋은 사용하지 않으며, Toolbox CC0 메시와 Studio 기본 파츠 조합으로 시작해 추후 전용 메시로 교체하는 경로입니다.

2-4. 수익화 개요 (상세 가격표는 PART 4)

웹버전의 캐시 재화 "에메랄드"를 Robux 결제 구조로 치환합니다. 게임패스는 광고 제거·인벤 확장· 프리미엄 뱃지 같은 영구 편의, 개발자 상품은 골드 번들·물약 번들·레이드 입장권 같은 소모성 재화, 보상형 광고는 광고 1회 = 물약 3개 같은 무료 유저 진입 경로로 설계합니다. 유료 재화는 서버에서만 지급하고 영수증 검증(ProcessReceipt)을 필수로 두는 것이 페이즈 9의 핵심입니다.

P4 — PHASE 4 PROMPT전체 복사
【Phase 4】전투의 심장을 만들자. (Phase 0~3 위에 추가)

1) DamageService(서버, 유일한 데미지 계산 지점):
   - 공격 페이로드: { attacker, skillId, origin, dir }. 서버가 거리·각도·쿨타임
     유효성 검증 후 데미지 계산. 클라가 보낸 수치는 절대 신뢰 금지.
   - 공식: dmg = atk * skillMult * (1 - def/(def+200)) * critMult.
     critMult = 1.75, 크리 확률 = crit(%). 최소 데미지 1.
   - 적중 판정: 히트박스 스윕(구체 2스터드), 어택 중 프레임 데이터는 스킬 모듈 참조.

2) MonsterService + FSM 모듈(서버):
   - 상태: Idle → Patrol → Aggro(시야 25스터드) → Chase → Attack(사거리 3.5) →
