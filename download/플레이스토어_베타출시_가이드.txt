  SERTZ — 플레이스토어 베타(내부 테스트) 출시 가이드  (v1.1.0 기준)
════════════════════════════════════════════════════════════════════

이 문서는 SERTZ를 구글 플레이스토어에 "베타(내부 테스트)"로 처음 올리기 위해
운영자(당신)가 직접 해야 할 일을 순서대로 정리한 것이다.
소요 시간: 계정 준비가 되어 있으면 1~2시간, 신규 계정이면 결제 후 심사 포함 1~7일.

────────────────────────────────────────────────────────────────────
0. 준비물 요약
────────────────────────────────────────────────────────────────────
  □ 구글 계정 (개발자용으로 새로 만드는 것 권장)
  □ 구글 플레이 콘솔 등록비 25달러 (1회성, 신용카드/체크카드)
  □ 본인 확인용 신분증 (개인 등록 시 48시간 내외 확인)
  □ 개인정보처리방침을 올릴 웹페이지 URL (아래 6번에서 직접 제공)
  □ 업로드할 AAB 파일 (빌드 방법은 7번)

────────────────────────────────────────────────────────────────────
1. 개발자 계정 만들기
────────────────────────────────────────────────────────────────────
  1) https://play.google.com/console 접속 → 구글 계정 로그인
  2) "개발자 계정 만들기" → 개인 계정 선택 (회사가 아니면 개인으로 충분)
  3) 개발자 이름 입력 (스토어에 공개됨 — 예: SERTZ Studio)
  4) 등록 수수료 25달러 결제
  5) 신원 확인 완료까지 대기 (보통 몇 시간~2일)

────────────────────────────────────────────────────────────────────
2. 앱 생성
────────────────────────────────────────────────────────────────────
  1) 콘솔 좌측 "모든 앱" → "앱 만들기"
     · 앱 이름: SERTZ (또는 "SERTZ : 이그드라실의 검")
     · 기본 언어: 한국어(KR)
     · 앱/게임: 게임
     · 무료/유료: 무료 (베타 기간 무료 권장)
  2) 생성 후 "대시보드"에 나오는 할 일 목록을 하나씩 처리한다.

────────────────────────────────────────────────────────────────────
3. 내부 테스트(베타) 트랙 설정 — 심사가 가장 빠르고 안전한 경로
────────────────────────────────────────────────────────────────────
  1) 좌측 "테스트 → 내부 테스트" 선택
  2) "테스터" 탭 → 이메일 목록 만들기 (본인 + 지인 구글 계정)
     · 내부 테스트는 최대 100명까지 즉시 배포 가능
  3) "릴리스" 탭 → 새 릴리스 만들기 → 7번에서 만든 AAB 업로드
     · 릴리스 이름: v1.1.0 (86)
     · 출시 노트 예시:
       ─ 캐릭터 외형 시스템: 남캐/여캠 선택 + 피부 6종 + 완전 교체 코스튬 10종 + 장식 5종
       ─ 프롤로그·인트로 시네마틱 신설
       ─ 몬스터 벽 뚫림·카오스 보스전 암전·EERT 큐브 등급 하락 등 20여 건 버그 수정
  4) "검토 후 출시" → 내부 테스트는 보통 몇 시간 내 승인 (최대 7일)

  ※ "비공개 테스트(폐쇄 테스트)"는 최소 20명 테스터 14일 운영 요건이 있다.
     정식 출시(프로덕션) 전에 이 요건을 채워야 하므로, 내부 테스트로 기능 검증 →
     비공개 테스트 20명 모집 → 프로덕션 순서를 권장한다.

────────────────────────────────────────────────────────────────────
4. 스토어 등록정보 (스토어에 보이는 페이지)
────────────────────────────────────────────────────────────────────
  · 앱 아이콘 512×512 PNG (android/app/src/main/res/mipmap-xxxhdpi/ic_launcher.png 재활용 가능)
  · 정사각형 아이콘은 배경 없는 순수 로고 권장
  · 최소 스크린샷 2장 (권장 4~8장: 타이틀/전투/유니온/캐릭터 생성 화면)
    - 16:9 또는 9:16, 각 변 최소 320px 최대 3840px
  · 기능 그래픽 1024×500 JPG/PNG (배너 이미지)
  · 짧은 설명 (80자 이내) 예시:
    "세계수의 결정을 되찾아라! 도트 액션 RPG — 전직·유니온·보스레이드"
  · 전체 설명 (4000자 이내) — 게임 소개 + 주요 시스템 나열

────────────────────────────────────────────────────────────────────
5. 콘텐츠 등급 / 타겟 오디언스
────────────────────────────────────────────────────────────────────
  · 콘텐츠 등급 설문: 폭력(몬스터 사냥 — 비묘사 수준), 혐오 표현 없음, 도박 요소
    주의: "뽑기(가챠)"가 있는 경우 확률형 아이템 문답에 정직하게 답변할 것.
    유료 재화(에메랄드)로 하는 뽑기가 있으면 "사용자가 구매로 획득 가능한
    확률형 아이템" = 예 답변 → 등급이 올라갈 수 있음 (12세/청소년 불가 등).
    베타 기간엔 캐시상점을 닫아두면 등급 리스크가 줄어든다.
  · 타겟 연령: 13세 이상 권장 (온라인 채팅 기능이 있으므로 12세 이하 대상 제외)
  · 데이터 안전 양식 (아래 6번과 일치시킬 것):
     - 수집 항목: 이메일(계정 ID), 닉네임, 게임 세이브(클라우드 백업)
     - 수집 목적: 계정 인증, 게임 저장/복원
     - 전송 중 암호화: 예 (HTTPS)
     - 삭제 요청 방법 제공: 예 (탈퇴 기능 또는 문의 이메일)

────────────────────────────────────────────────────────────────────
6. 개인정보처리방침 URL (필수 — 없으면 심사 반려)
────────────────────────────────────────────────────────────────────
  · 게임 서버에 정적 페이지로 제공하는 것을 권장: https://<서버도메인>/privacy.html
  · 최소 기재사항: 수집 항목(계정 ID·닉네임·세이브), 이용 목적, 보관 기간,
    제3자 제공 없음, 문의처 이메일
  · 참고: 게임 내 계정 서버는 ID+비밀번호(scrypt 해시)와 게임 세이브만 저장하며
    제3자 공유/광고 식별자 수집은 하지 않는다 — 이 사실을 그대로 쓰면 된다.

────────────────────────────────────────────────────────────────────
7. AAB 빌드 (서버에서 실행 — 운영자가 직접 할 일은 아님)
────────────────────────────────────────────────────────────────────
  서버에서:
    1) bun run build            # 웹 빌드
    2) JAVA_HOME=/home/z/jdk bash scripts/build_apk.sh    # cap sync 포함
    3) JAVA_HOME=/home/z/jdk bash scripts/build_aab.sh    # AAB 생성
  → android/app/build/outputs/bundle/release/app-release.aab
  → 이 파일을 콘솔 내부 테스트 릴리스에 업로드

  ⚠ 플레이 스토어는 APK가 아니라 AAB만 받는다. (APK는 GitHub Release 배포용으로 유지)
  ⚠ versionCode는 이전 업로드보다 항상 커야 한다 (현재 86 → 다음 87, 88, ...)

────────────────────────────────────────────────────────────────────
8. 출시 전 필수 보안 체크 (서버 운영자용)
────────────────────────────────────────────────────────────────────
  □ SERTZ_ADMIN_PASSWORD 환경변수 설정 (미설정 시 관리자 계정이 기본 비밀번호로
    시드될 수 있음 — 서버 부팅 로그에 경고가 뜬다)
  □ SERTZ_ADMIN_USERS에 운영자 아이디만 남았는지 확인
  □ 서버 HTTPS 적용 확인 (이미 Caddy 적용)
  □ 계정 DB 백업 동작 확인 (db-backup/ 자동 백업)
  □ 로그인/가입 레이트리밋 동작 확인 (이미 적용: 로그인 15회/5분)

────────────────────────────────────────────────────────────────────
9. 출시 전 저작권 최종 확인
────────────────────────────────────────────────────────────────────
  □ Mystic Woods (Game Endeavor) — 히어로/캐릭터 스프라이트 원본
    → 프리미엄(유료) 버전 소유 증명 확인 필수. 무료 버전 출처라면
      상업 배포 전 itch.io에서 프리미엄 업그레이드 구매 (~$10).
    → 팩 원본 재배포 금지 — 게임 내장(파생 스프라이트)은 의도된 용도로 OK
  □ 32rogues — 영리 가능 (NFT/블록체인/AI-ML 프로젝트만 제외)
  □ CC0 자산 (Kenney/ArMM1998/0x72 등) — 제약 없음, 크레딧 표기 권장(이미 표기)
  □ Kevin MacLeod BGM 40트랙 — CC-BY 4.0 (타이틀 크레딧 표기 이미 있음 — 유지할 것)
  □ 효과음연구소 SFX — 상업 이용 무료, 재배포만 금지
  □ Unity 에셋스토어 유료 (SPUM/Vefects/Hovl 등) — 게임 빌드 내장은 EULA 허용 범위
  □ "메이플스토리" 상표: 스토어 설명문에 넥슨 상표/명칭을 직접 쓰지 말 것
    ("메이플 스타일" 같은 표현도 스토어 등록정보에서는 피하는 것이 안전)
  □ 게임 내 크레딧 유지: 타이틀 화면 하단 크레딧 + public/assets/CREDITS.md

────────────────────────────────────────────────────────────────────
10. 베타 운영 팁
────────────────────────────────────────────────────────────────────
  · 내부 테스트 링크는 콘솔이 만들어주는 opt-in URL을 지인에게 공유
  · 콘솔 "Android vitals"에서 크래시율 모니터링
  · 서버 콘솔의 db/audit.log로 계정 가입/로그인 이상 감시
  · 업데이트 배포: 새 versionCode로 AAB 재업로드 → 내부 테스트 트랙에 새 릴리스
  · 게임 내 구버전 감지 배너(v1.0.17+)가 이미 있으므로 APK 직배포 유저도 자동 안내됨
