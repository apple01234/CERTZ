4-1. E2E 검증 프롬프트 (P12 이후 언제든 실행)

전 시스템을 한 바퀴 돌리는 통합 테스트 지시입니다. 페이즈를 몇 개만 완성했으면 해당 범위만 남겨 실행하세요. 버그가 발견되면 아래 리포트 양식으로 AI에게 되물어 합니다.

VERIFY — E2E TEST PROMPT전체 복사
【E2E 검증】지금까지 구현한 시스템을 통합 테스트하자. 아래 시나리오 각각에 대해
①필요한 테스트 코드(자동 검증 스크립트 또는 수동 절차) ②예상 결과 ③실패 시
원인 후보 3가지를 출력하라.

S1 세이브: 접속→골드 지급→강제 종료→재접속 = 골드 보존
S2 전투: 스킬 36종 각각 1회 발동 — 오류·쿨타임 무시·MP 음수 0건
S3 전직: 4계열 모두 1차→4차 완주 + 자유전직 2회 — 트리 누락 경로 0건
S4 레이드: 9보스 각각 토벌 1회 — 페이즈 전환·드롭·귀환 정상
S5 파티: 4인 구성→사냥→분배→레이드 8인→해산 — 분배 오차 0
S6 상점: 골드 구매 10건 / 게임패스 효과 4종 / 데브상품 6종 이중지급 0건
S7 수집: 에그 3개 획득→구간보상 / 퀘스트 일일 리셋
S8 운영: GM 커맨드 권한 검증 / 랭킹 갱신 / 환생 플로우
S9 모바일: 디바이스 에뮬레이터 3종(폰/태블릿) 조작·UI 표시
S10 보안: 클라 위조 공격(데미지·좌표·아이템 생성) 서버 거부

버그 리포트 양식(발견 시 이 형식으로 출력):
[BUG-n] 제목 / 재현 절차 / 기대 vs 실제 / 원인 파일·함수 / 수정 코드 / 회귀 테스트 방법

4-2. 로블록스 함정 10선 — AI에게도 미리 알려주기

다음 10개는 로블록스 개발에서 가장 흔한 사고 지점입니다. AI가 마스터 프롬프트의 규칙을 놓쳤다 싶으면 해당 항목을 인용해 지적하세요. 각 페이즈 프롬프트가 이미 대부분 예방하도록 작성돼 있지만, 리뷰 시 체크리스트로 활용합니다.

#함정대처
1DataStore 한도키당 4MB, 플레이어당 초당 쓰기 제한. 오토탈 30초 + 이벤트 시 저장으로 해결(P1 설계에 반영됨)
2ProcessReceipt 이중지급영수증 ID 기록 없이 지급하면 재시도 때 복제됨. 반드시 처리 기록 후 true 반환(P9)
3클라 신뢰클라가 보낸 데미지·아이템은 전부 위조 가능. 서버 재검증 원칙(P4)
4RemoteEvent 스팸초당 다수 fire → 네트워크 붕괴. 상태는 Attribute, 위치는 Unreliable(P4·P8)
5Humanoid 물리 랙몬스터 100체 Humanoid는 서버에 무겁다. 사고 스로틀 + 정리(Despawn) 필수(P4)
6wait() 폴링while true do wait(0.1)로 상태 감시하면 크래시 전조. task.wait + 이벤트 구독으로 교체
7모바일 UI 가림채팅·버튼이 조이스틱과 겹침. TouchEnabled 분기 레이아웃 필수(P3)
8Teleport 시 세이브 유실레이드 서버 이동 전 저장 + 귀환 후 재로드. 데이터는 Place별로 독립됨(P7)
9유령 참조사망한 몬스터/떠난 플레이어를 계속 참조하면 메모리 누수. Destroy 후 nil 체크 습관화
10Studio≠실서버스튜디오 통과 ≠ 실서버 통과. 퍼블리시 후 실서버에서 S1~S10 재실행 권장

4-3. 수익화 가격표 — 게임팸스 4종 · 개발자 상품 6종

웹버전 캐시 상점(에메랄드 90종)을 로블록스 결제 구조로 압축한 설계입니다. Robux 가격은 로블록스 수수료(약 30%)와 개발자 지분(프리미엄 가입자 이용분 70% 배분)을 감안한 표준 밴드이며, 출시 후 판매 데이터로 조정합니다. 게임패스는 영구 소유 효과만 올리고, 강한 전투력(스탯·장비)은 판매하지 않는 것이 커뮤니티 신뢰를 지키는 원칙입니다.
