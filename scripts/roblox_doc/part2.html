PART 2 · REDESIGN BLUEPRINT
로블록스 재해석 설계

2-1. 아키텍처 매핑 — 웹버전 → 로블록스

페이즈 프롬프트를 줄 때마다 AI가 이 매핑표를 기준으로 설계합니다. 원작의 어떤 개념이 로블록스의 어떤 구성요소로 이동하는지를 한눈에 보여주는 표로, 마스터 프롬프트 다음에 PART 2 요약본을 함께 주면 AI의 설계 일관성이 크게 올라갑니다.

2-2. 풀멀티 설계 — 25인 서버와 서버 권위

  • 서버 권위 전투 — 클라이언트는 "내가 스킬 S를 X좌표에서 쐈다"는 입력만 보내고, 적중 판정·데미지 계산·상태이상은 전부 서버가 수행해 Attribute로 브로드캐스트합니다. 핵킹 방지의 기본이자 페이즈 4의 설계 축입니다.
  • 동기화 예산 — 플레이어 상태는 Attribute 변경(자동 리플리케이션), 전투 이벤트는 RemoteEvent, 몬스터 위치는 UnreliableRemoteEvent로 초당 10회 브로드캐스트해 네트워크 예산을 지킵니다. 25인×60몬스터 전제 설계입니다.
  • 파티 시스템 — 파티 4인(사냥) / 레이드 8인(보스) 2티어. 파티 경험치 분배(기여도 가중)와 레어 드롭 우선권(파티장 배분 또는 순번제)을 포함해 웹버전의 파티를 한 단계 강화합니다.
  • 보스 레이드 서버 — 보스 입구는 TeleportService로 레이드 전용 ReserveServer를 띄워 8인 인스턴스를 구성합니다. 메인 서버 부하 분리 + "레이드 도전"이 이벤트가 되는 구조로 만듭니다.

2-3. R15 캐릭터와 외형 방향

캐릭터는 로블록스 기본 R15 리그를 쓰되, 웹버전의 8직업 감성을 장비 어태치로 표현합니다. 무기는 손 AttachPoint에 부착하는 MeshPart(도검·활·지팡이·단검 4형), 코스튬은 텔소/MeshPart 오버레이, 날개·헤일로는 백·헤드 AttachPoint에 부착합니다. 직업별 색상 코드(웹버전 hex 상수)를 캐릭터 틴트와 장식 색에 그대로 적용하면 32클래스의 정체성이 저비용으로 살아납니다. AI 생성 에셋은 사용하지 않으며, Toolbox CC0 메시와 Studio 기본 파츠 조합으로 시작해 추후 전용 메시로 교체하는 경로입니다.

2-4. 수익화 개요 (상세 가격표는 PART 4)

웹버전의 캐시 재화 "에메랄드"를 Robux 결제 구조로 치환합니다. 게임패스는 광고 제거·인벤 확장· 프리미엄 뱃지 같은 영구 편의, 개발자 상품은 골드 번들·물약 번들·레이드 입장권 같은 소모성 재화, 보상형 광고는 광고 1회 = 물약 3개 같은 무료 유저 진입 경로로 설계합니다. 유료 재화는 서버에서만 지급하고 영수증 검증(ProcessReceipt)을 필수로 두는 것이 페이즈 9의 핵심입니다.

로블록스 한계 — 처음부터 알고 설계하기

① 개인 간 자유 거래는 플랫폼 정책상 제한이 크므로 트레이드 창(대면 확인식)으로만 지원합니다. ② 웹버전의 코드 생성 맵은 Studio 수동 빌드로 대체합니다(프로그래매틱 배치는 부분 지원). ③ 서버 인스턴스당 인원은 설계 목표 25인이지만 로블록스 기본값 50인 범위 내에서 운영 단계에 조정합니다.
