Phase 7 — 맵·사냥터·보스 레이드 필수

마을 + 다층 사냥터 + 9종 보스 레이드 공간을 만듭니다. 보스는 CERTZ의 최대 강점으로 페이즈 패턴 레이드로 완성합니다.

P7 — PHASE 7 PROMPT전체 복사
【Phase 7】세계 구조와 보스 레이드를 만들자. (Phase 0~6 위에 추가)

1) MapsService — Workspace/Maps 아래 3개 구역을 프리빌트로:
   - 마을 Village: 안전구역(전투 금지), NPC 배치(전직·상점·퀘스트·치장), 포탈 2개.
   - 사냥터 HuntZone1~3: 층식 구조(층마다 몬스터 티어 상승), 포탈 파트 연결,
     웹버전처럼 포탈 진입 시 카메라 줌 전환(P3 카메라 상수 활용).
   - 레이드 공간 RaidArena: 보스 1체 전용 거대 원형 아레나, 등장 연출 공간 포함.

2) PortalService: 포탈 파트 터치 → 로딩 페이드 → 위치 이동(같은 Place는 Teleport
   대신 좌표 이동). 쿨다운 2초로 진동 방지.

3) RaidService — 이 페이즈의 핵심:
   - 보스 9종 데이터 GameData/Bosses: 수호자·로드·펜리르·스콜·수르트·니드호그·
     그람·아부디토스·베헤모스. { hp, atk, patternSet, drops, phases: 1~3 }.
   - 페이즈 전환: HP 100→70%(P1)→40%(P2)→15%(P3/광폭). 전환마다 패턴세트 교체 +
     등장 룬 마법진 연출(파티클 원형 + 사운드).
   - 시그니처 패턴 4종 구현으로 통일: 부채꼴 브레스 / 원형 충격파(점프 회피) /
     돌진 잔상 / 소환수 4마리. 보스마다 4종을 재조합한 patternSet 정의.
   - 입장: 레이드 포탈 → ReserveServer로 8인 전용 서버 생성(TeleportService) →
     토벌 성공 시 메인 서버로 귀환 + 드롭 지급. 실패 시 전멸 후 귀환.
   - 보스전 자동금지 원칙: 레이드 서버에서 자동전투 비활성(수동 조작만).

4) BossIntroService: 보스 등장 3초 카메라 시네마틱(이름·HP바 UI 등장).

출력: ①맵 구조 다이어그램(텍스트) ②전체 코드 ③9보스 패턴 조합표 ④레이드 입장→
토벌→귀환 전체 플로우 테스트 시나리오(2인 로컬 서버).
완료기준 — 실측 확인
  • 마을↔사냥터 3층 이동이 포탈로 매끄럽게 이어진다
  • 보스전에서 페이즈 3번 전환과 패턴 교체가 실측된다
  • 레이드 서버 생성→8인 입장→토벌→메인 귀환 플로우가 동작한다
  • 보스 연출(룬 마법진·시네마틱)이 모든 클라에 동시 표시된다

Phase 8 — 파티·채팅·멀티 완성 필수

25인 서버에서의 실시간 멀티 요소를 완성합니다. 파티(4인 사냥/8인 레이드), 채팅 연동, 경험치 분배를 구축합니다.

P8 — PHASE 8 PROMPT전체 복사
【Phase 8】멀티플레이를 완성하자. (Phase 4~7 위에 추가)

1) PartyService(서버):
   - 파티 생성/초대/수락/거절/탈퇴/해산(RF_Party·RE_Party). 최대 4인(일반),
     레이드 8인.
   - 파티원 HP·위치 미니 HUD(좌측 상단, 4인 표시).
   - 경험치 분배: 사냥터 내 파티원 등록 기여도(데미지 비중) 가중 분배.
   - 파티 채팅 채널: TextChatService 커스텀 채널 "Party" 등록, 파티원만 보임.

2) 전체 채팅: 로블록스 TextChatService 기본 전체 채팅에 CERTZ 커스텀 적용 —
   채팅창 접기 버튼, 레벨 표기(예: [Lv45] 닉네임), 채팅 로그 상단 3줄 미니 뷰.

3) 동기화 리팩터링: 25인 기준 성능 점검 — 몬스터 상태 브로드캐스트가
   UnreliableRemoteEvent인지, Attribute만 리플리케이션하는지 재확인.
   플레이어간 상호 작용(파티 표시 링, 같은 몬스터 어그로 공유) 검증.

4) 소셜: 파티 초대는 다른 플레이어 이름 클릭 → 팝업. 로블록스 친구 목록 연동은
   기본 Players 서비스로 충분.

5) 성능 검증 프롬프트: Studio 테스트 탭 8인 로컬 서버(최대)에서
   Performance Stats 캡처 지점 안내 포함.

출력: ①설계 요약 ②전체 코드 ③파티 플로우 시나리오(생성→초대→사냥→레이드→해산)
④채팅 채널 등록 확인 방법 ⑤8인 부하 체크리스트.
완료기준 — 실측 확인
  • 파티 4인 구성 후 사냥 시 경험치가 기여도 가중으로 분배된다
  • 파티 채팅이 파티원에게만 보인다(옆 서버 플레이어에게 미노출)
  • 파티 HUD에 파티원 HP가 실시간 표시된다
  • 8인 로컬 테스트에서 프레임 드롭·레이션 스파이크가 허용선 내다

Phase 9 — 상점·쿠폰·게임패스 수익화 필수

BM상점(골드 재화)과 로블록스 결제(게임패스·개발자 상품)를 구축합니다. 가격표는 PART 4의 표를 그대로 사용합니다.

P9 — PHASE 9 PROMPT전체 복사
【Phase 9】상점과 수익화를 만들자. (Phase 6 인벤 위에 추가)

1) ShopService(서버):
   - 골드 상점: 물약·버프·장신구 티어 1~2 등 소모/장비 21종 상시 판매.
   - 캐시 상점 대체 "로브룩스 샵": Robux 전용 = 게임패스/개발자 상품 연결 UI.
     (현금 재화는 두지 않는다 — 결제 즉시 상품 지급이 로블록스 원칙)
   - 특가 탭: 날짜 시드 기반 3종 로테이션(원작 dailyDeals 규칙 이식).
   - 출석 도장: 일일 접속 시 도장 1개, 7일 연속 보상 테이블, DataStore 날짜 관리.

2) 결제 시스템:
   - GamePassService: 게임패스 4종 구매 확인(UserOwnsGamePass) → 효과 적용.
     (광고 제거 / 인벤+40칸 / 골드 1.5배 / 프리미엄 뱃지)
   - DevProductService: 개발자 상품 6종 — ProcessReceipt 완전 구현(중복 지급
     방지, 재시도 안전). (골드 번들 3종 / 물약 번들 2종 / 레이드 입장권)
   - 결제 실패/지연 시 안내 UI, 영수증은 서버 로그 남김.

3) 광고 보상: 보상형 광고 API(가능 플랫폼) — 광고 1회 시청 = 물약 3개, 하루 5회
   제한. 실패 시 무보상 처리 안전장치.

4) 쿠폰: 서버 관리자가 발급하는 코드 입력 UI(RF_Coupon 검증), 1회용 코드 목록
   모듈(설정 파일) — PART 4 쿠폰 운영 규칙 참조.

5) 거래 재해석(원작 거래소 대체): 대면 트레이드 창(2인, 각자 아이템 올리고 양측
   확인 5초 후 교환, RF_Trade 서버 검증) — 자유 게시판은 만들지 않는다.

출력: ①설계 요약 ②전체 코드 ③결제 테스트 방법(Studio Test 모드에서
DevProduct 시뮬) ④트레이드 안전 검증 시나리오.
완료기준 — 실측 확인
  • 골드로 물약 구매 → 인벤 반영 → 도장 7일 보상 로직 실측
  • ProcessReceipt가 스튜디오 시뮬에서 지급되고 재시도에도 이중 지급되지 않는다
  • 특가 3종이 날짜마다 바뀐다(시드 변경 테스트)
  • 트레이드 중 아이템 교체·취소 시 교환이 안전하게 중단된다

Phase 10 — 퀘스트·에그 100종·펫·치장 콘텐츠

원작의 수집·성장 콘텐츠를 이식합니다. 에그 100종은 로블록스 맵 탐사 콘텐츠로 재해석합니다.

【Phase 10】수집·콘텐츠 시스템을 만들자.

1) QuestService:
   - 메인 퀘스트 20개(레벨 구간 연동: 첫 사냥→전직→보스→...), 일일 퀘스트 3개

   첫 전직 안내 4단계 가이드 화살표.

출력: ①설계 요약 ②전체 코드 ③에그 100종 좌표 배치 전략(에디터가 채울 수 있게
에그 스폰 헬퍼 제공) ④퀘스트 진행 테스트 시나리오.
완료기준 — 실측 확인
  • 일일 퀘스트가 날짜 초기화되고 보상이 지급된다
  • 에그 10개 획득 시 구간 보상이 지급된다(테스트용 에그 배치 포함)
  • 펫이 따라다니며 버프 스탯이 서버에 반영된다
  • 코스튬·날개 장착이 다른 플레이어에게도 보인다

Phase 11 — 랭킹·GM 운영·환생 운영

순위 경쟁(랭킹), 운영 도구(GM 커맨드), 장기 동기부여(환생)를 추가해 라이브 운영 체계를 완성합니다.

P11 — PHASE 11 PROMPT전체 복사
【Phase 11】운영 시스템을 만들자.

1) RankService:
   - OrderedDataStore 3개 보드: 레벨 랭킹 / 레이드 누적 토벌 / 도장 누적.
   - 마을 중앙 랭킹 게시물(SurfaceGui 상위 20명), 5분 갱신.
   - 갱신 실패 시 이전 데이터 유지(순위 표시는 항상 존재).

2) GMService — UserId 화이트리스트 기반 관리자 커맨드(서버 콘솔/채팅 프리픽스):
   - /gm give <플레이어> <아이템ID> <수량> / /gm level <플레이어> <레벨>
   - /gm boss <보스ID> (레이드 무시 직접 소환, 테스트용)
   - /gm announce <문구> (전체 공지 토스트)
   - GM 무한 엘릭서(웹버전 GM 권한) 재현: GM 태그 플레이어는 물약 소모 0.
   - 커맨드 실행 로그 남기기(운영 감사).

3) RebirthService — 환생 시스템(원작 이식):
   - 조건: Lv100 달성. 환생 NPC에서 환생 시 레벨·스킬 리셋, 환생 카운트+1.
   - 영구 보너스: 환생 1회당 스탯 +3%, 환생 전용 칭호·치장 5종.
   - 세이브 rebirth 필드와 UI(환생 횟수 표기) 포함.

4) EERT 등급(원작): 주간 활동 점수(사냥량+보스+퀘스트) → 등급 S/A/B/C 표기,
   랭킹 보드와 연동. 하락 방지 규칙(최고 등급 기록 유지)도 이식.

출력: ①설계 요약 ②전체 코드 ③GM 커맨드 테스트 시나리오 ④랭킹 더미데이터
삽입 스크립트(개발기 확인용).
완료기준 — 실측 확인
  • GM 커맨드가 화이트리스트 외 사용자에게는 거부된다
  • 환생 후 레벨 1로 돌아가고 영구 보너스 +3%가 적용된다
  • 랭킹 게시물이 상위 20명을 5분마다 갱신한다
  • 주간 등급이 활동량에 따라 산정된다

Phase 12 — 밸런스 조정 & 출시 체크리스트 필수

전체 밸런스를 골드 수치로 확정하고, 공개 출시 전 마지막 검증을 수행합니다. 밸런스 골드값은 PART 4의 수치표를 기준으로 합니다.

P12 — PHASE 12 PROMPT전체 복사
【Phase 12】출시 전 밸런스·마무리를 하자.

1) 밸런스 데이터 확정 — PART 4 밸런스 수치표를 GameData/Balance 모듈로:
   - 레벨 곡선: EXP_TABLE(Lv1→100, 배수 1.13), 몬스터 HP/ATK 티어별 배율

     유지 골드 500/분" 같은 목표 페이스를 만족하는지 시뮬 스크립트로 확인.

2) 성능 마무리:
