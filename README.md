# SERTZ — 자율 개발 루프 세트

한 바퀴마다 **새 헤드리스 AI 세션**을 열어 개발을 이어가는 무한 루프.
기억은 대화가 아니라 **파일**에 쌓는다 (DESIGN / STATUS / INBOX).

## 파일 지도

| 파일 | 역할 |
|---|---|
| `loop/loop.sh` | 루프 본체 — 무한 반복, 바퀴마다 새 세션, 날짜별 로그, STOP 감시 |
| `loop/env.sh` | 설정 — 모델 / 한 바퀴 최대 턴 수 / 바퀴 사이 대기 / 최대 바퀴 수. **여기만 고친다** |
| `loop/PROMPT.md` | 세션 지시서 6절 — ①합격기준 ②읽을 문서 ③규칙+근거 ④진행순서 ⑤커밋규칙 ⑥검사·QA |
| `loop/loopctl.sh` | 제어 — 켜기 / 끄기 / 상태 / 테스트 / 로그 |
| `loop/systemd/sertz-loop.service.in` | 리눅스 자동 시작 유닛 템플릿 (start 시 실제 경로로 치환해 설치) |
| `docs/DESIGN.md` | 무엇을 만드는가 — 초기 기획, 거의 안 고침 (**빈 틀**) |
| `docs/STATUS.md` | 어디까지 했고 다음은 뭔다 — 매 바퀴 갱신 (**빈 틀**) |
| `docs/feedback/INBOX.md` | 사용자 지시함 — 가장 먼저 처리 (**빈 틀**) |
| `logs/` | 날짜별 로그 (git 제외) |

## 동작 원리 (3줄)

1. 루프가 한 바퀴마다 헤드리스 세션을 **새로** 연다 — 대화를 이어붙이지 않는다 (`-p` 모드, `--continue`/`--resume` 없음).
2. 세션은 `loop/PROMPT.md` 를 받아 INBOX → STATUS → DESIGN 순으로 읽고, **하나만 만들고**, 실행해서 눈으로 확인하고, **커밋하고**, STATUS 를 갱신한다.
3. 기억·진행·지시는 전부 파일로 전달된다. 로그는 `logs/YYYY-MM-DD.log` 에 쌓인다.

## 켜기 / 끄기 / 상태

```bash
./loop/loopctl.sh start      # 켜기 — STOP 제거 + systemd 등록·시작 (재부팅/재로그인 후에도 자동)
./loop/loopctl.sh stop       # 부드럽게 끄기 — 현재 바퀴까지 마치고 멈춤
./loop/loopctl.sh hardstop   # 즉시 끄기 — 진행 중 세션 강제 종료
./loop/loopctl.sh status     # 상태 보기 — 프로세스/스위치/오늘 로그 요약
./loop/loopctl.sh log        # 오늘 로그 실시간 보기 (Ctrl+C 로 탈출)
./loop/loopctl.sh restart    # 즉시 끄고 다시 켜기
./loop/loopctl.sh test 2     # 스텁 2바퀴 스모크 테스트 (실제 에이전트 호출 없음)
```

⚠ **`loop.sh` 를 터미널에서 직접 실행하지 마라.** 무한 루프라 그 터미널과 세션이 묶이고,
창을 닫으면 같이 죽는다. 반드시 `loopctl start` (자동 실행 쪽)로 켠다 — 그래야 창을 닫아도,
컴퓨터를 껐다 켜도 돌아간다.

## 자동 실행 등록 상태

- 유닛 템플릿 준비 완료: `loop/systemd/sertz-loop.service.in`
  - 로그인 시 시작(`WantedBy=default.target`), 비정상 종료 시 재시작(`Restart=on-failure`),
    정상 종료(STOP·최대 바퀴 도달)면 그대로 둠, **PATH 명시**(자동 실행은 터미널 환경을 못 받음),
    설치 시 에이전트/node 실제 경로를 자동 탐지해 PATH 에 추가.
- 현재 실행 환경은 systemd 유저 세션이 없는 컨테이너라, `start` 시 **nohup 백그라운드로 폴백**한다
  (재부팅 자동 시작은 이 환경에서는 불가 — systemd 있는 머신에서는 `start` 한 번으로 전부 등록됨).
- 지금은 **등록만 하고 꺼진 상태**다: `loop/STOP` 파일이 있으면 루프는 절대 새 바퀴를 열지 않는다.
  `start` 가 이 파일을 제거하면서 켠다.

## STOP 스위치 규칙

- `loop/STOP` 존재 = 꺼짐 예약. 루프는 **현재 바퀴를 마치고** 멈춘다 (도중에 끊지 않음).
- 세션 본인도 "INBOX 요청 시 작업 커밋 후 STOP 생성"으로 루프 정지를 요청할 수 있다.

## 지시서에서 직접 채울 것 (loop/PROMPT.md)

- **① 합격 기준을 한 문장으로.** 없으면 AI는 "돌아가기만 하면 완료"로 판단한다.
  예) "이걸 다른 사람이 봤을 때도 퀄리티가 떨어지지 않는가?" — 통과 못 하면 커밋 금지도 함께 적을 것.
- **② 먼저 읽을 문서 + 읽을 범위.** 새로 시작한 세션이 아는 건 이 목록이 전부다.
  파일이 커지면 끝까지 못 읽으니 "어디까지 읽을지"를 꼭 적는다.
- **③ 규칙에는 근거를 붙인다.** 금지만 적으면 빠져나갈 길을 찾는다.
  - (X) "그림은 도구로 처리해라"
  - (O) "그림은 도구로 처리해라. 손으로 그리면 외곽선이 뭉개지고 선이 떨린다"

④⑤⑥(진행 순서·커밋 규칙·검사 QA)은 이미 채워져 있다.

## 자주 쓰는 설정 (loop/env.sh)

```bash
AGENT_BIN=claude        # 헤드리스 에이전트 실행 파일
AGENT_MODEL=sonnet      # 모델 (빈 값 = CLI 기본값)
MAX_TURNS=40            # 한 바퀴 최대 턴 수 (0=무제한)
CYCLE_WAIT_SEC=60       # 바퀴 사이 대기(초)
MAX_CYCLES=0            # 최대 바퀴 수 (0=무한)
```
