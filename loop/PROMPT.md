# 세션 지시서 — 자율 개발 루프

이 세션은 방금 **새로** 열렸다. 이전 대화는 없고, 네 기억은 이 문서와 아래 파일들뿐이다.
실시간으로 답해 주는 사용자는 없다. 판단 근거는 문서와 코드뿐이다.
한 바퀴의 원칙: **딱 하나의 작업**을 읽고 → 만들고 → 확인하고 → 커밋하고 → 기록하고 끝낸다.
여러 개 만들다 도중에 멈추면, 커밋 안 된 나머지는 전부 사라진다.

---

## ① 합격 기준 (한 문장)

> "첫 플레이어가 튜토리얼 없이 마을→뿌리숲→알프헤임→보스 클리어까지 막힘 없이 도달하고,
> 사냥→골드→상점→강화 순환이 리스폰으로 끊기지 않으며, 음소거·회복 같은 기본 UX가 있고,
> 이어하기가 진행 상태를 정확히 복원하며, tsc/eslint/콘솔 에러 0 + 화면 스크린샷 확인을 통과하는가?"
>
> 통과 못 하면: 커밋 금지. 실패 원인을 STATUS.md "다음 할 일" 맨 위에 남기고 다음 바퀴에서 그것부터 고친다.

---

## ② 먼저 읽을 문서

세션 시작 시 아래 순서대로 읽는다. 각 문서마다 "어디까지 읽을지"를 지켜라 —
파일이 커지면 끝까지 못 읽어서 아는 것 반, 모르는 것 반으로 일하게 된다.

1. `docs/feedback/INBOX.md`
   - 어디까지 읽을지: 전체 (짧게 유지). "미처리 지시" 섹션에 항목이 있으면 그것이 이번 바퀴 과제.
2. `docs/STATUS.md`
   - 어디까지 읽을지: "현재 상태" + "다음 할 일" 전부. 진행 로그는 최근 5줄만.
3. `docs/DESIGN.md`
   - 어디까지 읽을지: 전체 (200줄 이내 유지). 밸런스 수치는 "밸런스" 절만.

---

## ③ 규칙과 근거

규칙에는 반드시 **"왜"**를 붙인다. 금지만 적으면 세션은 빠져나갈 길을 찾고,
이유가 적히면 그 이유를 지키려 한다. 아래 형식으로 계속 추가한다.

- 규칙: 외부 에셋은 기존 CC0/CC-BY 소스 재사용 + 필요한 것만 scripts/ 베이커로 생성.
  왜: 라이선스 리스크 제거 + CREDITS.md 누락 방지. 새 팩 도입은 검증 비용이 크다.

- 규칙: 화면에 보이는 기능은 agent-browser로 실측(스크린샷 직접 읽기)하고 끝낸다.
  왜: tsc 통과와 화면이 괜찮은 건 다른 문제. 과거 데미지텍스트 풀 크래시는 눈으로 봐야 잡혔다.

- 규칙: 세이브 필드를 추가하면 loadSave()에서 구 세이브 기본값을 반드시 채운다.
  왜: 사용자 기존 세이브가 깨지면 "이어하기"가 전부 죽는다 (v1→v2 경험).

- 규칙: 몬스터 관련 수치(need/리스폰/드롭율)는 killTotals 누적 기준으로 판정한다.
  왜: 퀘스트 순서와 무관하게 진행돼야 소프트락(막힘)이 없다.

- 규칙: APK는 사용자가 "빌드"라고 말했을 때만 만든다.
  왜: 사용자 명시 지시 (하드 제약). 웹(dev) 검증까지만 진행한다.

---

## ④ 한 바퀴 도는 순서

1. **읽기** — ②의 문서를 순서대로 읽는다. INBOX 에 지시가 있으면 그것이 이번 바퀴의 과제다.
2. **하나만 만들기** — 이번 바퀴의 작업 하나를 정하고, 그것만 끝낸다. 두 개 이상 만들지 않는다.
   작업이 크면 "커밋 한 번으로 끝낼 수 있는 크기"로 잘라서 그 조각만 한다.
3. **실행해서 눈으로 확인** — ⑥의 검사를 수행한다. 코드가 도는 것과 화면이 괜찮은 것은 다른 문제다.
4. **커밋** — ⑤의 규칙대로 커밋한다. 커밋 메시지에 무엇을, 왜 했는지 한 줄 적는다.
5. **STATUS.md 갱신** — "어디까지 했고 다음은 뭔다"를 지금 시점 기준으로 고친다.
   다음 세션이 STATUS.md 만 읽고 이어서 일할 수 있게가 기준이다.

---

## ⑤ 커밋 순서 규칙

- 검사(⑥)를 통과하면, 화면을 사람이 다시 보기 **전에** 일단 커밋한다.
- 한 바퀴는 도중에 멈출 수 있다 — 턴 수 제한, 시간, 사고, STOP.
- **멈춘 자리에 커밋이 없으면 그 작업은 사라진다.** 그래서 "완성해야 커밋"이 아니라
  "검사 통과 즉시 커밋"이 원칙이다. 다음 바퀴의 새 세션이 커밋과 STATUS.md 를 보고 이어서 한다.
- 커밋하지 않은 작업을 STATUS.md 에 적지 마라 — 없는 커밋을 적어두면 다음 세션이 헤딩한다.
- 검사를 통과 못 했으면 커밋하지 않는다(① 참조). 대신 실패 원인을 STATUS.md 의 다음 할 일에 남긴다.

---

## ⑥ 검사와 QA

- **화면이 있는 것을 만들면**: 실행해서 스크린샷을 찍고, **그 이미지 파일을 직접 읽어라**(시각 확인).
  코드가 도는 것과 화면이 괜찮은 건 다른 문제다. 이미지를 읽을 수 없는 환경이면
  DOM/로그 기반이라도 "눈으로" 확인한 근거를 기록으로 남겨라.
- **같은 지적이 두 번 나오면**: 규칙(③)으로 올리고, 기계가 잴 수 있는 규칙이면
  검사(스크립트/테스트)로 만들어 둬라. 한 번 겪은 고장을 두 번 겪지 않는다.
- 이 프로젝트의 기본 검사 명령:
  - `npx tsc --noEmit` (타입 0 에러)
  - `npx eslint src --max-warnings 0` (린트 0 에러)
  - dev 서버 http://localhost:3000 응답 200 + agent-browser 스크린샷 (눈 확인)
  - 콘솔 에러 0 (agent-browser console 확인)
- 검사는 재실행 가능해야 한다. "눈으로 봤다"는 기록과 함께 명령어/스크립트 형태로 남겨라.
- 테스트로 오염된 localStorage는 마지막에 clear()해서 사용자 신규 시작을 보장할 것.

## 루프 운영 메모 (참고)

- 이 세션은 헤드리스로 실행됐고, 출력은 `logs/날짜.log` 에 쌓인다.
- 다음 바퀴는 지금 이 세션과 이어지지 않는다. 해야 할 것은 커밋 + STATUS.md 로만 전달된다.
- 사용자가 INBOX 에서 요청한 경우에만: 작업을 커밋으로 마무리하고 `loop/STOP` 파일을 만들어라.
  루프는 이 바퀴를 마친 뒤 멈춘다.
