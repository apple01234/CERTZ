# vc218 — `agd-rpg` 스킬 기준 RPG 시스템 감사

`/agd-rpg` 지시에 따라 스킬의 **함정 8개**와 프로젝트 구현을 실제 코드·수치로 대조한 기록.
감사만 수행했고 밸런스 수치는 건드리지 않았다(판단 근거만 남긴다).

## 함정별 판정

| # | 스킬 함정 | 판정 | 근거 |
|---|---|---|---|
| 1 | base 스탯을 버프/장비로 직접 수정 | **회피** | `atkTotal` 이 getter — 매번 재계산. `atk` 필드는 기본값 12 만 보관 |
| 2 | derived 스탯을 truth 로 저장 | **회피** | 위와 동일. 세이브의 `atk` 는 저장되지만 `atkTotal` 이 이를 대체 계산 |
| 3 | XP/데미지 폭주 | **부분** | 아래 §1 참조 — 곱셈 29.7배까지 가능 |
| 4 | 스택 버프 폭발 | **해당** | 아래 §1 — 퍼센트를 **곱**한다(스킬 권고는 "레이어 내 합산") |
| 5 | 콘텐츠가 코드에 하드코딩 | **회피** | 적은 `stages.ts` 의 `ENEMIES` 데이터, 아이템은 `data.ts` 의 `ITEMS` |
| 6 | 세이브에 version 필드 없음 | **해당(경미)** | 아래 §2 |
| 7 | 선택에 결과가 없음 | 미검증 | 대화 분기는 범위 밖 — 별도 조사 필요 |
| 8 | 퀘스트 진행 미저장 | **회피** | `questIdx`/`questAccepted`/`questTracked` 가 세이브에 있음 |

## §1. 함정 #4 — 버프가 곱셈으로 누적된다

`damageModel.ts` 의 `damageMultiplier()` 는 모든 배율을 **곱한다**:

```ts
(d.mult * d.clsSkillMult * fifth * runSkl * tierScl * ultMult) * d.rage * d.rebirthDmgMult
```

스킬 문서(`references/stats-combat-quests.md` §1)는 이렇게 경고한다:

> Sum within a layer by default and reserve multiplicative stacking for a few rare effects.

실측 배율 (atkTotal=1000 기준):

| 조건 | 배율 | 데미지 |
|---|---|---|
| 기본공격 | 1.000 | 1,000 |
| 스킬 1차 | 1.650 | 1,650 |
| 스킬 5차 | 3.474 | 3,474 |
| + 분노 1.5 | 5.211 | 5,211 |
| + 인런카드 50% | 7.817 | 7,817 |
| + 환생 2× | 15.634 | 15,634 |
| 2궁극기 + 모든버프 | **29.700** | 29,700 |

### 그러나 실제 밸런스는 붕괴하지 않는다 (실측)

처음엔 "atk 3000이면 보스 즉사"로 판단했으나 **과대평가였다.** 실제 최대치를 계산하면:

```
무기 atk 92 + 스타포스(별당 2+8%) + 잠재 130 + 기본 12 + 장신구 420
  별  0개 → atkTotal ≈ 654
  별 22개 → atkTotal ≈ 852
```

즉 **atkTotal 상한 ≈ 852** 이고, 이때 최대 버프 한 방은:

| atkTotal | 최대버프 데미지 | HP 95,000 보스 |
|---|---|---|
| 200 | 8,910 | 10.66방 |
| 400 | 17,820 | 5.33방 |
| 654 | 29,136 | 3.26방 |
| 852 | 37,957 | **2.50방** |

**최종 보스도 2.5방**이면 잡힌다. 일반 몬스터는:
- HP 5,200 → 0.16방 (한 방)
- HP 34,000 → 1.03방 (한 방)

### 판정

- **HP 34,000 이하 잡몹은 최대 버프 상태에서 전부 한 방** — 이건 의도된 파워 판타지일 수 있다.
- **최종 보스 2.5방은 짧다.** HP 95,000 은 852 atk 의 기본공격(852) 기준 111방인데,
  풀버프를 쌓으면 2.5방이 된다. 편차가 **44배**다.
- 원인은 곱셈 누적이다. 퍼센트를 레이어 내에서 **합산**하면 29.7배 → 약 10배로 줄어
  보스가 6~7방이 되고, 편차도 완화된다. 다만 이는 **밸런스 변경**이라 지시 없이 하지 않았다.

## §2. 함정 #6 — 세이브에 스키마 version 이 없다

`SaveData`(config.ts:53)에 `version` 필드가 없고, 모든 신규 필드가 **optional + 로드 시 기본값**
방식이다:

```ts
questIdx?: Record<string, number>;
if (!d.questIdx || typeof d.questIdx !== "object") d.questIdx = {};
```

이 방식은 실제로 잘 동작한다(구 세이브 호환). 하지만 스킬이 지적한 위험이 있다:

- **의미가 바뀌는 변경**에 취약하다. 예: `weaponStars` 를 0~15 에서 0~22 로 늘리면?
  기존 값은 그대로라 문제없다. 그러나 **단위를 바꾸면**(예: exp 를 절대값→퍼센트)
  구 세이브를 구분할 방법이 없다.
- 마이그레이션 경로를 **강제할 지점이 없다.** 모든 필드가 "없으면 기본값"이라
  "이 버전에서만 실행할 변환"을 표현할 수 없다.

### 판정

지금 당장 깨지지는 않는다(필드 추가만 해왔으므로). 그러나 **위험한 변경 1회면 세이브가
조용히 오염된다.** 권고: `SaveData` 에 `v?: number` 를 추가하고 로드 시
`if ((d.v ?? 0) < N) migrate...` 를 두는 것. 이번엔 **하지 않았다**(세이브 포맷 변경은
사용자 데이터에 직접 영향).

## §3. 잘 되어 있는 것 (기록)

- **XP 커브**: `expTable.ts` 가 메이플스토리 공식 레벨별 요구경험치 테이블을 그대로 쓴다.
  자체 공식(`40 × lv^1.45`)을 폐기한 이력이 주석에 남아 있다 — 스킬의 "커브를 의식적으로
  고르라"를 실제로 수행한 사례.
- **방어력**: `defense.ts` 가 정액 감산 + 비율 감소를 함께 쓰고, **감소율 상한 75%** 와
  **최소 피해 1** 을 보장한다. 스킬 §2 의 "floor at 1" 을 지킨다.
- **데미지 순수함수 분리**: `calcDamage()` 가 부수효과 없이 분리돼 있고,
  `damageMultiplier()` 와 **동일식을 유지해야 한다**는 계약이 주석에 명시돼 있다.
  (한쪽만 고치면 조용히 갈라지는 위험을 인지하고 있음)

## 권고 (실행하지 않음 — 지시 대기)

1. **퍼센트 합산화** — `damageMultiplier` 의 퍼센트 계열(rage/runSkillPct/rebirth)을
   곱 대신 합으로. 29.7배 → 약 10배. 보스 HP 조정 없이 템포가 잡힌다.
2. **보스 HP 상향** — 위를 안 하면 최종 보스 HP 를 95,000 → 250,000 수준으로.
3. **세이브 version 필드 추가** — 위험한 변경 전에 미리 넣어두는 것이 안전.
4. 함정 #7(선택의 결과)은 대화 시스템 조사가 필요해 미검증으로 남긴다.
