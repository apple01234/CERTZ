## 1. Executive Summary

### 현재 상태 요약

SERTZ는 **이미 상당한 규모의 완성된 게임**이다. 63,984줄, 에셋 284MB/4,186파일, 23개 API 라우트, 보스 9종, 직업 10종, 생활콘텐츠 5종(낚시·채집·도박·교실·이세카이)을 갖추고 있다. 웹·APK·PC 3플랫폼 배포가 실측으로 확인됐다.

문제는 **기능 부족이 아니라 구조적 부채와 검증 부재**다.

| 축 | 실측 상태 | 판정 |
|---|---|---|
| 기능량 | 보스 9·직업 10·생활 5·던전 5모드 | 충분 |
| 안정성 | 부팅 404 1건, WebGL 손실 루프 | **위험** |
| 부팅 비용 | 에셋 2,979요청 / 49MB | **위험** |
| 코드 구조 | `WorldScene.ts` 16,471줄(전체의 26%) | **위험** |
| 자동 테스트 | `*.test.ts` **0개** | **위험** |
| 계측 | 유지율 이벤트 **없음** | 미측정 |
| 직업 차별화 | 5계열 공유 구조 → 10직업 분기 미완 `[미확인]` | 부분 |
| 경제 설계 | 등급 4단(common 14/rare 53/epic 87/legend 62) | 존재, 검증 없음 |

### 핵심 결론 3가지

**① 지금 필요한 것은 콘텐츠 추가가 아니라 "지울 수 있게 만드는 일"이다.**
16,471줄 단일 씬에서는 어떤 기능 추가도 회귀 위험이 크다. 테스트가 0개이므로 회귀는 사람이 눈으로만 확인한다. 이 상태에서 기능을 더 얹으면 유지비가 복리로 늘어난다.

**② 부팅 비용이 이탈의 1차 원인 후보이며, 수치로 확인된다.**
에셋 2,979요청/49MB, 그리고 404 1건이 매 부팅마다 3회 재시도를 유발한다. 30초 계측 캡 안에 타이틀 도달이 확인되지 않았다.

**③ 게임성 개편의 최대 레버리지는 "직업 정체성"과 "첫 10분"이다.**
직업 10종이 있으나 계열 5종 연출을 공유하는 구조가 코드에 남아 있고, 첫 마을에는 NPC가 1명뿐이며 마을은 2곳이다. 신규 유저가 "이 게임은 넓다"고 느낄 지점이 초반에 없다.

### 1차 권고 범위

P0 2건(404 제거, WebGL 복구 로직) + P1 1건(부팅 비용)을 **게임성 변경 없이** 먼저 처리한다.
완료 조건은 전부 실측 수치로 판정한다(§15).

## 4. 게임의 핵심 재미와 차별화 전략

### 4.1 현재 게임이 실제로 제공하는 것

실측된 자산 기준으로 SERTZ의 강점은 **"양"과 "북유럽 신화 정체성"**이다.

- 세계관: 위그드라실 9왕국, 보스 이름이 신화 원형(니드호그·수르트·펜리르·요르문간드)
- 스케일: 보스 9 + 직업 10 + 궁극기 20 + 던전 5모드
- 접근성: 웹/APK/PC 3플랫폼

약점은 **"왜 계속 해야 하는가"의 밀도**다. 기능은 많으나 각 기능이 성장으로 이어지는 사슬이 약하다(낚시·채집은 독립, 마을은 2곳).

### 4.2 차별화 3축 (제안)

**축 1 — 직업 손맛 (가장 높은 레버리지)**
10직업이 있는데 평타·스킬 판정이 계열(5) 단위로 공유되면 유저는 "직업이 3개뿐"으로 느낀다.
→ 직업별 **모션·판정 형태·자원 소모·사거리**를 다르게. 수치 조정이 아니라 **형태**가 달라야 한다.

**축 2 — 신화 보스의 예고와 회피**
보스 9종이 있으니 "패턴을 읽고 피하는 재미"를 1급 시민으로 만든다.
→ 모든 보스 공격에 `telegraph` 단계(0.4~0.8초 예고) + 판정과 예고의 일치율 100%.

**축 3 — 생활 → 제작 → 전투 순환**
낚시·채집(279줄)이 이미 있다. 재료 → 장비 제작 → 보스 도전으로 닫는 고리 하나만 만들면 저비용 고효율.

### 4.3 하지 말아야 할 것

- 아홉 세계 전체 동시 제작 (현재 마을 2곳인데 9세계 확장은 순서 역전)
- 에셋 일괄 교체 (284MB/4,186파일 규모에서 회귀 위험 과다)
- 엔진 교체 (Phaser 4.2.1이 이미 4.x 대응 완료, 이전 비용 대비 이득 없음)

## 6. 전투 및 보스 시스템

### 6.1 현재 구현 (실측)

- 기본공격: `Player.attack()` → `familyOf(cls)` 분기 (warrior 근접/ranger 원거리/mage 볼트/thief 표창혼합/pirate 총)
- 스킬: 1~5차 슬롯, 쿨다운, `rollDamage(mult, true)` 계수
- 궁극기: `useSkill5` / `useSkill5b` — 20종 개별 구현(누락 0 실측)
- 적: `sim/fixedStep.ts` 20Hz 고정틱, `MAX_STEPS_PER_FRAME=4`
- 방어력: `combat/defense.ts` — 잡몹 정액+비율, 보스 25/10%, 상한 75%, 최소 1
- 피격: `takeDamage(dmg, dir, knock, crit)`

### 6.2 설계 규칙 (제안)

| 규칙 | 값 | 근거 |
|---|---|---|
| 보스 예고 시간 | 0.4~0.8초 (패턴 위험도 비례) | 회피 가능 하한 |
| 일반몹 예고 | 0.25초 | 템포 유지 |
| 무적 프레임 | 회피기 280ms(기존 유지) | 이미 구현됨 |
| 경직 | 일반몹 120ms, 보스 면역 | 보스 압박 방지 |
| 판정-예고 일치 | **100%** | 불일치가 "억울한 피격"의 근원 |
| 화면 흔들림 상한 | 0.026 (기존 blademaster 값) | 과도한 흔들림 방지 |

### 6.3 실패 사례 (회귀 테스트 대상)

1. 예고 없이 피격 → 유저 신뢰 붕괴
2. 예고와 판정 불일치 → "맞을 자리 아닌데 맞음"
3. 궁극기 오브젝트 폭주 → 프레임 정지 (**과거 실측: 해적 22발 × 4오브젝트 = 88개**)
4. 전체 순회 `getAllTargetsIn(999)` 반복 → CPU 스파이크
5. 줌 복원 실패 → 화면이 넓어진 채 고정 (**과거 실측: `perspZoom` 미존재 필드 참조**)

## 7. 성장, 장비, 전직 시스템

### 7.1 레벨

`expTable.ts`가 메이플 공식표 1~299를 그대로 사용. 300+는 마지막 증가율 ×1.1 연장.
- 장점: 검증된 곡선, 급격한 누진 구간(190~200)이 후반 목표 의식 형성
- 위험: 초반 1~5레벨이 15/34/57/92/135로 매우 빠름 → 튜토리얼과 성장이 겹쳐 "성장했다"는 감각이 흐려질 수 있음

### 7.2 장비

| 등급 | 개수(실측) | 비중 |
|---|---|---|
| common | 14 | 6.5% |
| rare | 53 | 24.5% |
| epic | 87 | 40.3% |
| legend | 62 | 28.7% |

**문제**: 등급 분포가 epic/legend에 69% 편중. 초반 파밍에서 쓸 만한 하위 등급 선택지가 적다.
**제안**: 계열별 무기를 `common 2 / rare 2 / epic 2`로 각 계열에 최소 6종 보장(현재 도적 1종 → 8종 추가로 보완했으나 등급 재배치 필요).

### 7.3 전직

5계열 → 2차 → 3차 → 4차 leaf 10직업. `TIER4_ULTIMATES` 10종 전부 존재(실측).
**핵심 개선**: `familyOf()`가 5계열만 반환하는 구조가 남아 있으면 10직업이 연출을 공유한다. → `Skill5Key` 기반 `leafKeyOf()` 전환.

### 7.4 장기 수집 (제안)

- 보스 도감: 9종 × 난이도 3 = 27칸
- 어종 도감: 이미 구현(지역별 20종)
- 칭호: 업적 16 → 1:1 대응 구현됨

3. 각 직업 1개씩 생성 → 평타 애니메이션·판정 확인
4. 4차 직업 궁극기 2종 시전 → 프레임 정지 없는지
5. 보스 1종 조우 → 예고 후 피격
6. 장비 장착 → 타 직업 무기 차단 메시지
7. 저장 → 새로고침 → 상태 복원
8. 모바일(실기기) 부팅 시간 측정

### 15.3 측정 불가 항목 (정직하게)

- S20+ 발열: 컨테이너 WebGL 불가 → **실기기 필요**
- RTX 5070 프레임: 동일
- PC EXE 실행: Linux aarch64에서 Windows PE 실행 불가 → 구조·버전만 검증
