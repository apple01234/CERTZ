# vc213 — 에셋 지적사항 처리 기록

PR 리뷰 지적 12건 중 에셋·맵 관련 항목의 원인과 조치를 기록한다.
"고쳤다"가 아니라 **무엇이 원인이었고 무엇으로 검증했는지**를 남긴다.

## #2 유령 애니메이션 — "아틀라스인데 애니메이션이 아니라 통짜 사진을 썼다"

### 진짜 원인 (측정)
- `wraith_idle0/1`, `wraith_run0..3` 6개 PNG의 MD5를 비교한 결과:
  - `wraith_idle0` = `wraith_run0` = `wraith_run2` (**완전히 동일한 파일**)
  - 고유 프레임은 3개뿐 (`run` 4프레임 중 3개)
- 전 몬스터를 스캔한 결과 **33종 전부 "4프레임 중 고유 3개"** 였다.
- 출처: `scripts/redesign_sprites.py` 헤더에 명시 —
  "정적 셀 → 하단 앵커 스쿼시 사이클로 idle/run/atk 프레임 합성".
  즉 원본 시트의 **정적 셀 1장만 잘라** 상하 스쿼시로 4프레임을 **합성**한 것이다.
- 그 결과 달리기 애니메이션이 "제자리에서 껑충거리는" 모션이 됐고,
  사용자는 이를 "4프레임이 한 장에 다 들어간 아틀라스"로 인식했다.

### 조치
- Balmer "Skeleton and Ghost" (CC0) 10프레임 시트를 도입.
  - 10프레임 전부 고유(md5 상이) · 25×35 · 꼬리 물결이 실제로 움직임.
  - 5×2 배열을 10×1 스트립으로 재배열해 `public/assets/anim/wraith_spirit.png` 로 저장
    (**PNG 무손실 검증: `back.tobytes() == strip.tobytes()` → True**).
- `textures.ts`: 시트가 있으면 `wraith-idle`(10fps) / `wraith-run`(14fps) 을 시트로 등록,
  없으면 기존 2/4프레임 폴백. (기존 세이브·리소스 환경에서도 안전)
- `Enemy.ts`: `key === "wraith"` 이고 시트가 로드돼 있으면 `wraith_spirit` 텍스처로 스폰.

### 남은 한계
- 나머지 32종 몬스터는 **여전히 합성 3프레임**이다. 원본 시트
  (`32rogues/monsters.png`, `Mystic Woods player.png`)가 저장소에 없어 재슬라이스가 불가하다.

  후보는 이미 확보해 두었다: `assets_dl/ghosts/ghost_11variations_32x32.png`(11색×6프레임),
  `assets_dl/tilesets/kenney_roguelikeSheet_16px.png` 등.

### 2026-10-31 후속 — 나머지 33종 프레임 문제 (미해결, 원인 규명 완료)

`wraith` 를 제외한 **33종 몬스터가 여전히 합성 4프레임**이다. 실제로 시도한 것과 결과:

1. **스쿼시 파라미터 보강 실험** — `fh`(상하) 뿐 아니라 `fw`(수평)까지 조합해 4프레임을 만들면
   md5 가 전부 달라지는지 확인했다. 결과: **md5 는 4개 모두 달라짐**(02621a28/e968ee170/4dccae9d/94716c4b).
   그러나 육안 평가는 **"여전히 걷기로 안 보인다 — 제자리에서 젤리처럼 출렁이는 것으로 읽힌다"**.
   이유가 명확하다: **발(발톱)이 모든 프레임에서 같은 좌표에 있다.** 걷기의 본질은 발이 지면을
   딛고 이동하는 것인데, 스쿼시는 몸통 높이만 바꾸므로 다리 교차(stride)가 생기지 않는다.
   → **파라미터 튜닝으로는 해결 불가.** 프레임 개수를 늘려도 같은 한계다.

2. **다리 조작 시도는 하지 않았다** — 원본 셀 1장에서 다리를 분리해 앞뒤로 옮기면
   관절·발톱·몸통 연결부가 왜곡되고, 33종 × 4프레임을 손으로 만드는 것은
   "퀄리티 저하 금지" 원칙에 정면으로 어긋난다. 억지 변형보다 현 상태 유지가 낫다고 판단했다.

3. **대체 시트 조사** — 34종을 커버할 CC0 탑다운 애니메이션 팩을 탐색 중이다.
   로컬 보유분 점검 결과:
   - `monster-builder-pack`(Kenney CC0): 파츠 조립형, **애니메이션 프레임 없음** → 부적합
   - `oga-animal-bestiary`: Blender 3D 씬 스크린샷, 종류별 1개씩 → 부적합
   - `Dungeon Crawl Stone Soup` 타일: 정적 1장 → 부적합
   - `wraith/gwraith 21프레임`(Game2rise CC0): 이미 확보, 단 흑백 실루엣이라 현재 팔레트와 불일치

### 결론 (정직한 현재 상태)
- **유령 1종은 진짜 10프레임 애니메이션으로 교체 완료.**
- **나머지 33종은 합성 프레임 유지.** 원본 시트(`32rogues/monsters.png`)가 저장소에 없어
  재슬라이스가 불가능하고, 스쿼시 조합은 걷기로 보이지 않음이 실험으로 확인됐다.
- 해결 경로는 둘뿐이다: (a) 원본 32rogues/Mystic Woods 시트 복구, (b) 34종을 커버하는
  CC0 애니메이션 팩 도입 후 `textures.ts` 의 `-idle/-run` 등록부를 시트 기반으로 교체.
  (b)는 `Enemy.ts` 가 `${key}_idle0` 텍스처를 쓰는 구조라 스폰 경로 수정이 함께 필요하다.

원작 대조로 "지역에 알맞게"를 점검한 결과, 지역 테마와 어긋나는 배치가 3곳 있었다.

### 2026-10-31 최종 — 33종 몬스터 프레임: 원본 부재 확정 (실측)

후속 조사로 **원본 시트의 실체를 특정**했다. 결론부터: **재슬라이스로는 해결 불가**다.

1. **`50+ Monsters Pack 2D` (isaiah658, CC0, 56종) 를 실제로 받아 대조했다.**
   - 규격은 64×64로 게임 `x2_*` 와 정확히 일치하지만, **몬스터 디자인이 다르다**.
     예: 팩의 Monster #17 = 초록 잎벌레형, 게임의 `x2_bat_idle0` = 보라 박쥐.
     픽셀 차이 10.94(0에 가까우면 동일) → **동일 원본 아님**.
   - 더 중요하게, **이 팩은 애니메이션이 없다.** 56종 × (정면 1장 + 후면 1장) = 112장이 전부다.

2. **즉 게임의 run 4프레임은 원본에 존재하지 않는 데이터다.**
   `golem` 실측: `run0` = `run2` = `idle0` (**md5 0b28b2a0 동일**),
   `run1`(bc0248dd)·`run3`(bc678056) 만 스쿼시 변형. 4프레임이라지만 실제 고유는 2~3개다.

3. **전수 집계** — 261프레임 중 고유 200개(77%). 중복 목록은
   `docs/monster_frame_dupes.json` 에 기계 판독 가능 형태로 남겼다(후속 자동화용).

4. **원본 후보 소진** — 저장소 전체(`.next`, `standalone`, `.next-apk`,
   `android/.../public`, `electron/game`, `tmp/`)에서 `32rogues/monsters.png` 를 찾지 못했다.

### 왜 억지로 고치지 않았는가
- 스쿼시(상하)에 수평 변형까지 넣으면 md5는 4개 모두 달라지지만, 육안 검수 결과
  **"여전히 걷기로 안 보인다 — 제자리에서 젤리처럼 출렁인다"**.
  원인은 **발톱이 모든 프레임에서 같은 좌표**에 있는 것. 걷기는 발이 지면을 딛고
  이동해야 성립하므로 스쿼시로는 원리적으로 불가능하다.
