# APPLIED vc278 — 구역 균등화 (CreepZone)

작성: 2026-11-12 KST
대상: `src/game/creepZone.ts`
근거: `docs/handoff/NEXT_AI_vc277.md` §4 작업 B

## 문제

핸드오프 지적: "`splitCreepZones` 의 보로노이 분할이 불균등(6구역 → cells 18/23/11/7/3/2).
k-means 스타일 반복으로 균등화 검토. 단 결정론은 유지."
목표: 3종족 스테이지에서 **종족별 반경 편차 ≤ 30%**.

## 측정 방법

브라우저 E2E 는 비싸다. 분할 품질은 `splitCreepZones`/`assignCreepZones` 의 **순수 출력**만으로
측정되므로 먼저 `scripts/measure-zone-balance.mjs` 를 신규 작성해 잰다.

- 레이아웃 5종: 전면개방 11×9 / 12×12 / 16×16, 동굴형(78% 개방) 16×16 g=6·g=12
- 시드 4~6종(`stage-1-1`, `stage-1-2`, `stage-2-5`, `alpha`, `omega`, `seed42`)
- 지표: 구역 크기 min/max/ratio/cv, 빈 구역 수, 종족별 최대 반경 편차
- **최악값 기준**(평균 아님) — 평균은 나쁜 케이스를 가린다

실행: `node --experimental-strip-types scripts/measure-zone-balance.mjs`

## 시도한 것 (실패 포함)

### 1차 — Lloyd 반복 (성공, 부분적)
무게중심 재계산 후 최근접 재배정을 4회.
ratio 29 → 2.0, cv 0.52 → 0.15 로 **분할은 고르게** 됐다.
그러나 **반경 편차는 49.5% → 46.9% 로 거의 안 움직였다.** 배정 단계가 병목이었다.

### 2차 — 균형 배정 (실패)
시작 구역을 farthest-point sampling 으로 서로 멀리 뽑고, 남은 구역은 "가장 큰 것부터,
받으면 총 셀이 가장 고르게 되는 종족"에 배정.
**셀 수는 32/33/34 로 완벽히 균형**이 됐는데 **반경 편차는 37~43% 로 여전히 FAIL**.
→ **반경은 셀 개수가 아니라 구역 모양이 정한다**는 것을 실측으로 확인.
   이 사실이 이번 작업의 핵심 발견이다. 셀 수만 맞추는 접근은 목표에 도달하지 못한다.

### 3차 — 구역 맞교환 스왑 (성공)
두 종족의 구역을 맞바꿔 (최대반경 − 최소반경) 이 **엄격히** 줄어들 때만 수용. 최대 8패스.
반경 편차 0.0~6.9%, 전 케이스 PASS. 여기서 멈췄다.

## vc278 후속 — 인게임 E2E 실측 (같은 날, 브라우저)

순수 함수 지표(위)만으로는 부족해서 **실제 게임에서** 쟀다.
`scripts/playtest-creep-zone.mjs`, Playwright Chromium headless, 1280×800.

### 1차 측정 — 목표 미달 (ratio 1.07)

| 값 | 측정 |
|---|---|
| 스테이지 | `howlrstone1x1` (1-1) |
| 종족 | 개구리 5 / 물고기 3 (2종족 8마리) |
| 종족 내 평균 거리(intra) | 267 |
| 종족 간 거리(inter) | 286 |
| **ratio** | **1.07** ← 목표 1.5 **미달** |
| 최대 반경 | 개구리 429 / 물고기 456 |

`layout` 은 정상(57셀)이었고 `assignCreepZones` 도 호출되고 있었다. **버그가 아니라 설계 문제**였다.

### 원인

종족마다 구역 3개(`zonesPerGroup=3`)를 받는데, 물고기는 **3마리**다.
3마리가 3개 구역에 1마리씩 들어가면서 합집합의 외곽이 넓어졌고, 실질적으로 균등 산개와 같아졌다.
구역이 공간적으로 인접해도 **1마리씩 흩어지면 응집으로 보이지 않는다.**

### 수정

`WorldScene` 스폰 루프에서 종족이 쓰는 구역 수를 **마릿수에 비례**하도록 제한:
`takeZones = clamp(1, 구역수, floor(count / 4))` — 구역 하나에 최소 4마리는 있어야 뭉쳐 보인다.

**첫 시도가 틀렸다.** `min(count, 구역수)` 로 했더니 개구리 `min(5,3)=3`, 물고기 `min(3,3)=3` 로
**전혀 줄지 않아** 측정값이 1.07 그대로 나왔다. 핸드오프 §7 이 경고한
"측정값이 이전과 똑같이 나오면 probe 잔존을 의심하라"에 해당하는 상황이었고,
실제로는 빌드가 아니라 **식 자체가 틀린 것**이었다. 확인 절차(git diff · 빌드 산출물 대조)로 갈라냈다.
