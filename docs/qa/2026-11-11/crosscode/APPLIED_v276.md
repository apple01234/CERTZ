# vc276 — 스킬 이펙트 3단 시점 분리

적용일: 2026-11-11 UTC / 버전 **vc276 / 2.2.20**

---

## 1. 무엇을 바꿨나

`src/game/fx/StudioFX.ts` 의 `spawnSkillImpact` 한 함수.

종전에는 링·코어 섬광·참격 잔상 3겹이 **전부 t=0** 에 동시에 생성됐다. 셋이 겹쳐 한 덩어리로 보였고 "터졌다"는 인상만 남았다.

이제 **시점과 위치를 분리**한다.

| 단계 | 시점 | 텍스처 | 위치 | 역할 |
|---|---|---|---|---|
| ① 시전 | 0ms | `hv2_circle2` | 발밑 | 준비 동작을 알린다 |
| ② 먼지 | stepMs (70ms) | `hv2_smoke26` ← **신규 사용** | 발밑 **+4px** | 무게를 만든다 |
| ③ 타격 | stepMs×2 (140ms) | `vf_impact` + `vf_slash` | 전방(`hitDx`) | 실제로 맞는 지점 |

**새 에셋 0장.** `hv2_smoke26` 은 이미 로드돼 있었지만 스킬 임팩트에 쓰이지 않던 텍스처다.

### 왜 이렇게 하는가

참고 게임(ISEKAI GATE)의 스킬 이펙트 프리팹은 한 덩어리가 아니라 **3개로 쪼개져 있다**:

```
FX_Attack_11800_c        (시전)
FX_Attack_11800_c_Dust   (먼지)
FX_Attack_11800_c_Hit    (타격)
```

같은 그림을 **시점만 옮겨도** "차고 → 내려찍고 → 터진다"로 읽힌다. 프레임을 늘리거나 그림을 새로 그리는 것보다 비용이 낮다.

## 2. 실측 결과 (실제 브라우저)

`scripts/playtest-skill-impact-staging.mjs`, Chromium headless, 60fps(16.7ms 확인)

```
링(시전)   t= 33ms   hv2_circle2  (298,503)
먼지       t=100ms   hv2_smoke26  (298,507)   ← +4px 아래
타격       t=183ms   vf_impact    (298,503)
타격       t=183ms   vf_slash     (298,503)

저사양(fxLevel 0): 생성 0건
페이지 예외: 0
```

간격 실측 **67ms / 83ms** — `stepMs = 70` 과 일치.
첫 프레임이 33ms인 것은 요청 시점이 프레임 경계에 걸리기 때문이며 정상이다.

### 계측 오류 정정

첫 측정에서 33/**183**/**533**ms 가 나왔다. 원인은 `t` 기준점을 instrument 시점에 잡아, 측정 사이에 흐른 시간이 섞인 **내 계측 버그**였다. 매 측정 시작 시 리셋하도록 고쳐 33/100/183ms 로 정정했다. 첫 수치를 그대로 보고하지 않는다.

## 3. 호환성

- **옵션 미지정 시 `stepMs = 70`** → 기존 호출부 6곳(`Player.ts` 3곳 + `StudioFX` 내부)이 무수정으로 동일하게 동작한다.
- 저사양 게이트(`fxLevel === 0`)는 **최상단 조기 반환을 그대로 유지** — 4겹 전부 생략.
- 시각 지연일 뿐 **판정(피해)은 호출부에서 이미 확정**된다. 전투 결과를 바꾸지 않는다.
- 신규 옵션: `stepMs`, `dustTex`, `hitDx`, `hitDy` (전부 optional).

### 신규 테스트가 고정하는 것

1. 세 레이어가 서로 다른 지연값을 쓴다 (`stepMs`, `stepMs*2`) — 전부 t=0 으로 되돌아가면 실패
2. 사용 텍스처 4종이 **실제 파일로 존재** — 미로드 키는 검은 사각형이 된다
3. 저사양 게이트가 모든 오브젝트 생성보다 **앞**에 있다
4. `stepMs` 기본값이 존재하고 현실적 범위(0 < ms ≤ 200)다

## 5. 검증 과정에서 실패한 접근 (기록)

| 시도 | 실패 이유 |
|---|---|
| `useSkill1()` 직접 호출 | 1차 직업은 `weaponMasterProfileOf` → `STARTER_SIGNATURE` 분기로 빠져 `spawnSkillImpact` 미도달 |
| `useSkill3()` 직접 호출 | `SKILL3_KIND[cls]` 가 없어 초입 return (`state` 가 idle 로 남음) |
| 튜토리얼 게이트만 해제 | `canPlayerAction()` false 는 풀렸지만 위 두 문제가 남음 |
| **최종: `__SERTZ__` 에 함수 노출** | 게이트와 무관하게 계측 대상 함수만 호출. 순수 시각 함수라 판정 영향 없음 |

계측 훅은 `PhaserGame.ts` 의 기존 E2E 노출 관례(`__SERTZ__`)를 그대로 따랐다.

## 6. 검증하지 않은 것

- **S20+ 실기기**에서 70ms 간격이 실제로 "차고→내려찍고"로 읽히는지. headless swiftshader 수치만 있다.
- 근접 다수전에서 이펙트가 겹칠 때의 가독성.
- 나머지 두 구조(**SPUM 파츠 조합**, **CreepZone 구역 볼륨 스폰**)는 **적용하지 않았다**. 코디 시스템·스폰 레이어 개편은 규모가 커 별도 판단이 필요하다.
- 참고 게임의 실제 화면을 보며 대조하지 않았다(정적 번들 분석만).
