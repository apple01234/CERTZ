# CrossCode Deep 관찰 → 기존 게임 적용 (v2.2.10 / vc266)

기준: CERTZ/main `e227b84`. Craft Anything 실제 MCP를 `--deep --allow-run`으로 실행했다. 사용자의 기존 실행·Deep 승인을 이어 사용했다. 관찰 대상은 공식 사이트의 **CrossCode v0.7.1 BETA DEMO**이며 최신 상용판 전체 분석이 아니다.

## 이번에 직접 확인한 것

1. 기존 검증된 진입 절차(공지 닫기 → New Game → 대화 진행)를 재사용했다. 첫 방의 다리와 북쪽 길을 키보드로 통과하고 다음 방 전투로 진입했다. 게임의 위치·진행·능력치를 JavaScript로 변경하지 않았다. 좌표 조회만 읽기 전용으로 사용했다.
2. 첫 전투의 `Dodge!` 화면에서 방향 + 회피 입력을 요구한다. 실제 D+Alt 입력 후 `Attack!`과 마우스 4회 안내로 바뀌었다.
3. 실제 왼쪽 마우스 연속 입력 뒤 피해 숫자와 감소한 적 HP바를 확인했다.

## 적용한 판단 (관찰에서 도출한 설계 선택)

- **한 행동을 실제로 성공해야 다음 수련으로 넘어간다.** 기존 Tutorial/WorldScene의 독립 돌진을 그대로 사용했다. 지정 수련 적의 공격 예고 중 성공한 돌진 + 실제 빗나감 + 64px 이상 이동이 모두 있어야 회피 수련을 완료한다. 걷기만 하기, 쿨타임으로 거부된 입력, 예고 전 돌진, 제자리·벽에 막힌 돌진, 피격, 직전 시도 기록으로는 통과하지 않는다. 매 시도와 수련 정리 시 기록을 초기화한다. PC Shift와 모바일 버튼은 같은 `tryFreeDash()`를 이용한다.
- **기존 보스의 공격 기회를 읽기 쉽게 한다.** 기존 `recover`의 1~2초 후딜과 피해 ×1.15는 변경하지 않았다. 보스 위에 보라색 `공격 기회 · 피해 +15% · 남은 초`를 표시한다. 노란 카운터(성공 시 기절·×1.6)와 구별된다. 보스당 텍스트 하나만 재사용하며, 창 만료/다른 상태/사망에는 숨기고 `destroyPool()`에서 제거한다. 이것은 CERTZ 기존 후딜의 가독성 개선이며 CrossCode 보스의 동일 메커니즘을 확인했다는 주장이 아니다.
- 기존 픽셀아트, 클래스, 에셋, 전직, 세이브 필드와 형식은 유지했다. CrossCode 코드·이미지·음악은 런타임에 복사하지 않았다. 새 의존성·생성 에셋은 없다.

## 검증

- 전체 `npm test`: **608 통과 / 0 실패**. 회피 시점·충돌·피격·기록 재사용과 공유 입력 경로, 후딜 표시의 상태 전이·재사용·정리를 실행 검증한다.
- `npx tsc --noEmit`, `npm run lint:strict`, `npm run build:next`: 통과. 로컬 메모리 디스크 빌드 시 모듈 경로 오류를 수정한 후 빌드와 실행을 분리 확인했다. 원본 런타임 에셋 보존 메시지 확인.
- 보스 UI: `node scripts/playtest-recovery-cue.mjs`로 PC 1280×800 / 터치 844×390 통과. **격리된 테스트 캐릭터 근처에 보스를 생성하고 실제 `endAttack(slam)`과 일반 타이머를 사용한 fixture다. 자연 진행 보스 클리어 검증은 아니다.** 화면·정리 결과는 `v266/`에 있다.
- 튜토리얼 실제 진행 결과는 `v266/keyboard-tutorial-results.json`, `v266/touch-tutorial-results.json`에 별도 보관한다. 터치 실행은 회피에서 실제 두 손가락 조이스틱+돌진 버튼을 사용하며, 나머지 단계는 일반 키보드/UI를 병용한다.

## 남은 조사

CrossCode의 조준·차지 시간, 후반 보스 패턴, 회피 무적 시간, 전체 타일맵 및 컷씬 설계는 이번 실행으로 검증하지 않았다. 이전 정적 JS 그래프는 런타임 확인과 구분한다. CERTZ의 자연 성장 첫 보스 클리어, 장기 전 직업 밸런스도 이번 결과에서 완료로 표시하지 않는다. 다음 작업은 공식 데모의 첫 전투 이후 조준/원거리 수련 관찰이며, 이미 있는 시스템을 확인한 뒤 작은 개선을 실제로 적용한다.
