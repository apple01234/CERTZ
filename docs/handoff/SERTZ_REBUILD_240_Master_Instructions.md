## 0. 에이전트에게 전달하는 총괄 명령

너는 SERTZ의 리드 게임 디렉터이자 시니어 엔지니어다. 현재 게임에 기능이 많다는 이유로 완성도가 높다고 판단하지 마라. 실제 플레이 중 재미를 떨어뜨리는 부분, 과도하게 반복되는 구조, 서로 충돌하는 시스템, 시각 품질이 떨어지는 장면, 개발자가 만들어 놓고 연결하지 않은 기능을 조사하고 필요한 부분을 근본적으로 다시 설계하라. **전체 엔진을 처음부터 만드는 것이 아니라 품질이 낮은 시스템을 교체하고 정상 시스템을 유지하는 개편**이다.

최우선은 정상 입력으로 처음 게임을 켠 사용자가 첫 보스를 처치하고 다음 목표에 도전하고 싶어지는 경험이다. 이를 확립한 뒤 후반과 반복 콘텐츠에 적용한다. DDD(도파민 주도 개발)는 짧고 명확한 행동-피드백-성취 순환으로 구현하되 이용자에게 강제 접속, 불공정 경쟁, 과도한 결제를 유도하는 방식은 금지한다.

### 절대 준수 사항

1. 기존 Next.js 16 / React 19 / TypeScript / Phaser 4.2.1 / Three.js 구조를 유지한다. Godot·Unity·별도 캠페인 엔진으로 이전하지 않는다. 현재 package.json 기준이며 착수 시 다시 확인한다.
2. `GameRoot → PhaserGame → WorldScene → Player`의 정상 진입과 세이브, 계정, 전직, 인벤토리, 장비, 제작, 하우징, 파티를 보호한다. 불량 모듈만 교체한다.
3. **에셋은 기존 구매·제공 원본 또는 웹에서 합법적으로 다운로드한 에셋을 사용한다.** 외부 다운로드를 적극 허용하며 더 적합한 리소스로 교체 가능하다. AI로 스프라이트·보스·타일맵·초상화를 임의 생성하지 않는다. 원본의 합법적 크롭, 아틀라스 패킹, 리깅, 색 보정, 포맷 변환은 허용한다. 구매·유료 라이선스 체결은 별도 사용자 승인을 받는다. 저작권 불명확, 무단 추출, 타 게임 고유 파일 복제는 금지한다.
4. 기존 원본 파일을 배포에서 제거하지 말고 필요한 시점에 로딩하도록 바꾼다. 라이선스상 원본 배포가 허용되지 않는 외부 에셋은 적용하지 않는다. 라이선스와 출처는 파일별/팩별로 관리한다.
5. 기존 정본 8개만 지정 순서대로 사용한다. 하루·라일락·펜던트의 설정과 현재 스토리를 유지하고 옛 9개의 바다를 본편 서사로 복구하지 않는다. 실제 사람 이름, 타 작품의 고유 캐릭터·호칭은 사용하지 않는다.
6. `startTransition()` 단일 씬 전환 계약을 지킨다. 세이브 필드 변경 시 SaveData·복원·buildSave를 함께 수정한다. 이전 정상 저장 및 구매 자산을 삭제하지 않는다.
7. 작업 전 `AGENTS.md`, `skills/ponytail/SKILL.md`, `docs/handoff/CURRENT_HANDOFF.md`, 최신 `worklog.md`를 확인한다. 인계 파일은 역사 자료일 수 있으므로 현재 코드와 대조한다.
8. 기존 규칙상 **APK/EXE/웹 프로덕션 빌드와 버전 증가에는 사용자 승인 필요**. 자동 APK/EXE 빌드를 다시 켜지 않는다. 현재 요청은 지시서 작성이며 실제 코드 변경·커밋·배포 승인이 아니다. 실행 단계에서 별도 승인 및 저장소 규칙을 지킨다.
9. 각 작업은 작게 변경하고 실제 실행으로 검증한다. 작업과 직접 관계 없는 리팩터링, 새 의존성, 거대한 전역 관리 클래스 도입은 금지한다. 정상 동작을 제거해 성능이나 테스트 수치를 맞추지 않는다.
10. 검증용 강제 워프·직업 변경·스탯 주입·모의 인증은 반드시 정상 플레이 검증과 구분하고 운영 사용자 데이터에는 실행하지 않는다. 실패 증거를 숨기거나 측정값을 추정으로 채우지 않는다.

### 증거 상태 표기법

- **[확인]**: 이 지시서 작성 시 최신 기준 코드 또는 저장소 규칙에서 직접 확인. 수정 완료 또는 운영 재현을 뜻하지 않는다.

- **[검증]**: 문제가 발생할 수 있는 경로에 대한 검증 작업. 아직 실제 버그라고 단정하지 않는다.
- **[설계]**: 품질을 높이기 위한 신규 설계/개편 제안. 현재 반드시 결함이라는 뜻은 아니다.

## 01. 제품 방향·작업 통제 (001~020)

### 001. [P0·확인] 최신 기준점 잠금

- **수정 지시:** main의 HEAD, 운영 /api/version, 실제 게임 버전, 작업 시작 시각을 기록한다. 인수인계 문서의 오래된 상태를 최신 코드와 대조하고 이미 완료된 기능을 재구현하지 않는다.
- **완료 조건:** 기준 SHA와 비교 링크, 현재 변경 파일 목록, 미해결 이슈 목록이 하나의 작업 보고서에서 일치한다.

### 002. [P0·설계] 개편 범위 결정

- **수정 지시:** GameRoot→PhaserGame→WorldScene→Player를 유지한다. 불량 시스템은 현행 호출 경로를 조사한 후 모듈 단위로 교체하고, 별도 축소 캠페인이나 엔진 전환으로 문제를 숨기지 않는다.
- **완료 조건:** 기존 캐릭터 생성·장비·전직·계정·파티·제작·하우징 진입 경로가 보존된다.

### 003. [P0·설계] 수직 슬라이스 우선

- **수정 지시:** 마을→라일락 튜토리얼→첫 사냥→장비 성장→디오 처치를 대표 완성 구간으로 선정하고 이 구간의 조작·시각·성장 품질부터 완성한다. 이후 같은 규격을 나머지 지역에 적용한다.
- **완료 조건:** 정상 입력으로 첫 구간을 처음부터 끝까지 플레이한 영상과 이탈 원인 기록을 확보한다.

### 004. [P0·설계] 기능 동결

- **수정 지시:** 기존 결함의 수정과 개편을 위한 기능만 허용한다. 신규 던전·BM·직업·시즌 추가는 핵심 루프와 안정성이 검증될 때까지 보류한다.
- **완료 조건:** 변경 요청마다 기존 문제 ID와 직접 연결되며 무관한 기능 추가 diff가 없다.

### 005. [P0·설계] 작업 소유권 분리

- **수정 지시:** 전투·보스, 월드·아트, UI·온보딩, 성장·경제, 서버·저장, QA로 책임을 나눈다. WorldScene과 Player 공통 파일은 단일 통합 담당자만 최종 수정한다.
- **완료 조건:** 작업별 변경 파일 계약과 의존 순서가 기록되고 동일 파일의 덮어쓰기나 기능 유실이 없다.

### 006. [P0·기록] 기존 병렬 병합 결함 방지

- **수정 지시:** 메서드 호출만 추가하고 본체를 누락한 vc284 사례를 참고한다. 모든 타입·호출부·실행부를 함께 추적하고 import/export 및 이벤트 등록 순서를 확인한다.
- **완료 조건:** 실제 호출되는 함수의 존재, tsc 통과, 브라우저 재현까지 확인한다.

### 007. [P0·설계] 변경 전 기준선 확보

- **수정 지시:** 동일 세이브·기기·해상도·네트워크·맵 시드로 진입 시간, 프레임 시간, 처치 시간, 피해량, 퀘스트 진행을 측정한다. 기존 운영 수치를 환경이 다른 로컬 수치와 직접 비교하지 않는다.
- **완료 조건:** 측정 조건이 명시된 before/after JSON과 화면 캡처가 존재한다.

### 008. [P0·설계] 회귀 차단 게이트

- **수정 지시:** 로그인, 신규 생성, 로딩, 저장, 전직, 포탈, 보스 종료를 핵심 경로로 지정한다. 하나라도 막히면 다음 개편보다 복구를 우선한다.
- **완료 조건:** 핵심 시나리오가 동일 빌드에서 모두 실행되며 실패한 항목은 배포 후보에서 제외한다.

### 009. [P0·설계] 세이브 호환 원칙

- **수정 지시:** 개편 전후의 저장 스키마와 마이그레이션 계획을 먼저 작성한다. 구 필드 삭제나 아이템 ID 재사용으로 데이터의 의미를 바꾸지 않는다.
- **완료 조건:** 구버전 대표 세이브를 불러와 자산·레벨·전직·스토리 진행 상태가 보존된다.

### 010. [P1·설계] 게임의 정체성 문장

- **수정 지시:** 빠른 회피와 직업별 전투, 이야기 기반 필드 탐험, 의미 있는 성장이라는 세 축을 제품 기준으로 삼는다. 서로 관계없는 미니 콘텐츠는 유지하되 핵심 동선에서 우선 노출하지 않는다.
- **완료 조건:** 첫 10분에 세 축을 경험할 수 있고 메뉴에 기능을 나열하는 것으로 대신하지 않는다.

### 011. [P1·설계] 참고작 분석 방식

- **수정 지시:** CrossCode의 공격 가독성·방 설계, Hades의 전투 피드백, Eastward의 장면 구성에서 원리를 분석한다. 고유 코드·이미지·이름을 무단 복제하지 않는다.
- **완료 조건:** 참고 사례마다 관찰한 원리, SERTZ에 적용할 차이, 검증 화면을 기록한다.

### 012. [P0·설계] DDD 정의

- **수정 지시:** 도파민 주도 개발을 조작의 즉각적 피드백, 예측 가능한 목표, 성취와 선택의 재미로 정의한다. 강제 접속·손실 공포·과도한 확률형 보상으로 플레이를 유도하지 않는다.
- **완료 조건:** 플레이테스트에서 유저가 다음 행동의 이유를 스스로 설명하며 강제 대기 없이 진행한다.

### 013. [P1·설계] 콘텐츠 인벤토리

- **수정 지시:** 실제 진입점·해금 조건·사용 빈도·보상·완성도를 기능별로 조사한다. 미구현 UI, 중복 시스템, 사용되지 않는 에셋은 구분해서 정리 후보로 표시한다.
- **완료 조건:** 콘텐츠 목록에 실제 진입 여부와 유지·개편·노출 축소 결정이 있으며 근거 없는 삭제가 없다.

### 014. [P1·설계] 난이도 목표 합의

- **수정 지시:** 일반몹, 엘리트, 보스, 반복 콘텐츠에 목표 TTK와 실수 허용량을 명시한다. 직업·성장 수준에 따라 합리적 범위를 두고 숫자를 테스트 결과에 맞춰 수정한다.
- **완료 조건:** 최소 3개 직업과 3개 성장 구간에서 목표 대비 편차를 수치로 확인한다.

### 015. [P1·설계] 디자인 토큰

## 02. 초기 로딩·성능·기기 최적화 (021~040)

### 021. [P0·기록] 초기 로딩 계측

- **수정 지시:** 현재 신규 월드 로딩 1,313개와 운영 관찰 약 18~23초를 기준선으로 사용하되 동일 조건에서 재측정한다. 타이틀 표시, 생성 완료, 첫 입력 가능 시각을 분리한다.
- **완료 조건:** cold/warm 각각 5회 이상 p50·p95와 환경 정보를 남긴다.

### 022. [P0·기록] 첫 지역 필수 에셋 분리

- **수정 지시:** BootScene과 ensureWorldAssets의 의존성을 추적해 첫 장면·첫 적·첫 컷씬·기본 조작에 필요한 것만 우선 받는다. 후반 전직·보스·대형 FX는 해당 콘텐츠 직전 준비한다.
- **완료 조건:** 첫 입력 목표 p50 10초 이하, 필수 에셋 누락·빈 스프라이트 0건을 실제 브라우저에서 확인한다.

### 023. [P0·기록] 공통 FX 페이로드 분석

- **수정 지시:** 약 54MB로 보고된 기존 초기 응답 용량을 재측정하고 파일별 전송·디코딩·GPU 메모리 비용을 정렬한다. 가장 큰 공통 FX의 지연 로딩을 우선한다.
- **완료 조건:** 동일 네트워크 조건에서 초기 전송량과 진입 시간이 모두 감소하며 시전 직후 효과가 누락되지 않는다.

### 024. [P1·검증] 프리로드 경계 재정의

- **수정 지시:** 마을에서 전체 몬스터를 로드하는 이유를 실제 임의 소환 경로와 대조한다. GM·특수 콘텐츠 전용 의존성은 일반 신규 유저의 필수 로드에서 분리 가능 여부를 검증한다.
- **완료 조건:** 일반 신규 유저 요청 목록에서 불필요한 몬스터가 제거되고 특수 소환의 정상 실행이 유지된다.

### 025. [P1·검증] 동시 요청 24개 검증

- **수정 지시:** 6→24로 바뀐 동시 다운로드 정책을 8·16·24·32 등 소수 후보로 비교한다. 네트워크 병목과 모바일 디코딩 경쟁을 따로 측정한다.
- **완료 조건:** 동일 조건 p95가 가장 양호하고 오류율이 늘지 않는 값을 채택한다.

### 026. [P0·검증] 로딩 실패 후 복구

- **수정 지시:** 필수 텍스처 실패·네트워크 끊김·타임아웃을 로컬 프록시로 재현한다. 재시도·안전한 복귀·입력 및 물리 정지 해제를 기존 경로에서 보장한다.
- **완료 조건:** 실패 이후 복구하거나 타이틀로 돌아갈 수 있으며 영구 검은 화면과 입력 잠금이 없다.

### 027. [P0·기록] 모바일 WebGL 크래시 조사

- **수정 지시:** 과거 모바일 탭 종료·시간 초과를 재현하고 GPU/JS 메모리·텍스처 수·렌더러·열 상태를 기록한다. 에뮬레이션 성공을 실기기 성공으로 간주하지 않는다.
- **완료 조건:** S20+ 등 실제 기기에서 30분 월드 왕복·전투 중 크래시가 없고 실측 데이터가 남는다.

### 028. [P1·설계] 디코딩과 업로드 분산

- **수정 지시:** 동시 다운로드 완료 직후 이미지 디코딩과 GPU 업로드가 한 프레임에 몰리는지 프로파일링한다. 필요한 경우 큐를 제한하고 프레임 예산 내로 분산한다.
- **완료 조건:** 최대 긴 프레임과 입력 지연이 감소하고 첫 표시 시 텍스처가 준비된다.

### 029. [P1·검증] 아틀라스 요청 최적화

- **수정 지시:** 기존 개별 보스·캐릭터 프레임의 실제 사용 경로를 조사하고 아틀라스 변환 가능 여부를 검증한다. 원본 파일은 삭제하지 않고 프레임 인덱스 호환을 유지한다.
- **완료 조건:** 동일 동작의 프레임 이미지·피벗·순서가 동일하며 네트워크 요청 감소가 확인된다.

### 030. [P1·설계] 지역 간 로딩 캐시

- **수정 지시:** 현재·인접 지역 중심 캐시 정책을 정하고 참조 중인 텍스처는 해제하지 않는다. 다시 방문할 때 동일 파일을 재다운로드하지 않도록 검증한다.
- **완료 조건:** A→B→A 반복 시 로딩이 단축되고 텍스처 누락·GPU 메모리 지속 증가가 없다.

### 031. [P1·검증] 캐릭터 외형 준비

- **수정 지시:** 외형 변경 시 정지 이미지 1장만 먼저 적용하지 말고 기존 28동작 로드 완료 후 원자적으로 교체한다. 실패하면 기존 외형을 유지한다.
- **완료 조건:** 이동·공격 중 변경해도 깜빡임, 빈 프레임, 잘못된 피부색이 없다.

### 032. [P1·설계] 프레임 예산

- **수정 지시:** PC 60fps 목표와 저사양 30fps 안정 모드를 정의한다. 평균 FPS뿐 아니라 p95/p99 프레임 시간, 최장 끊김을 측정한다.
- **완료 조건:** 대표 전투 5분에서 p95 16.7ms PC 목표, 저사양 33.3ms 목표를 검증하고 미달 환경을 표시한다.

### 033. [P1·검증] 월드 객체 컬링

- **수정 지시:** 화면 밖 장식·비전투 파티클·렌더 객체의 불필요한 업데이트를 측정하고 절감한다. 사거리 밖 적의 상태나 퀘스트 판정은 유지한다.
- **완료 조건:** 적 AI·상호작용의 결과는 유지되며 CPU/GPU 부하가 줄어든다.

### 034. [P1·검증] 파티클 풀·수명

- **수정 지시:** 기본공격, 죽음, 날씨와 궁극기의 생성·파괴 횟수를 측정한다. 기존 풀을 재사용하고 수명 종료 후 객체 및 참조를 제거한다.
- **완료 조건:** 100회 전투 후 활성 파티클·리스너·타이머 수가 안정 범위로 복귀한다.

### 035. [P1·검증] Three.js 레이어 수명

- **수정 지시:** 궁극기 GLB/텍스처·캔버스·렌더러가 씬 이동과 연출 중단 시 정리되는지 확인한다. 재사용 객체와 제거 객체의 소유권을 명확히 한다.
- **완료 조건:** 궁극기 반복 20회와 씬 이동 후 WebGL 컨텍스트 수가 증가하지 않는다.

### 036. [P1·설계] 그래픽 품질 프리셋

- **수정 지시:** 효과 밀도, 블룸, 후처리, 조명, 화면 해상도를 묶은 낮음/보통/높음 프리셋을 기존 설정에 연결한다. 공격 예고와 핵심 피해 피드백은 모든 모드에서 보존한다.
- **완료 조건:** 저사양 모드로 전환 시 FPS가 개선되고 공격 회피 가능성이 동일하다.

### 037. [P0·검증] 백그라운드 복귀

- **완료 조건:** 5초·1분·5분 중단 이후 중복 재시작·검은 화면·저장 유실 없이 복귀한다.

### 038. [P1·설계] 오디오 지연 로딩

- **수정 지시:** 지역 BGM과 후반 스킬 SFX는 필요한 시점에 준비하고 로딩이 전투를 막지 않도록 한다. 첫 입력 후 오디오 정책과 초기화 실패를 처리한다.

### 039. [P1·검증] 네트워크 캐시 무결성

### 040. [P0·설계] 성능 합격 보고서

## 04. 월드·맵·던전·카메라 개편 (061~080)

- **완료 조건:** 대표 3개 던전에서 방이 잘리지 않고 여백이 유지되며 캐릭터를 읽을 수 있다.

### 067. [P1·검증] 카메라 픽셀 안정성

- **수정 지시:** Phaser4 카메라 원점, zoom, 스크롤 좌표 계산을 실제 viewport에서 비교한다. 해상도 변경으로 방 중앙이 밀리는 문제를 재현한다.
- **완료 조건:** 가로/세로/창 리사이즈 10회 후 방 중심과 플레이어 위치가 올바르다.

### 068. [P1·기록] 던전 조명 복원 유지

- **수정 지시:** 암전 던전의 횃불·앰비언트 효과를 유지하면서 조명 오버레이와 날씨가 검은 여백으로 새지 않게 한다. 조명을 끄는 해결책은 금지한다.
- **완료 조건:** 검은 여백 픽셀 검사와 방 내부 조명 스크린샷이 동시에 통과한다.

### 069. [P1·설계] 카메라 모드 전환

- **수정 지시:** 야외 추적, 방 전체 보기, 컷씬 팬/줌, 보스 등장, 궁극기 연출의 우선권과 복귀 지점을 명확히 한다.
- **완료 조건:** 연출 중 스킵·사망·씬 이동 후 원래 카메라 모드가 정확히 복원된다.

### 070. [P1·기록] 던전 컷씬 연출 복원

- **수정 지시:** 기존 framedRoom 분기가 팬·줌을 생략한 경로를 확인한다. 연출 중 필요한 제한적 확대 후 방 맞춤 카메라로 복귀하게 한다.
- **완료 조건:** 대표 던전 보스 입장 컷씬에서 대상이 보이고 종료 후 검은 여백과 조명이 정상이다.

### 071. [P1·설계] 카메라 추적 감도

- **수정 지시:** 이동·대시 시 추적 지연을 적절히 제한하고 프레임률에 독립적으로 보정한다. 급정지·방향 전환 시 화면이 과도하게 흔들리지 않게 한다.
- **완료 조건:** 키보드·터치 대시와 좁은 통로 이동 영상에서 플레이어가 예측 가능한 위치에 유지된다.

### 072. [P1·설계] 전투 공간 가독성

- **수정 지시:** 보스 방에서는 큰 구조물이 보스와 경고 영역을 가리지 않도록 한다. 안전 공간과 회피 경로를 의도적으로 배치한다.
- **완료 조건:** 각 대표 패턴을 실제 이동으로 피할 수 있고 카메라 밖에서 갑작스러운 불가피 피해가 발생하지 않는다.

### 073. [P1·기록] 몬스터 군집 배치

- **수정 지시:** creepZone의 종족별 응집 개선을 보존한다. 20마리 이상·3종족 이상에서 군집 반경뿐 아니라 통로 점유, 겹침, 사냥 흐름을 검증한다.
- **완료 조건:** 실제 사냥에서 무리를 의도적으로 분리할 수 있으며 이동 불가 구역에 스폰되지 않는다.

### 074. [P1·설계] 스폰 공정성

- **수정 지시:** 입구·NPC·포탈 주변에는 보호 반경을 둔다. 리스폰이 플레이어와 겹쳐 즉시 피해를 주지 않도록 위치와 시간 기준을 명시한다.
- **완료 조건:** 맵 진입 및 10회 리스폰에서 즉사·포탈 막힘·벽 내부 스폰이 없다.

### 075. [P1·검증] 소품 발밑 충돌

- **수정 지시:** decorCollisionBounds와 실제 불투명 영역을 대조한다. 식탁·나무·기둥의 윗부분은 가릴 수 있어도 발밑만 충돌하도록 유지한다.
- **완료 조건:** 상하좌우에서 접근할 때 시각적 바닥과 물리 충돌 경계가 맞는다.

### 076. [P1·설계] Y축 깊이 정리

- **수정 지시:** 캐릭터, 몬스터, 소품, 무기, 이름표, 그림자가 동일 기준점에서 깊이를 계산하도록 기존 경로를 통일한다.
- **완료 조건:** 플레이어가 나무 뒤·앞을 지날 때 몸과 장식의 레이어가 자연스럽고 순간 반전이 없다.

### 077. [P1·설계] 미니맵·지도 일치

- **수정 지시:** 실제 열린 셀·막힌 벽·포탈·NPC·현재 목표 데이터를 지도와 연결한다. 의도적 탐험 비공개 영역은 별도로 표시한다.
- **완료 조건:** 지도 안내대로 모든 표시된 이동 경로를 실제 통과할 수 있다.

### 078. [P0·검증] 포탈 왕복 안전성

- **수정 지시:** startTransition 단일 경로를 유지하고 연타·충돌 이벤트·긴급귀환·보스 종료 타이밍의 중복 호출을 검사한다.
- **완료 조건:** 대표 맵 A→B→A 20회에 검은 화면·중복 씬·저장 위치 불일치가 없다.

### 079. [P1·설계] 환경 사운드

- **수정 지시:** 숲·동굴·마을·행성의 BGM과 환경음 구분을 실제 지역과 연결하고 전투 BGM 전환 및 페이드를 정리한다.
- **완료 조건:** 보스 처치·귀환 후 BGM이 정상 복귀하며 이전 지역 음악이 겹치지 않는다.

### 080. [P1·검증] 맵 전수 감사

- **수정 지시:** 모든 StageKey의 진입·포탈·퀘스트 대상·보스 배치·충돌 데이터 연결을 자동 검사하고 대표 맵을 육안 확인한다. 테스트용 워프는 정상 진행 검증과 구분한다.
- **완료 조건:** 잘못된 스테이지 키, 도달 불가 필수 목표, 의도치 않은 막다른 포탈을 목록화하고 수정한다.

## 05. 캐릭터·보스 아트·외부 에셋 도입 (081~100)

### 081. [P0·설계] 에셋 다운로드 허용 정책

- **수정 지시:** 기존 원본, 제공 자료, 라이선스가 확인된 외부 에셋을 모두 사용 가능하게 한다. AI 생성 이미지나 임시 코드 드로잉을 최종 아트로 사용하지 않는다.
- **완료 조건:** 신규 리소스마다 원본 URL·작가·라이선스·다운로드 날짜·수정/재배포 허용 여부가 기록된다.

### 082. [P0·설계] 라이선스 및 배포 권리

- **수정 지시:** itch.io, OpenGameArt, Unity Asset Store, 제작사 공식 페이지 등에서 실제 이용 조건을 확인한다. 웹 게임의 원본 파일 노출과 상용·수정·추출·재배포 제한을 따로 검토한다.
- **완료 조건:** 배포에 필요한 권리가 확인된 파일만 포함하고 크레딧·고지 조건을 만족한다.

### 083. [P0·설계] 에셋 교체 승인 기준

- **수정 지시:** 새 외부 팩을 통째로 덮어쓰기 전에 대표 캐릭터 1종과 지역 1개에서 스타일·스케일·동작·권리·용량을 비교한다. 부적합하면 원본을 유지한다.
- **완료 조건:** before/after 캡처, 아트 사양, 매핑 표로 교체 필요성을 증명한다.

### 084. [P1·설계] 아트 스타일 가이드

- **수정 지시:** 픽셀 크기, 윤곽선, 광원 방향, 채도·명도, 캐릭터와 배경 비율을 정한다. SPUM과 신규 타일셋/보스팩의 충돌을 사전에 검사한다.
- **완료 조건:** 대표 장면 5개에서 서로 다른 에셋 출처가 시각적으로 과하게 분리되어 보이지 않는다.

### 085. [P1·검증] 플레이어 28동작 유지

- **수정 지시:** 기본 남녀, 피부 6종, 전직 외형, 이동·피격·공격 전체 애니메이션의 실제 프레임을 검사한다. 새로운 외형은 같은 동작 계약을 만족해야 한다.
- **완료 조건:** 모든 동작에서 빈 프레임·갑작스러운 얼굴/피부 변경·잘림이 없다.

### 086. [P1·검증] 픽셀 선명도

- **수정 지시:** 텍스처 필터, 스프라이트 확대 배율, 화면 스케일링을 점검하고 픽셀아트에 불필요한 보간·번짐을 줄인다. 3D/FX는 필요한 필터를 별도로 유지한다.
- **완료 조건:** 100%·150%·모바일 확대에서 캐릭터 윤곽이 선명하고 카메라 이동 중 흔들리지 않는다.

### 087. [P1·설계] 스프라이트 아틀라스 규격

- **수정 지시:** 외부 아틀라스의 셀 크기, 프레임 수, 애니메이션 행, origin, trim/rotation 여부를 메타데이터로 관리한다. 기존 6열/12열 인덱스 오류를 재발 방지한다.
- **완료 조건:** 모든 프레임 경계가 실제 파일 크기 안에 있고 idle/run/attack/death 전환이 정상이다.

### 088. [P1·검증] 보스 방향 표준

- **수정 지시:** 원본 스프라이트의 기본 방향을 보스마다 기록하고 좌우 반전 조건을 데이터화한다. 가름처럼 별도 원본 방향이 필요한 예외는 명시한다.
- **완료 조건:** 각 보스가 플레이어 좌·우에 있을 때 몸체, 무기, 투사체가 올바른 방향을 향한다.

### 089. [P1·검증] 보스 크기 및 피벗

- **수정 지시:** 시각적 크기와 충돌 반경, 그림자, HP바, 타격 이펙트 위치를 맞춘다. 큰 보스의 투명 여백을 물리 영역으로 계산하지 않는다.
- **완료 조건:** 최소·최대 크기 보스에서 타격점과 머리 위 UI가 안정적으로 붙는다.

### 090. [P1·검증] 보스 죽음 애니메이션

- **수정 지시:** 사망 dissolve가 아틀라스 전체 UV를 읽지 않도록 기존 프레임 UV 처리와 호환성을 확인한다. 지원하지 않는 아틀라스는 안전한 기존 효과를 사용한다.
- **완료 조건:** 보스별 죽음에서 다른 프레임 노출, 잘림, 뒤늦은 재등장이 없다.

### 091. [P1·설계] NPC 디자인 역할 구분

- **수정 지시:** 상점·퀘스트·대장장이·가문 영주를 쉽게 구분할 수 있는 기존/외부 캐릭터 디자인을 매핑한다. 서사에 없는 요정형 NPC를 임의로 되살리지 않는다.
- **완료 조건:** 실제 등장 명단과 에셋 목록이 일치하고 상호작용 역할을 외형 및 표식으로 구분한다.

### 092. [P1·기록] 초상화 일관성

- **수정 지시:** SPUM 원본 NPC와 초상화의 머리색·의상·화자가 일치하도록 매핑을 검사한다. 중앙 정렬과 투명 경계를 보정한다.
- **완료 조건:** 대표 대사 20개 및 주요 화자 전수에서 잘못된 초상화·잘림·가운데 어긋남이 없다.

### 093. [P1·설계] 머리·표정 에셋 조건

- **수정 지시:** 플레이어용 헤어/얼굴 리소스가 확보되지 않으면 기존 기능을 유지한다. 라이선스와 동작 호환성이 확인된 파츠 팩을 확보한 후 연결한다.
- **완료 조건:** 없는 텍스처를 참조하지 않고 실제 동작에 맞는 에셋으로만 추가한다.

### 094. [P1·기록] 모자·날개 독립 슬롯 검토

- **수정 지시:** 현재 cape는 독립이지만 accessory는 모자와 날개를 공유한다. 두 슬롯 분리가 필요한 경우 기존 세이브의 accessory를 정확히 이관한다.
- **완료 조건:** 모자+날개+망토 동시 착용, 개별 해제, 구세이브 이관 및 재접속이 모두 정상이다.

### 095. [P1·검증] 장식 앵커 전수

- **수정 지시:** 왕관·리본·오라·날개·망토의 방향별 anchor와 depth를 characterParts 데이터로 검증한다. 이동·대시·전직·스케일 변경 중에도 따라오게 한다.
- **완료 조건:** 모든 방향에서 장식이 스폰 위치에 남거나 몸을 부자연스럽게 가리지 않는다.

### 096. [P1·검증] 멀티 외형 동기화

- **수정 지시:** 망토·모자·날개·코스튬이 원격 플레이어에게 올바르게 전달되는지 확인한다. 구 클라이언트와 알 수 없는 키는 안전하게 처리한다.
- **완료 조건:** 두 클라이언트에서 외형 변경·재접속·맵 이동 후 동일한 착용 상태를 본다.

### 097. [P1·설계] 무기 디자인 매핑

- **수정 지시:** 전승 및 직업별 무기 종류에 맞는 원본/다운로드 에셋을 연결한다. 공격 방향, 손잡이 위치, 스윙 프레임을 해당 직업에 맞춘다.
- **완료 조건:** 전사·궁수·마법사·도적·해적 계열의 실루엣과 공격 방식이 분명히 다르다.

### 098. [P1·검증] 텍스처 무결성

- **수정 지시:** asset manifest의 키·경로·파일 대소문자·포맷·크기를 검사하고 원본과 생성된 아틀라스의 매핑을 대조한다.
- **완료 조건:** 404·중복 키·빈 이미지·잘못된 MIME·누락 프레임이 없고 CI 검사가 존재한다.

### 099. [P1·설계] VFX 아트의 계열 구분

- **수정 지시:** 기본 타격, 화염, 냉기, 번개, 암흑, 물, 기계 효과를 라이선스 확인된 기존/외부 팩에서 선정한다. 모든 직업이 같은 마법진만 사용하지 않게 한다.
- **완료 조건:** 동일 화면에서 서로 다른 직업의 스킬을 효과의 형태와 색으로 구별한다.

### 100. [P1·설계] 아트 납품 패키지

- **수정 지시:** 신규 다운로드 원본, 라이선스 증빙, 변환 스크립트, 매핑 표, 변경 전후 화면을 정리한다. 원본 런타임 에셋을 삭제해 강제 교체하지 않는다.
- **완료 조건:** 누가 어떤 파일을 어떤 이유로 변경했는지 재현 가능하고 원복 경로가 존재한다.

## 06. 기본 조작·전투 코어·타격감 (101~120)

### 101. [P0·검증] 입력 응답 기준선

- **수정 지시:** 키 입력과 터치 시작부터 첫 이동·공격 프레임 및 피해 판정까지 각각 측정한다. 입력 장치·FPS별 차이를 기록하고 불필요한 지연을 제거한다.
- **완료 조건:** PC·모바일 각각 30회 입력의 지연 분포가 개선되고 입력 누락이 없다.

### 102. [P0·기록] 기본공격 대시 캔슬

- **수정 지시:** 기존 basicAttackSeq 취소 방식을 유지하면서 준비·첫 피해·후딜 구간별 대시를 검사한다. 정상 타격을 남기고 취소된 공격의 지연 피해는 제거한다.
- **완료 조건:** 각 구간에서 대시를 20회 시도해 이전 공격의 유령 타격과 중복 타격이 없다.

### 103. [P0·기록] 대시 쿨다운 실측

- **수정 지시:** 사용자 요구 1초 기준을 실제 대시 시작 시각 간격으로 검증한다. 이동 종료 후 쿨다운을 세는 구현이라면 의도한 기준과 일치시키고 UI도 동일하게 표시한다.
- **완료 조건:** 연속 입력 측정에서 합의한 쿨다운과 표시 시간이 일치하며 무한 대시는 없다.

### 104. [P0·기록] 회피 무적 창 검증

- **수정 지시:** 기존 이동 180ms 및 무적 420ms 설계를 출발점으로 피격·돌진·장판·지속 피해를 각각 시험한다. 피해 무효 범위를 공격 종류별로 명확히 한다.
- **완료 조건:** 무적 중 허용된 피해는 차단되고 종료 직후 정상 피해가 적용된다.

- **완료 조건:** 의도한 피격 후 회피가 가능하고 상태이상 해제 우회나 입력 영구 잠금이 없다.

- **완료 조건:** 연타와 빠른 방향 전환에서 공격이 자연스럽게 연결되고 유령 입력이 없다.

### 107. [P1·설계] 공격 판정 상태

- **수정 지시:** 준비→활성→회복의 구간을 기존 스킬 실행 경로에 명시한다. 모션과 피해 활성 창을 같은 타임라인에서 관리한다.
- **완료 조건:** 대표 기본공격 및 직업 S1에서 이미지 프레임과 피해 발생 시점이 일치한다.

### 108. [P1·설계] 타격 범위 가시화

- **수정 지시:** 근접 공격의 호·직선·원형 등 실제 판정 형태가 이펙트와 대응하게 한다. 디버그 hitbox는 개발용으로만 제공한다.
- **완료 조건:** 경계 안팎에 배치한 적에게 표시 범위와 동일한 판정이 발생한다.

### 109. [P1·검증] 투사체 방향·수명

- **수정 지시:** 활·마법·보스 탄환의 방향, 벽 충돌, 거리, 최대 수명을 점검한다. 로컬과 원격 flip 규칙을 맞춘다.

### 110. [P1·설계] 타격음 레이어

- **수정 지시:** 무기 휘두름, 실제 적 타격, 치명타, 방어/무적 소리를 구분한다. 사운드를 남발하지 않고 핵심 타격 순간에 맞춘다.
- **완료 조건:** 빗맞힘·명중·치명타를 눈을 감고도 구분할 수 있고 같은 효과음이 폭주하지 않는다.

### 111. [P1·설계] 히트스톱 예산

- **수정 지시:** 기본공격과 강한 스킬에 차등 히트스톱을 적용하되 물리·입력·카메라와 연계한다. 연타가 정지 시간을 무한 연장하지 않도록 한다.

## 07. 궁극기·직업별 연출 전면 재설계 (121~140)

### 121. [P0·확인] 총 피해 예산 오류 수정

- **수정 지시:** Player.useSkill5의 0.35*waveIntensity가 23~24회 더해지는 현상을 재현한다. 기존 직접 타격을 포함한 직업별 목표 총 피해 예산을 정의하고 웨이브에 정규화 분배한다.
- **완료 조건:** 기존/개편 총 직접 피해 계수 비교와 실제 고정 조건 피해량 차이가 승인 범위 이내다.

### 122. [P0·확인] 워브링어 종결 순서 수정

- **수정 지시:** 현재 2.27초 종결기 뒤 23.3초까지 추가 웨이브가 발생하는 구조를 정리한다. 연속 참격→고조→대붕괴→복귀 순서가 되도록 하나의 타임라인으로 묶는다.
- **완료 조건:** 종결 일격 뒤 신규 피해 예약이 없고 연출·카메라·피해 발생 시각이 일치한다.

### 123. [P0·확인] 전 직업 타임라인 감사

- **수정 지시:** 최대 지연을 단순 delayedCall 첫 인자로 판단하지 말고 반복문·중첩 타이머·도트·투사체까지 추적한다. 10개 직업별 첫/마지막/종결 타격 시각을 기록한다.
- **완료 조건:** 각 직업의 실제 타격 이벤트 로그와 설계 타임라인이 대응한다.

### 124. [P1·검증] 궁극기 조작 계약

- **수정 지시:** useSkill5는 idle 유지 정책이므로 22~30초 강제 경직이라고 단정하지 않는다. 실제 이동·일반 스킬·대시 허용 여부와 연출 가독성을 검증한다.
- **완료 조건:** 궁극기 중 허용/금지 행동 표가 실제 입력 결과와 일치한다.

### 125. [P0·설계] 시전 식별자와 취소

- **수정 지시:** 궁극기 타이머에 해당 시전 ID와 씬 수명을 연결한다. 사망·재시작·맵 이동·재사용·캐릭터 교체 시 오래된 예약을 무효화한다.
- **완료 조건:** 중단 후 새 캐릭터 또는 새 맵에서 이전 궁극기 피해와 FX가 발생하지 않는다.

### 126. [P1·설계] 피해 영역 기준

- **수정 지시:** 시전 지점 고정, 플레이어 추적, 표적 추적 중 직업별 의도에 맞는 방식을 선택한다. 공통 반경 360을 무조건 모든 직업에 적용하지 않는다.
- **완료 조건:** 시전 중 이동하는 플레이어와 이동하는 적을 각각 테스트해 표시 영역과 판정이 일치한다.

### 127. [P1·설계] 워브링어 천멸극

- **수정 지시:** 9연속 참격과 출혈, 공격력 버프, 대붕괴를 단계별 역할로 분리한다. 직업의 묵직한 참격 에셋과 종결 효과를 사용한다.
- **완료 조건:** 출혈 중첩·버프 적용·종결 순서·총 피해가 의도와 맞고 과도한 화면 진동이 없다.

### 128. [P1·설계] 크루세이더 성흔극

- **수정 지시:** 빛기둥 표적 선정과 성검 강림·회복·기절의 타이밍을 정리한다. 기절 저항 및 회복량이 다른 직업보다 과도한 생존 우위를 주지 않는지 검증한다.
- **완료 조건:** 동일 조건 적 수별 피해·회복·기절 시간이 기록된다.

### 129. [P1·설계] 블레이드마스터 궁극기

- **수정 지시:** 즉발 계수 집중과 장시간 장식의 불일치를 개선한다. 발도/연속 베기/마무리의 실루엣을 기존 또는 외부 참격 에셋으로 구분한다.
- **완료 조건:** 최초 타격과 최종 타격의 경계가 영상으로 명확하며 타격 범위를 읽을 수 있다.

### 130. [P1·설계] 아크로드 궁극기

- **수정 지시:** 마법진·원소 폭발·표적 범위를 시간 순서에 맞춘다. 장판과 직접 타격의 피해 예산을 분리한다.
- **완료 조건:** 원소별 효과가 겹쳐도 공격 경고와 적 실루엣이 보이고 피해 로그가 일치한다.

### 131. [P1·설계] 이터널 궁극기

- **수정 지시:** 장시간 지속 효과의 버프·회복·피해 역할을 기존 직업 데이터와 대조한다. 지속시간이 끝나면 상태와 연출을 동시에 정리한다.
- **완료 조건:** 효과 종료 후 버프·타이머가 잔류하지 않고 기대 피해와 회복이 기록된다.

### 132. [P1·설계] 데드아이 궁극기

- **수정 지시:** 원거리 연속 사격과 표적 이동, 탄환 비행 시간을 명확히 한다. 공통 원형 피해보다 실제 조준 방향이 살아나게 설계한다.
- **완료 조건:** 좌우 조준·이동 표적·벽 뒤 대상의 판정이 시각 연출과 일치한다.

### 233. [P0·검증] 단위 테스트 품질

- **수정 지시:** 현재 761개 통과 기록은 기준선으로만 활용한다. 정상·경계·실패·중복 호출을 실행하는 테스트를 추가하고 소스 정규식만으로 완료 판단하지 않는다.
- **완료 조건:** 실제 수정 전 실패/수정 후 통과를 재현한 테스트와 전체 결과를 제출한다.

### 234. [P0·설계] 브라우저 E2E 성공 판정

- **수정 지시:** Playwright 스크립트가 클릭 시도만 하고 성공으로 끝나지 않도록 화면 상태·이벤트·실제 피해·저장을 assert한다. 타깃 0개와 시전 실패도 실패 처리한다.
- **완료 조건:** 실패를 의도적으로 주입했을 때 테스트가 비정상 종료하며 정상 경로는 통과한다.

### 235. [P0·검증] 개발 서버 제약 처리

- **수정 지시:** inotify/EACCES 등 기존 환경 실패를 기록하고 지원되는 개발 서버/격리된 QA 환경을 사용한다. 동일 실패를 반복하거나 브라우저 미실행을 실행으로 보고하지 않는다.
- **완료 조건:** 환경 오류와 게임 오류가 구분되고 실행 가능한 재현 명령을 남긴다.

### 236. [P1·설계] 시각 회귀 검증

- **수정 지시:** 고정 시드·세이브·뷰포트로 주요 화면을 캡처한다. 의도된 변화와 타일 누락·UI 잘림·잘못된 프레임을 비교한다.
- **완료 조건:** 스크린샷의 SHA와 환경이 명시되고 승인되지 않은 시각적 회귀가 없다.

### 237. [P0·검증] 설치형 플랫폼 버전

- **수정 지시:** APK/EXE 자동 빌드 중지 정책을 유지한다. 사용자 승인 후 버전 표기·다운로드 파일·릴리스 SHA·Adaptive Icon 실제 전경/배경을 대조한다.
- **완료 조건:** 설치형 버전의 실제 설치·실행·아이콘·로그인이 확인되고 웹 버전과 차이가 명시된다.

### 238. [P0·설계] 배포 전후 검증

- **수정 지시:** 사용자 허가 범위에서만 빌드/배포한다. 운영 API SHA, 실제 화면, 캐시, 신규 생성, 저장 및 핵심 전투를 재검증한다.
- **완료 조건:** 배포된 SHA와 평가 대상이 정확히 일치하며 롤백 방법과 실패 기준이 기록된다.

### 239. [P0·설계] 회귀 평가와 릴리스 중단

- **수정 지시:** 항목별 1점 평가에서 관찰된 악화와 미검증을 구분한다. 진입 불가·저장 손실·권한·결제·기록 무결성 결함은 출시 차단 사유로 둔다.
- **완료 조건:** 점수가 목표에 미달해도 실제 근거를 유지하며 P0 실패를 숨기지 않는다.

### 240. [P0·설계] 최종 인수인계

- **수정 지시:** 작업마다 변경 이유, 파일, 테스트 결과, 실제 화면, 남은 위험, 롤백 방법을 worklog에 기록한다. 최신 SHA를 적고 과거 인계와 충돌하는 내용을 정리한다.
- **완료 조건:** 후속 에이전트가 오래된 작업을 반복하지 않고 미완료 항목부터 시작할 수 있다.
