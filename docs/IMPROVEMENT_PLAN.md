## 5. 이펙트

AGENTS.md 철칙: **"스킬에만 화려한 이펙트. 기본공격·적 처치 등 자주 호출되는 지점은 절대 과하게."**
현재 이 규칙은 대체로 지켜지고 있다(파티클 수/스케일 축소 유지). 개선은 **추가가 아니라 비용 제거** 방향으로만 한다.

- `spawnHitSpark`의 애니 키 3종을 모듈 상수로 승격 (`WorldScene.ts:3496`)
- `setParticleTint`는 색이 바뀔 때만 호출 (`:3487`)
- 히트스톱: 일반 26ms / 크리 55ms 유지 (`Enemy.ts:620`) — 밸런스 손대지 않음

### E1 — **히트스톱이 자가치유에 잘리고 있었다** (감사 미탐지 · 직접 발견 · 수정 완료)

v3.3.0의 물리 자가치유 블록(`update()` 안)이 `physics.world.isPaused`만 보고 즉시 `resume()` 했다.
`hitStop()`은 `pause()` 후 `delayedCall(ms)`로 푸는 구조라, **다음 프레임(≈16ms)에 자가치유가 먼저 풀어버렸다.**

| 시점 | 종전 동작 |
|---|---|
| t=0 | `hitStop(55)` → `pause()` |
| t≈16ms | `update()` 자가치유 → **`resume()`** ← 연출 잘림 |
| t=55ms | `delayedCall` → `resume()` (이미 풀린 뒤) |

즉 일반 26ms는 1프레임으로 축소, 크리 55ms·격파 70ms 연출은 사실상 무효였다. AGENTS.md가
"타격감은 히트스톱+사운드가 담당"이라 적은 그 기능이 v3.3.0 이후 죽어 있었다.

**수정**: 자가치유 게이트에 `this.time.now >= this.hitStopUntil`을 추가했다. Phaser의 `Clock`은
`System.step()`에서 `sceneUpdate`(=우리 `update()`) **이전에** 틱하므로, 히트스톱 만료 프레임에는
`delayedCall`이 먼저 복원하고 그 이전 프레임들은 가드가 막는다. `delayedCall`이 유실된 경우에는
만료 후 자가치유가 복원하므로 **안전망도 오히려 강화**된다.
씬 재시작 시 `hitStopUntil = 0`으로 리셋도 추가(새 씬 `time.now`는 0부터 시작해 이월 시 자가치유가 막힘).

> 실기기 확인 필요: 프레임 타이밍에 의존하는 변경이라 tsc/eslint로는 검증되지 않는다. 인게임에서
> 타격 시 정지감이 26/55/70ms로 체감되는지, 대사·전환 후 조작 불능이 없는지 확인할 것.

**새 이펙트는 추가하지 않는다.** 예산이 남으면 스킬 연출에만 쓴다.

## 부록 B — 진행 상황 (2026-10-16 세션)

### S8 해결 — `cid` 위조로 남의 파티 강퇴 (2026-10-17 수정 완료)

**문제(수정 전)**: `snapshot()`이 멤버 `id`에 실제 cid를 담아 응답했고, `leave`·`beat`는
클라이언트가 보낸 cid만 보고 본인이라 판단했다. cid는 `localStorage`의 랜덤 문자열이라
비밀이 아니다 → 아무 파티에 들어가 남의 cid를 읽은 뒤 그 값으로 남을 축출할 수 있었다.

**초기 판단(철회)**: 처음엔 "세션 인증을 강제해야 한다 → APK 교차 오리진 쿠키 문제로 못 한다"고
보고 3단계(credentials + cid 마이그레이션 + own-member-only)가 필요하다고 적었다. **이는 과설계였다.**
cid를 **비밀로 쓰지 않으면** 되는 문제이고, 그러면 쿠키도 마이그레이션도 필요 없다.

**실제 수정 (2곳, 새 의존성 0)**
1. **cid를 응답에서 제거** — `snapshot()`의 멤버 `id`는 표시용 슬롯(`CODE#0`), `leader`는
   **이름**으로 반환. 리더 여부는 멤버별 `leader: boolean`으로 노출한다.
2. **서버 발급 좌석 비밀(`seat`)** — `create`/`join` 응답으로 CSPRNG 32자를 1회 발급하고
   (`randomBytes(24).toString("base64url")`), `leave`·`beat`가 일치를 요구한다. 불일치는 403.
   seat은 파티별로 다르고 재입장 시 갱신되며 응답 스냅샷에는 절대 싣지 않는다.

**부수 수정**: `leader`가 cid로 내려가는데 UI는 `m.name === party.leader`로 비교해
**리더 왕관이 원래부터 뜨지 않았다**(PartyWidget.tsx:151). 이름으로 바꾸면서 함께 해결됐다.

**검증** (로컬 standalone, 실제 공격 재현 — `_boss_work/s8_verify.mjs`)
| 단계 | 결과 |
|---|---|
| 스냅샷에 cid 노출 | 없음 (`P39W#0` 슬롯 id만) |
| [공격] 남의 cid로 leave | **403 차단** |
| [공격] 자기 seat으로 남 탈퇴 | **403 차단** |
| [공격] 위조 seat으로 beat | **403 차단** |
| 공격 후 피해자 생존 | **예** |
| 정상 탈퇴(자기 seat) | **200 정상** |

**남은 한계(의도적)**: `beat`가 403이면 클라이언트가 자동 재입장한다(`relay.ts`).
seat 없는 구(舊)멤버는 통과시키지 않으므로 **배포 직후 기존 파티는 재입장이 1회 필요**하다
(파티 자체는 유지 — 15분 무활동 정리 대상이 아니면 명단에 남는다).

### F3 정정 — "33곳"은 과장이었다 (2026-10-18)

기획서는 F3를 "24~28px 33곳(중)"으로 적었다. 실측하니 달랐다.

**측정 조건**: 가로 412×915(APK 실제 환경), 인게임 상태.
세로 화면에서는 `RotatePrompt`가 게임을 가려 HUD가 아예 렌더되지 않으므로 **가로 기준으로 재야 한다**(첫 시도에서 이걸 놓쳐 HUD 0개로 측정됐다).

| 대상 | 실측 | WCAG 2.2 SC 2.5.8 (24px) |
|---|---|---|
| 퀘스트창 토글 | **17×14** | ✗ **미달** |
| HUD 아이콘 6개 | 33×33 | ○ 통과 |
| 채팅 접기(▾) | 28×28 | ○ 통과 |
| 채팅 기록 | 50×28 | ○ 통과 |
| 채팅 Enter | 96×25 | ○ 통과 |

**33px의 정체**: HUD 우측 컬럼에 `zoom`이 걸려 있다(화면 폭에 따라 0.85~1.28 — HUD.tsx). `h-9`(36px) × 0.85 = 30.6px로 렌더된 값이다. 코드상 `h-9 w-9`만 보면 36px이라 "44px 미만 33곳"으로 세어졌다.

**44px로 키우지 않은 이유**: HUD 버튼 간격이 `gap-1.5`(6px)다. 33px → 44px로 키우면 각 버튼이 5.5px씩 초과해 **인접 버튼과 5px씩 겹친다.** 오탭이 줄기는커녕 늘어난다.

**채택한 방법**: `.tap-safe` — `::after` 의사요소로 히트 영역만 44px까지 넓힌다(시각 크기·레이아웃 불변).
`zoom` 컨텍스트에서는 44px가 44×zoom으로 렌더되므로 `--tap-zoom` 변수로 역보정한다.

**검증**: `elementFromPoint`로 퀘스트 토글 중심에서 상하좌우 18px 이동한 지점이 모두 그 버튼으로 잡힘을 확인(4/4 적중). 실효 히트 영역 약 53×50px.

### F4 상세 — 측정 방법을 네 번 고쳐야 정확해졌다 (2026-10-18)

**결과**: `text-white` 전 구간이 WCAG AA를 통과한다.

| 알파 | 곳수 | 지정색 최소 대비 | 판정 |
|---|---|---|---|
| /25~/30 | → /55 | — | 2.11~2.70 (심각) |
| /35 | → /55 | — | 3.11 |
| /40 | → /55 | — | 3.73 |
| /45 | → /55 | — | 4.31~4.50 (경계) |
| **/50** | 96 | **4.51** | AA 통과 |
| **/55** | 290 | **5.10** | AA 통과 |
| /60~/90 | 174 | 5.74~10.81 | AA 통과 |

**측정 실패 4회 (기록)**
1. **텍스트 노드 5~15개만 검출** — `page.evaluate`에 문자열로 함수를 넘겨 이스케이프가 깨졌다. 함수 객체를 직접 넘겨 해결.
2. **`color` 단계에서 402개 탈락** — Tailwind v4는 `oklab()`/`lab()` 표기를 쓰는데 정규식이 `rgb()/rgba()`만 처리했다. 캔버스에 그려 픽셀을 읽는 방식으로 해결.
3. **대비 1.0~1.32라는 거짓** — 배경을 `backgroundColor`로만 읽어 **그라디언트(`background-image`)를 놓쳤다.** 스크린샷 픽셀 샘플링으로 해결.
4. **대비 3.89~4.15로 과소평가** — 알파 색을 **검정 위에** 합성해 비교했다. WCAG는 **선언색을 실제 배경 위에** 합성한다. 지정색 기준으로는 5.05~5.15로 통과.

**교훈**: 접근성 측정은 **선언된 색 + 실제 배경**으로 계산해야 한다. 픽셀 샘플링은 안티에일리어싱·그라디언트·이미지 배경에서 오판한다.
