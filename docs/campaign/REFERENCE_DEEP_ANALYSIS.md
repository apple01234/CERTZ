## 1. JENNY — 이번에 추가한 공격·연출 분석

Drive ID `133Td4oi5ZXvgVRe4LlR10oTIgC9fTC1y`. ZIP 256,674,681바이트, SHA-256 `db197e67058919c9e4db918f29759f8a429036117768d68a72f414369b2952be`. 안에는 `Jenny Game.exe`와 `Jenny Game.pck` 두 파일이 있다. 실행 파일을 실행하지 않았다. PCK SHA-256은 `c02c12125df9de1f45ffd7d10d231e89ad5d1153cd64698070ea7836a90d8c57`이다.

- PCK 검사 `ev_50dcba8f9d64a272ecac710638dacb18ade69827d3b71cdc3098b7616c8cb6ea`.
- PCK inventory `ev_d89cc2c149107e4ffa30c7f1ca9d9f922423a82c3bf4e79cda4eec3fb1111a8f`.

GDRE Tools 2.7.4의 별도 정적 복원 결과는 스크립트 800개, 변환 리소스 1,454개, 실패 변환 0개다. 이 수치는 도구의 복원 범위다. 800개 모두의 게임 의미를 완전 해석했다는 뜻이 아니다. 최종 텍스트에는 GD 800개, TSCN 470개, TRES 183개가 있다. 원본 3D 리소스 변환 1개는 비원본 경로라 non-importable로 보고됐다. 복원 산출물은 분석 폴더에만 보관한다.

### 공격의 실제 호출 흐름

`system/traits/behavior/attack_state.gd`는 `state_entered`에서 공격 목록을 실행한다. `parallel`이면 각각 호출하고, 순차 모드에서는 각 `attack.attack()`을 기다린 뒤 상태 차트에 `attack_ended`를 보낸다. 따라서 공격 애니메이션 목록과 실제 공격 실행 순서를 같은 것으로 단정하면 안 된다.

`system/traits/behavior/attacks/attack.gd`의 `can_attack()`은 생존 조건, 표적 가시성, 이미 공격 중인지, 쿨타임 날짜, 거리, 스턴, 추가 조건 노드를 검사한다. `attack()`은 다음 흐름을 가진다.

1. 공격 중 사용하는 컴포넌트를 켜고 `_pre_attack`, `attack_started`를 호출한다.
2. `is_starting_up`과 `starting_up`을 설정하고 `get_attack_startup()` 시간을 기다린다. 선택적으로 조준을 잠근다.
3. 각 연속 공격 전에 취소·트리 이탈·`can_sequence()`를 검사한다. `attacking`, 애니메이션 이벤트, `_do_attack()` 순서로 진행하고 공격 간격을 기다린다.
4. 공격 종료 처리를 한 뒤 `recovering`→회복 시간 대기→`recovered`로 진행한다.
5. 쿨타임 날짜를 기록하고 공격 중 상태와 임시 컴포넌트를 해제한다.

사망 신호는 `cancel()`로 연결된다. 스턴 취소와 사망 취소가 존재한다는 사실은 확인했지만, 모든 파생 공격이 모든 중단 경로에서 완벽하게 정리된다고 증명한 것은 아니다.

**SERTZ 적용:** `skills.ts`와 공유 `battle.ts`에 준비→한 번의 발동→후딜→쿨타임을 구현했다. 준비 시간은 전사 180ms, 궁수 220ms, 마법사 340ms, 도적 120ms, 항로 계열 240ms로 직접 설계했다. 준비 중 이동은 느려지고 회피하면 미발동 공격을 취소한다. 취소해도 쿨타임은 유지한다. 타격 순간의 거리를 다시 검사하고, 후딜 중 기본 공격을 막는다. 이 수치와 스킬 이름은 SERTZ 고유 설정이며 JENNY의 수치를 복제한 것이 아니다.

### 대시와 근접 타격

`world/items/weapons/dash_drill/dash_component.gd`는 장착·사용자 유효성·쿨타임을 검사하고 물리 impulse를 적용한다. 속도/감속 곡선 modifier는 인스턴스 키로 추가·제거하며 종료에서 임시 보정을 제거한다. 무적 효과는 별도 장면이다. `baseball_bat/melee_item.gd`는 스윙 활성 상태·이전 transform·형상 sweep을 분리하며, `intersect_shape`를 사용한다. 존재하는 `hit_bodies` 변수만으로 모든 무기의 중복 타격 차단이 검증됐다고 주장하지 않는다.

**SERTZ 적용:** 회피 무적과 물리 통과를 분리했다. 회피 중에도 가구·나무의 발밑 충돌을 통과하지 않는다. 서버도 같은 `canWalkAt`을 호출한다. 직업별 스킬은 발동 상태를 소모하므로 다음 tick에 같은 피해를 반복 적용하지 않는다. 스킬 판정은 화면 파티클 개수와 무관하다.

### 카메라와 전투 컷씬

`characters/player/player_camera.gd`는 플레이어 위치, lookahead, 줌 보너스와 `CameraEffect` 목록을 합성한다. 줌은 0.25~6 범위로 제한하고 효과 강도로 목표 위치를 섞는다. `shake()`는 5단계 감쇠 offset을 tween으로 더한다. `CameraShakeShooterComponent`는 발사/탄약 검사/명중 중 지정된 이벤트에 연결되며 player-only와 abort 조건을 검사한다.

`world/logic/camera_effect_area.gd`는 진입 시 효과를 복제·등록하고, 이탈 후 줌이 1로 돌아오면 카메라 목록에서 제거한다. `world/buffs/zoom_in_effect.gd`도 적용/처리/제거가 분리된다. 이는 효과 수명의 근거이며 스토리 컷씬 전체를 읽었다는 근거는 아니다.

**SERTZ 적용:** 보스전 시작에서 1.4초 동안 카메라를 보스에 맞추며 전투 시뮬레이션을 진행시키지 않는다. E 또는 화면 버튼으로 건너뛰면 카메라의 pan/zoom 효과를 정리하고 원래 줌·추적·입력을 복구한다. 동작 줄이기 설정에서는 이 등장 연출을 생략한다. 대화도 같은 복구 원칙을 적용했다. 온라인 전투의 서버 시계를 연출 때문에 멈추지는 않는다.

### 이펙트 수명

`assets/effects/effect.gd`는 입자·음원·수명·종료 수명을 관리한다. `start`에서 입자를 켜고 음원을 재생하며, `stop`에서 입자와 처리를 끈다. 유한 수명이 끝나면 해제하고, splat은 별도 캐시 경로를 가진다. `TrailEmitter`는 master와 실제 trail child를 나눠 발산 중에만 위치점을 추가한다. `timescale_system.gd`는 시간 stack, cooldown 날짜, 오디오 배율을 별도로 다룬다.

**SERTZ 적용:** 새 이미지를 만들지 않고 보유한 원본 `slash0..5.webp`를 1회 재생한다. 준비 중에는 UI 진행 원호, 발동 후에는 명중 위치 또는 빗나간 시전자 위치에 효과를 표시한다. 명중한 스킬만 기존 `ImpactFX.shake`를 호출하며 접근성 흔들림 배율을 유지한다. 일반 공격에는 강한 효과를 추가하지 않는다. 장면 전환 때 재생 중인 참격과 위험 표시를 정리한다. 공유 전투에 전역 timeScale을 적용하지 않아 서버와 클라이언트의 시간 차이를 만들지 않는다.

## 2. Nefarius — 이동·피격·대시의 분리

기존 `windows.zip`의 Godot 4.3 배포본을 분석했다. 새로 첨부됐던 EXE 바이트와 같다는 해시 비교는 하지 않았다. REA로 리소스 820개를 추출한 뒤 GDRE로 스크립트 77개를 복원했다.

`src/entities/player/player.gd`의 물리 tick은 입력 확인, 아이템 능력 사용과 쿨타임 감소, 이동, `move_and_slide()`로 이어진다. 조준 방향과 이동 입력은 별도다. 공격 중에는 조준을 보며 이동할 수 있고, 평소에는 이동 방향을 본다. 피격은 잠시 조작 차단·피격 애니메이션·knockback·무적 타이머를 사용한다.

`player.tscn`의 물리 형상은 13×6 사각형이고 피격 반경은 6, 경험치 수집 반경은 60이다. 같은 캐릭터 그림이라도 세 판정 영역을 분리한다. 대시 능력은 중복 시전과 쿨타임을 검사하고, 애니메이션 완료 후 속도·애니메이션 속도를 되돌린다. 선언된 duration 값만으로 실제 지속 시간을 단정할 수 없으며, 읽은 구현은 애니메이션 종료를 기다린다.

상호작용 `InteractionArea`는 플레이어가 들어온 동안에만 입력 처리를 켜고, 대화가 이미 재생 중이면 중복 시작하지 않는다. 나갈 때 프롬프트 소멸 단계로 바뀐다. 스폰 연출은 카메라 이동→등장 애니메이션 완료→기본 애니메이션 루프→카메라 해제로 이어진다.

**적용:** 원본 몸체 프레임을 실제 이동량에 연결하고, 걷지 않을 때 idle로 되돌린다. 발밑 충돌·피격 무적·상호작용 범위를 분리했다. 대화/메뉴 중 입력 초기화와 종료 복원을 유지한다. 애니메이션 속도 보정은 회피 중에만 적용하고 정상 속도로 되돌린다.

## 3. Feather Park — 작은 구역과 명확한 상호작용

Godot 3.5 PCK 형식 1이다. REA 6.8의 해당 검사 경로가 거부했으므로 이 게임의 깊은 복원은 별도 GDRE 도구 결과다. GD 78개, TSCN 90개를 확보했다.

`src/player/Player.gd`는 속도 75, 정규화 입력, 마지막 입력 방향, idle/walk 상태를 나눈다. EastArea에서는 물리 반경 3, 다른 구역에서는 6을 쓴다. 첫 구역 시작 시 3.5초 조작 잠금 뒤 해제와 음악 시작을 호출한다. 몸체·발 스택을 회전하며 최단 회전 방향을 보정한다. 이 시점은 정적 코드상의 대기 시간이며 실제 기기의 체감 시간을 측정한 것은 아니다.

`src/ui/Interactable.gd`에는 상호작용 반경 28, 표시 원 반경 8, 말풍선 offset (0,-22), 글자 간격 0.05초가 있다. 구역 진입/이탈에서 대상과 프롬프트를 교체하고, 상호작용 시 캐릭터가 대상을 본다. `TransitionScreen.gd`는 fade 애니메이션 완료 신호에서만 scene을 바꾸고 다음 fade를 시작한다.

장면은 거대한 한 맵보다 구역 연결을 사용한다. EastArea 카메라 경계는 (0,0)~(384,144), MainArea는 (-96,0)~(288,288), NorthArea는 (0,0)~(192,288), WestArea는 (-192,0)~(192,144)다. YSort가 구역 장면에 있으며 여러 Area2D로 출입/상호작용을 구성한다. 이 구역을 모두 타일맵이라고 부르면 부정확하다. 확인한 장면에는 Sprite 배경과 별도 충돌 형상도 있다.

**적용:** 기존 발밑 Y 정렬을 유지하고, 목표와 입구 주변을 소품 배치에서 보호했다. 클릭 길찾기는 16px 탐색 격자로 실제 소품을 우회하며, 시작/끝의 짧은 이동 구간도 검사한다. 전환은 `startTransition` 한 경로를 유지하고 대화 카메라를 정상 줌으로 복구한다.

## 4. Veronikka — 이동 상태에서 Animator까지

Unity Mono의 선택 어셈블리를 REA로 읽었다. 선언 140개 타입, 메서드 798개, 호출 edge 3,205개를 확보했다. 이 숫자는 메타데이터/호출 분석 범위이며 게임 전체 장면 분석 수가 아니다.

`PlayerMovement.FixedUpdate`→입력 두 축 읽기→`UpdateAnimationAndMove` 호출이 있고, 그 메서드에는 움직임 벡터 비교·`MoveCharacter`·Animator의 float/bool 설정 호출이 있다. 실제 상태가 Animator로 전달되는 연결을 확인한 근거다. `DialogueManager`에는 대화 queue와 종료 때 옵션 처리가 있다.

**적용:** 프레임 파일이 존재하는 것으로 완료 처리하지 않고 실제 sprite의 프레임 키가 시간에 따라 변하는지 브라우저에서 검사한다. 오른쪽·위쪽·공격 애니메이션과 정지 상태를 구분했다. 대화 중 이동을 막고 건너뛰기 후 조작을 복구한다.

## 5. Morfosi — 체크포인트와 대화 종료 정리

Unity 타입 231개, 메서드 1,040개, 호출 edge 2,657개를 읽었다. `CheckpointInteractable.StartedInteraction`에는 CheckpointReached 생성, 이벤트 publish, 오디오 stop/play, 조명·콜라이더 관련 coroutine과 SavingText 호출이 있다. 이것이 세이브 파일의 실제 원자성을 증명하지는 않는다.

`DialogueManager.StartDialogue`는 queue와 Animator, 구독, 다음 문장 호출을 사용한다. `EndDialogue`에는 coroutine 중지, 오디오/문자열/Animator 정리, 구독 해제, `EnablePlayerInput`, 종료 이벤트 publish가 있다. 종료 경로까지 읽어야 입력 잠금 버그를 예방할 수 있다는 근거다.

**적용:** 기존 새 캠페인 백업과 저장 실패 경고를 유지했다. 원래 RPG를 복구하면서 구 저장을 직접 마이그레이션하지 않고 `sertz:memory-oath-v1:rpg:` 저장 공간으로 격리한다. 이야기 저장·레거시 바이트·RPG 장비 저장이 서로 덮이지 않는지 검사했다. 대화 건너뛰기의 카메라·입력 정리도 검사한다.

## 6. HoloDungeon — 탐험과 전투 상태 왕복

Unity 타입 182개, 메서드 1,076개, 호출 edge 6,135개를 읽었다. `RoomManager.StartCombat`과 `EndCombat`은 coroutine 생성 wrapper다. 실제 흐름을 읽기 위해 `<StartCombat>d__50.MoveNext`, `<EndCombat>d__51.MoveNext` 호출을 따로 선택했다.

StartCombat coroutine에는 카메라·플레이어·파티 위치 읽기와 목록 저장, BGM 정지/재생, CanvasGroup alpha, WaitForSeconds 호출이 있다. EndCombat에는 coroutine 중지, 음악 fade, 전투 UI 종료, scene load, 파티 갱신, 선택된 PlayableDirector 호출이 있다. `ResetPositions`는 저장 위치를 transform에 다시 쓰는 호출을 가진다. CIL 호출 목록만으로 모든 분기 순서와 타이밍을 복원했다고 주장하지 않는다.

**적용:** 전투 상태와 본편 진행은 분리하고, 전투 승리 후 기존 `startTransition`으로 본편 목표를 다시 만든다. 캠페인 음악은 기존 오디오 재생기를 이용한다. 온라인 보상은 서버 서명과 일회성 처리 규칙을 유지한다.

## 7. Bloodkeeper — 시각 레이어와 물리 레이어

Construct JSON의 오브젝트 타입 434개, 레이아웃 11개, 이벤트 시트 12개를 읽었다. Hub 600×700, Forest 2600×1000, Profaned 1202×2200, Hamlet1 4096×4096, Prison 702×1298 등으로 구역 크기가 다르고 메뉴/인벤토리는 별도 480×270 레이아웃이다.

Hub에는 BG/Char/Tile_Ground/Collision 등 별도 레이어가 있고 실제 충돌 인스턴스가 직렬화되어 있다. Dash 방향 오브젝트는 각 3프레임, 선택 공격 오브젝트 Bossatk2의 ATK는 8fps·13프레임으로 선언된다. 이 선언은 게임 실행 중의 state 선택이나 hit frame을 관찰한 것이 아니다.

**적용:** 그림이 보이는 지형과 통행 여부를 분리하고, 바닥 가구라도 단단한 물체면 발밑 충돌을 준다. 실내 통로는 3가지 위치를 사용하고 보스전은 분할벽을 제외한다. 동일 배치 데이터가 렌더와 판정에 쓰이도록 중복 배치를 제거했다.

## 8. WYDTTM — 23개 맵, 이벤트 페이지와 전송 그래프

이번 후속 분석은 첫 5개만이 아니라 ZIP 안의 Map JSON 23개를 모두 읽었다. 각 데이터 길이는 width×height×6임을 검사했다. 예를 들어 17×13 소형 화면, 30×30 공간, 50×50 구역, 50×100 세로 구역이 있다. 이벤트마다 페이지 조건·trigger·priorityType·through·walk/step animation·moveType을 기록했다.

전송 명령 201은 70개, 이동 경로 205는 62개, 명시적 fade-out/fade-in 221/222는 각각 4개다. 선택지 102와 그 분기 402/404, self-switch 123도 존재한다. 텍스트 내용은 제품에 복사하지 않고 opcode 분포만 기록했다. 명령 225가 9,135회 있다는 사실만으로 좋은 셰이크 연출이라고 평가하지 않는다.

Tilesets의 flags에서 방향 통행 비트와 상층 star 비트 수를 읽었다. `through`가 없는 것으로 모든 타일 충돌이 막힌다고 단정하면 안 된다. 이벤트 우선순위와 타일 passage는 별도다. 변수 전송 목적지와 스크립트 명령 의미는 완전 해석하지 않았다. 기존 REA JavaScript 두 파일 분석은 81,292 AST 노드이며 일부 의미 분석 상한이 있다.

**적용:** 맵 재질/구조물/통행 레이어와 대화·수집 목표 상태를 나눈다. 목표 완료는 캐릭터 저장에 남고 재방문 보상을 중복 지급하지 않는다. 자동 검사에서 34개 장의 입장·안내자·목표 지점까지 이동 가능함을 확인한다.

## 9. Flooded Burials — 방의 역할과 규모

GameMaker FORM의 ROOM/STRG를 범위 검사하며 읽었다. ROOM 레코드 233개 중 기존 크기 기준(가로·세로 각각 16 이상)에 해당하는 방은 230개다. 처음 보고서의 230은 이 필터 결과이며 전체 레코드 수와 구분한다. 방 이름·크기 분포는 JSON에 있다. level select와 parent stage 역할이 나뉜 방이 존재한다.

**적용:** 장 선택/재방문과 전투/탐험을 별도 상태로 유지한다. 원본 RPG의 다양한 필드·실내·콘텐츠 맵을 다시 연결한다. GML bytecode의 전투 분기는 해독하지 않았으므로 해당 게임의 스킬 설계를 복제했다고 표시하지 않는다.

## 10. Vampire No Survivors — 전투장과 종료 화면

ROOM 4개와 rmBattlefield 2000×400, 별도 rmGameOver를 확인했다. 상자·획득 완료 상자·함정 상자 식별자가 있지만 이벤트 실행은 확인하지 않았다.

**적용:** 실제 전투와 패배/재도전 UI를 나누고 최초 완료 보상은 기존 일회성 처리로 유지한다. 상자 이름에서 드롭 확률이나 보상 행동을 추론하지 않는다.

## 11. SangTDB — 클래스 선택·튜토리얼·방향 상태

ROOM 27개, 클래스 선택과 튜토리얼 방, 방향별 플레이어 sprite 선언, 보스 등장/승리/사망 음악 리소스를 확인했다. GML 이벤트와 실제 타이밍은 읽지 못했다.

**적용:** 직업 선택을 유지하고, 원본 RPG 전직/스킬 패널을 다시 노출했다. 본편 HUD에 직업별 스킬 이름·시전 잔여·후딜·쿨타임·회피 준비 상태를 표시한다. 보스 등장 연출은 자체 상태로 구현하고 스킵을 제공한다.

## 12. COBB — 작은 화면과 전역 UI 분리

REA로 패키지 63개 아티팩트를 검사·추출했다. Construct 데이터에는 오브젝트 타입 91개, 레이아웃 14개, 이벤트 시트 15개가 있다. 대부분 화면은 640×360이지만 finale는 1600×1600, chunk 레이아웃은 5880×1720이다. global layers와 parallax가 다른 레이어가 분리된다. 플레이어 몸체·눈·동공·손은 별도 오브젝트이고 일부 애니메이션은 0fps로 선언된다. 따라서 단순히 프레임이 4개라고 자동 재생을 주장할 수 없다.

**적용:** HUD와 월드 오브젝트를 분리하고 모바일에서 목표·대화·전투 조작을 확인했다. 모든 그림을 한 atlas/canvas로 합쳐 원본 기능을 잃는 방식은 사용하지 않는다.

## 13. NightShift — 분석 한계

PE import와 동봉 readme를 확인했다. 문서에는 Save/Load 없음, 약 30~40분, 7개 낮/밤 이동 조작이 명시된다. 내장 게임 데이터·애니메이션·전투 의미는 해독하지 못했다. 이 게임에서 특정 타일맵·스킬 코드를 가져왔다고 주장하지 않는다. 유지한 개선은 SERTZ 자동 저장·복구 동선이며 이는 자체 제품 결정이다.

## 14. Aereven Advance — 분석 한계

GBA ROM 헤더 `Aereven2 Adv`와 체크섬을 확인했다. 에뮬레이터 실행, 맵·애니메이션·전투 루틴은 분석하지 않았다. ROM에서 에셋이나 기능을 가져오지 않았다. 14개 전체를 완전 역공학했다는 표현은 사용하지 않는다.

## 에셋과 원래 기능을 복구한 범위

- 빌드 후 에셋을 약 16MB로 줄이던 pruning과 Vercel 제외 규칙을 철회했다. 원본 `public/assets`, 3D·VFX 팩은 그대로 보존한다. 에셋이 배포에 존재하는 것과 모든 파일이 현재 장면에 사용되는 것은 다르다.
- 새 캠페인 플레이어 5종×방향·공격 7종×4프레임, 원본 보스 시트 6종, 미니언·참격을 포함해 개별 원본 152장과 보스 시트 6종의 SHA-256을 검증한다. 보스 초상 파일과 실제 월드 보스 애니메이션을 구분한다.
- 새로 만들었던 sunburst 이미지·atlas를 삭제했다. UI도 기존 lucide 아이콘을 사용한다. 이번 작업에서 이미지·동작 프레임·효과 시트를 생성하지 않았다.
- ‘벤치’로 잘못 분류된 자판기, ‘천막’으로 분류된 시트 조각을 실제 이미지로 확인했다. 본편 건물은 온전한 원본 `house_a/house_b`로 교체하고 거점의 잘못된 town 카탈로그 랜덤 배치를 제외했다.
- Pixel Frog 공식 `TS_old version_CC0 Licensed` ZIP도 다운로드하고 전체 멤버 해시를 기록했다. 최신 Tiny Swords 팩과 라이선스를 혼동하지 않는다. `game-dev` CLI가 없어 해당 스킬의 admission 검증을 수행하지 않았으며, 이 다운로드 팩은 제품에 편입하지 않았다. 현재 적용한 그래픽은 사용자 원본이다.
- 원래 `GameRoot`/`WorldScene`/`Player`/`Panels`를 직접 재사용한다. 구 스토리는 부활시키지 않고 기존 지형은 재료/경험치 원정지로 재해석했다. 제거한 이야기의 입구와 DLC 경로는 현재 본편으로 돌려보낸다.
- 원래 온라인 경제와 새 본편 경제를 임의로 합치지 않는다. 운영 계정/클라우드/실결제/상시 전투 서버는 별도 운영 설정이 필요하다.
