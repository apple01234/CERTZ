- 34장(15+10+9)의 상태 진행, 중복 보상 방지, 퍼즐 순서, 잠긴 장 이동, 손상/미래/레거시 저장 거부와 백업 복구를 검사했다.
- 모든 장의 목표 접근성, 벽을 우회하는 경로, 물·용암·맵 밖 진입 차단, 도서관 통로와 열린 보스 전투장을 검사했다.
- 선택 에셋의 SHA-256·이미지 규격·Ogg 헤더, 22개 보스 대응과 배포 허용 목록을 검사했다. 음악은 한 곡 스트리밍·장면 교체·효과음 제한·숨김/종료 정리를 검사했다.

- 실제 Socket.IO 클라이언트 3개로 동일 전투 상태와 서명 결과를 수신했다. 클라이언트의 승리 선언은 처리되지 않았다.
- 프로덕션 서버의 Chromium 플레이: 첫 장의 모든 목표와 보상, 새로고침 복원, 기존 저장 바이트 보존, 실제 보스 공격·원소술·회피 공략과 승리 후 본편 복귀를 통과했다.
- 별도 브라우저 컨텍스트 3개로 파티 생성/입장/공유 보스전/서명 결과/보상 UI/본편 복귀를 통과했다. 계정·클라우드 HTTP는 모의하며 실시간 전투 서버와 서명 검증은 실제 구현이다.
- 390×844 터치 뷰포트와 데스크톱에서 HUD·조작·메뉴를 확인했다. 저장 공간 오류를 재현해 경고가 보상 알림에 덮이지 않고 설정에서 백업 파일을 내려받을 수 있음을 확인했다.

## Vercel 업로드 회귀 수정

`.vercelignore`가 새로 연결한 프로젝트 이미지/음악 37개와 소스가 import하는 초상 인덱스·레거시 JSON 메타데이터를 제외하던 오류를 수정했다. 선택 파일과 상위 디렉터리만 다시 포함하고 미사용 팩은 계속 제외한다. Vercel 빌드 명령은 기존 `npm run build:next`를 재사용해 Prisma 생성을 선행한다.

업로드 목록 회귀 검사가 수정 전 실패하고 수정 후 통과함을 확인했다. 제외 규칙을 적용해 추적 파일 848개(약 43MB)를 별도 경로에 복사하고, 별도 Next 캐시에서 `VERCEL=1` 빌드를 통과했다. 이 산출물을 서빙해 선택 이미지/음악 37개의 HTTP 200 응답을 확인했다. 이 산출물에서도 첫 장·저장 복원·보스 승리/복귀·터치 HUD·3인 협동·서명 보상·저장 오류 복구의 Chromium 전체 검사를 통과했다. 로컬에만 있는 제외 파일에 의존하지 않는 검사다. 의존성은 기존 설치본을 하드링크로 재사용했으며 새로 설치한 Vercel 환경 자체의 검증을 뜻하지 않는다.

최신 main의 고대비 기본값·낚시 제거·타일 위상 정렬·GM 해금·적 그림자 변경도 보존해 병합 충돌을 정리했다. 원격 Vercel 로그는 처음에는 연결 앱 재인증 오류, 재연결 후에는 대상 sertz 팀 접근 권한 오류로 읽지 못했으므로 최초 실패 로그의 내용을 인용하지 않는다.

## 이전 검증과 실환경 한계

2026-11-02 기준 구현에서는 Playwright MCP 0.0.84의 실제 브라우저 호출, pixelfx 렌더·검사, API 라우트를 격리한 앱용 정적 export를 통과했다. 이번 에셋·맵 변경 후에는 웹 빌드와 production 브라우저 검사를 다시 실행했으며 앱용 export와 네이티브 설치는 재실행하지 않았다.

운영 계정 DB, Firebase/Google 실제 로그인, Google Play 실결제/구매 복원, 서명 APK·iOS·EXE 설치, 실기기 성능과 상시 서버 배포는 검증하지 않았다. 34장 전체 경로는 자동 검사했으나 사람이 모든 장을 완주한 것은 아니다. 2부는 기획서 요약의 게임 각색, 3부는 설정을 바탕으로 한 새 완결편이다.

13개 레퍼런스 모두 실행하거나 완전 역공학한 것은 아니다. 특히 GBA는 ROM 헤더만 확인했고 NightShift의 내장 게임 데이터는 해독하지 않았다. FeatherPark PCK 형식 1은 설치된 REA가 지원하지 않아 별도 파서로 텍스트 장면을 읽었다.

Next 16 정적 export와 웹 빌드는 `.next` 작업 캐시를 공유하므로 같은 체크아웃에서 동시에 실행하지 않는다.
